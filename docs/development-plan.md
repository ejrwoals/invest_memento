# Investment Memento — 개발 계획 문서

## 0. 한 줄 요약

> 영화 <메멘토>처럼, 과거의 나(투자 판단의 근거와 가설)를 잊지 않도록 기록하고
> 주기적으로 리마인드하며, AI가 그 가설에 영향을 줄 새로운 정보를 계속 조사해주는
> **투자 판단 보조 노트 앱**.

---

## 1. 배경 및 문제의식

- 개인 투자자는 과거에 스스로 세웠던 분석/가설/전제를 시간이 지나면서 잊어버린다.
- 그 결과 눈앞의 뉴스, 단기 변동성, 감정에 휩쓸려 과거의 논리와 모순되는 판단을 반복한다.
- "내가 왜 이 종목/자산을 샀는지", "그 판단의 전제 조건이 아직 유효한지"를 스스로
  추적하지 못하는 것이 어리석은 투자 판단의 핵심 원인 중 하나다.
- 필요한 것은 단순한 메모장이 아니라, **과거의 가설을 잊지 않게 강제로 리마인드**하고
  **그 가설이 여전히 유효한지 판단할 근거(뉴스/데이터)를 계속 모아주는 보조 장치**다.

## 2. 핵심 컨셉

### 2.1 메멘토 원칙

영화 속 주인공이 문신과 메모로 기억을 대체하듯, 이 앱은 사용자의 "과거 투자 관점"을
잃어버리지 않도록 구조화해서 저장하고, 시간이 지남에 따라 사용자에게 능동적으로
다시 보여준다.

1. **기록(Record)**: 판단 당시의 근거, 조사 자료, 관점을 시나리오·시점과 함께 구조화하여 저장한다.
2. **리마인드(Remind)**: 주기적으로 과거 기록을 다시 보여줘서 현재 판단이 과거 논리와
   일관적인지 스스로 점검하게 한다.
3. **추적(Track)**: AI가 각 가설/시나리오와 관련된 새 뉴스·데이터를 지속적으로 조사해서
   요약해준다.
4. **재평가(Re-evaluate)**: 시간이 지나며 어떤 시나리오의 발생 확률이 올라가고, 어떤
   시나리오는 이제 접어도 되는지 사용자가 판단하도록 돕는다.

### 2.2 가설-시나리오 중심 설계

이 앱에서 "노트"는 단순 텍스트가 아니라 **검증 가능한 구조**를 가진다.

- 하나의 투자 노트(Note)는 하나의 투자 대상(종목/자산/테마)에 대한 **핵심 가설(Thesis)**을 가진다.
- 하나의 가설은 여러 개의 **시나리오(Scenario)**로 분기된다. (예: 낙관/중립/비관, 또는 사건 발생/미발생 등)
- 각 시나리오는 다음을 반드시 포함해야 한다.
  - 시나리오 설명 (구체적으로, 무엇이 어떻게 되면 이 시나리오인지)
  - **예상 시점(Target Timeframe)** — "언제까지 이 일이 일어나거나 판가름 나는지"
  - **판단 지표(Indicator)** — 맞았는지 틀렸는지를 확인할 수 있는 수치 조건 (§2.3)
  - 최초 추정 확률(선택), 그리고 시간에 따라 갱신되는 확률
- 시점을 명시하기 때문에, 그 시점이 다가오거나 지나면 앱이 "이 시나리오 재검토 시점입니다"라고
  능동적으로 알릴 수 있다.

### 2.3 반증 가능성 — 모든 가설에는 수치 조건이 붙는다

"유동성이 풀린다" 같은 가설은 '풀린다'의 기준이 모호해서 나중에 맞았는지 틀렸는지 판정할 수
없다. **판정할 수 없는 가설은 복기할 수 없고, 복기가 불가능하면 이 앱은 그냥 일기장이 된다.**

따라서 시나리오를 만들 때 **그것이 맞았는지 확인할 수 있는 수치 조건을 함께 정한다.**
주가·지수·환율·금리·거시 통계처럼 외부에서 객관적으로 가져올 수 있는 값을 쓴다.

#### 두 종류의 지표를 구분한다

이 구분이 이 기능의 핵심이다. 그냥 "삼성전자 주가 +20%"만 달면 가설을 검증하는 것이 아니라
**결론을 다시 쓴 것**에 불과하다.

| 종류 | 의미 | 예 |
|---|---|---|
| **근거 지표** | 내 논리가 참이라면 **먼저 움직여야 하는** 중간 고리 | DRAM 현물가, HBM 매출 비중, 수출 증가율 |
| **결과 지표** | 내가 기대하는 최종 결말 | 삼성전자 주가, 코스피 지수 |

- 각 시나리오는 **근거 지표를 최소 1개 갖도록 AI가 대화에서 유도**한다.
- 두 종류를 나눠 두면 가장 값진 복기가 가능해진다:
  **"결과는 맞았는데 내가 생각한 이유 때문이 아니었다"** — 근거 지표는 미달성인데 결과 지표만
  달성된 경우가 여기 해당한다. 이걸 잡아내지 못하면 사용자는 틀린 논리로 운 좋게 번 것을
  실력으로 착각하고 다음에 같은 논리로 크게 잃는다.

#### 지표의 구성 요소

```
지표 = 데이터 출처 + 대상 + 비교 방식 + 목표값 + 관측 규칙
예) FRED · 미국 기준금리 · 이하 · 3.5% · 종가 기준 1회라도
    KIS  · 삼성전자    · 이상 · 95,000원 · 5거래일 연속 종가
```

- **비교 방식**: 이상 / 이하 / 범위 안 / 변화율(기준일 대비 ±N%)
- **관측 규칙**: 조건을 언제 "달성"으로 볼 것인지 명시한다.
  - 기간 내 1회라도 (장중 터치 포함 여부를 함께 정한다)
  - N거래일 연속 종가 기준
  - 특정 시점의 값 (예: 분기 말)
  - 이걸 정하지 않으면 "코스피 3000 돌파"가 장중 1초 터치로 달성되는지 아닌지 다투게 된다.

#### 여러 지표를 묶는 방식

지표가 여러 개일 때 **전부 달성(AND)만 강요하지 않는다.** 현실의 가설은 대부분 OR이거나
"몇 개 이상"이다. AND만 있으면 거의 모든 가설이 실패로 끝나 사용자가 지표 설정을 회피하게 된다.

- 전부 달성 (AND)
- 하나라도 달성 (OR)
- N개 중 M개 이상

#### 수치화할 수 없는 것은 사건형 지표로

규제 승인, M&A 성사, 경영진 교체처럼 숫자가 없는 조건도 있다. 이런 것은 **사건형 지표**
(예/아니오)로 두고 사용자가 직접 표시한다. 자동 수집은 안 되지만, "무엇이 일어나야 맞는
것인가"를 미리 못 박아두는 효과는 동일하게 얻는다.

#### 자동 판정은 하지 않는다 — 제안까지만

**지표가 전부 달성되어도 앱이 "맞았다"고 확정하지 않는다.** 지표는 내 논리와 무관한 이유로도
달성될 수 있고, 그걸 앱이 적중으로 처리해버리면 사용자는 틀린 논리를 옳다고 학습한다.
이 앱의 목적과 정면으로 어긋난다.

- 지표 달성 시: "지표가 전부 달성됐습니다. 어떻게 보시겠습니까?" → 사용자가 판단
- 기한 경과 + 지표 미달성 시: 자동 실패 처리가 아니라 `결과 확인 필요` 상태로 전환
- 결과 확인 선택지에 네 번째를 추가한다:
  `그대로 되었다` / `틀렸다` / `방향은 맞지만 시기를 다시 본다` /
  **`지표는 달성됐지만 내가 생각한 이유 때문은 아니었다`**

#### 지표를 나중에 고치면 이력이 남는다

지표를 사후에 유리하게 낮추면 이 기능 전체가 무의미해진다. 수정 자체는 허용하되,
**"처음엔 3,200이었는데 2,900으로 낮춤" 같은 변경 이력이 복기 화면에 반드시 남는다.**
원본 대화를 고치지 않는 원칙(§3.1)의 연장이다.

### 2.4 AI의 역할

AI는 판단에 필요한 정보를 모으고 정리해서 사용자가 더 나은 판단을 하도록 돕는
보조자이면서, 동시에 **적극적으로 의견을 개진하는 어드바이저**이기도 하다.

- **리서치 보조**: 노트/가설/시나리오와 관련된 최신 뉴스, 공시, 데이터를 조사해서 읽기 쉽게 요약.
- **관련성 판단**: 수집한 정보가 어떤 시나리오를 뒷받침하는지, 어긋나는지 표시.
- **리마인드 큐레이션**: 언제, 어떤 노트를, 어떤 맥락과 함께 다시 보여줄지 결정.
- **확률 갱신 제안**: 새 정보 기반으로 시나리오 확률 조정을 "제안"하되, 최종 확정은 사용자가 함.
- **소크라테스식 질문**: 사용자가 놓친 반대 시나리오나 리스크를 질문 형태로 환기.
- **직접적인 매수/매도 의견 제시**: AI 프롬프트 단에서는 매수/매도 추천, 목표가, 타이밍 의견 등을
  자유롭게 낼 수 있도록 제한을 두지 않는다. "투자 판단과 그 책임은 전적으로 사용자 본인에게
  있다"는 고지를 UI 레벨(예: 앱 전역 푸터, 리서치/추천 카드마다, 온보딩 등)에서 상시 노출하는
  것으로 책임 소재를 명확히 하고, 그 대신 AI는 판단을 흐리지 않고 소신 있게 의견을 낸다.
  즉 **면책은 UI의 책임, 유용하고 직접적인 조언은 AI의 책임**으로 역할을 분리한다.

## 3. 핵심 기능 명세

### 3.1 투자 노트 작성 — AI와의 대화 기반

노트는 폼 입력이 아니라 **AI와의 대화**로 만들어진다. 사용자는 생각나는 대로 말하고,
AI가 대화를 통해 필요한 구조를 끌어낸 뒤 노트를 작성한다. 폼을 강제하면 작성이 귀찮아져
기록 자체가 쌓이지 않고, 기록이 없으면 이 앱의 가치는 0이 되기 때문이다.

- 대화를 통해 AI가 확보해야 할 항목
  - 투자 대상(티커/자산/테마) — 필수
  - 핵심 가설 — 필수
  - 시나리오 2개 이상 (긍정/부정 등 대칭적 사고 유도) — 필수
  - 각 시나리오의 **판단 시점** (특정 날짜 또는 범위, 예: "2026 Q4까지") — 필수
  - 각 시나리오의 **판단 지표** (수치 조건, §2.3) — 필수. 근거 지표 최소 1개 권장
  - 반증 조건 — 권장
  - 근거 자료 (링크, 텍스트 메모, 파일, 스크린샷) — 선택
- AI는 **판단 시점과 판단 지표에 대해서만 끈질기게 확보를 시도**한다. 이 둘이 없는 시나리오는
  검증도 리마인드도 불가능해 앱의 존재 이유가 사라지기 때문. 다만 강요하지 않고 막연하면
  범위로라도 받아낸다.
- 지표를 끌어내는 대화는 다음 순서를 따른다.
  1. "그렇게 되고 있다는 걸 무엇을 보면 알 수 있을까요?" — 사용자가 떠올린 관측 대상 수집
  2. AI가 그것을 실제 데이터 계열로 변환해 제안 ("그건 FRED의 미국 기준금리로 볼 수 있습니다")
  3. "어느 수준이면 그렇다고 보시겠어요?" — 목표값 확보
  4. "장중에 잠깐 닿아도 되나요, 종가로 며칠 이어져야 하나요?" — 관측 규칙 확보
  5. 결과 지표만 나왔다면 근거 지표를 한 번 더 유도한다
     ("주가 말고, 그 전에 먼저 움직일 만한 게 뭐가 있을까요?")
- 대화 종료 시 AI가 노트 초안을 생성 → 사용자가 미리보기에서 확인·수정 후 저장
- **원본 대화 전문은 노트에 영구 첨부되며 수정·삭제할 수 없다.** AI가 노트를 쓰는 구조에서
  "과거의 나의 관점"이 AI의 문장이 되는 문제를 방지하는 장치로, 사용자는 언제든
  자신이 실제로 무슨 말을 했는지 원문으로 확인할 수 있다.
- 필수 항목이 덜 찬 노트도 저장 가능하되, 미완성 상태로 표시되고 리마인드 대상에서 제외된다.

> 화면 구성과 인터랙션 상세는 [`ux-design.md`](./ux-design.md) 참조.

### 3.2 리마인드 시스템
- 예약된 리마인드: 노트 작성 후 N일/주/월 후 자동 리마인드 (사용자 설정 가능, 기본값 제공)
- 시점 기반 리마인드: 시나리오의 예상 시점이 임박하거나 도래하면 알림
- 이벤트 기반 리마인드: AI가 수집한 뉴스가 특정 시나리오와 강하게 연관되면 즉시 알림
- 리마인드 화면 구성: "과거의 나는 이렇게 생각했다"(원문 그대로) + "그동안 이런 일이 있었다"(AI 요약)
  + "지금은 어떻게 보시나요?"(다시 판단하도록 유도)

### 3.3 AI 리서치 & 뉴스 모니터링
- 노트/가설/시나리오 단위로 관련 키워드·엔티티 자동 추출
- 주기적으로 (또는 온디맨드로) 관련 뉴스/공시/데이터 검색
- 검색 결과를 다음 기준으로 정리:
  - 어느 노트/시나리오와 관련 있는지
  - 해당 시나리오를 뒷받침하는지 / 어긋나는지 / 관련만 있는지
    (내부 값 `supports` / `contradicts` / `neutral`, 화면 표기는 UX 문서 §7.4 대응표를 따른다)
  - 한 줄 요약 + 원문 링크
- 사용자는 각 리서치 결과에 대해 "반영함/무시" 피드백 → AI 리서치 품질 개선에 활용

### 3.4 시나리오 트래킹 보드
- 노트별로 시나리오들을 보드 형태로 시각화, 홈에서는 전체 노트의 판단 시점을 타임라인으로 표시
- 시간 경과에 따른 확률 변화 이력
- 시나리오 상태 (화면 표기 / 내부 값): 지켜보는 중 `active` / 결과 확인 필요 `pending_judgment` /
  그대로 됨 `confirmed` / 틀렸음 `rejected`
  - **앱이 알아서 "틀렸다"고 정리하는 경우는 없다.** 시점이 지나면 `결과 확인 필요`가 되어
    리마인드가 뜨고, 결론은 반드시 사용자가 낸다.
  - 선택지는 네 가지:
    `그대로 되었다` / `틀렸다` / `방향은 맞지만 시기를 다시 본다` /
    `지표는 달성됐지만 내가 생각한 이유 때문은 아니었다`
    - 세 번째를 같은 비중으로 두는 이유: 현실에서 가장 흔한 경우가 "방향은 맞았는데 시기를
      잘못 봤다"인데, 틀렸다만 고를 수 있게 하면 사용자가 확인 자체를 피하고 방치하게 된다.
    - 네 번째는 근거 지표는 미달성인데 결과 지표만 달성된 경우를 잡아내기 위한 것이다(§2.3).
      운으로 맞은 것을 실력으로 착각하지 않게 하는 장치이며, 회고에서 가장 값진 기록이 된다.
    - 시점 재설정 시 `active`로 복귀하며, 재설정 이력은 회고용으로 보존한다.
  - 시나리오 카드에는 항상 **지표 달성 현황**이 함께 표시된다 (예: `지표 3개 중 2개 달성`).
    부분 달성은 그 자체로 강한 신호이므로 최종 판정 전에도 계속 보여준다.
  - 결과를 정할 때 이유를 한 줄 남기도록 권한다(선택). 이것이 가장 값진 회고 자료가 된다.
- 한 노트 안의 시나리오들은 **동시에 일어날 수 없는 경우로 보고, 확률 합을 항상 100%로** 맞춘다.
  하나를 올리면 다른 것이 줄어드는 제약이 있어야 트레이드오프 사고가 강제된다.
- 모든 노트에 지울 수 없는 **`그 외 예상 못한 전개`** 항목을 자동으로 만들고 최소 5%를 남긴다.
  "내가 생각한 경우가 전부"라는 착각을 구조적으로 막기 위함.

### 3.5 지표 수집 & 평가

- 사용자가 설정한 지표를 **하루 1회 배치로 수집**하고 달성 여부를 평가한다.
- 이 앱은 **실시간 시세가 필요 없다.** 지표는 종가·일별 값 기준으로 판정하고, 거시 통계는
  월·분기 단위로 갱신된다. 실시간을 전제하면 비용·라이선스·복잡도가 모두 불필요하게 올라간다.
- **지표 값은 사용자별이 아니라 전역으로 캐시한다.** 삼성전자 종가는 모든 사용자에게 같은
  값이므로, 외부 API 호출량은 사용자 수가 아니라 **서로 다른 지표의 개수**에 비례한다.
  노트 10개 내외 × 사용자 수천 명이어도 실제 호출은 수백 건 수준에 머문다.
- 평가 결과는 `IndicatorSnapshot`으로 날짜별 보존한다. "그때 실제로 얼마였는지"가 남아야
  나중에 복기가 가능하다.
- 달성/미달성이 바뀌는 순간은 리마인드 트리거가 된다 (§3.2의 이벤트 기반 리마인드).

### 3.6 회고 & 학습
- 특정 기간 동안 작성한 노트/시나리오들의 적중률, 판단 패턴 리포트
- "나는 낙관 시나리오를 과대평가하는 경향이 있다" 같은 개인화된 인사이트 (장기 로드맵)

### 3.7 AI 어드바이저
- 노트 상세 화면에서 "지금 어떻게 해야 할까?"를 AI에게 직접 물어볼 수 있다.
- AI는 현재 가설, 시나리오별 확률, 최근 수집된 정보를 근거로 **매수/홀드/매도 등 구체적인 스탠스**를
  명확히 제시한다. 애매한 원론적 답변이나 "전문가와 상담하세요" 같은 회피는 하지 않는다.
- 제시된 의견은 노트에 `AdvisorOpinion`으로 기록되어, 이후 리마인드 시점에 "그때 AI는 이렇게 말했고,
  나는 이렇게 판단했다"를 함께 되돌아볼 수 있다. (AI 의견의 적중률도 함께 축적됨)

### 3.8 면책 고지 UI
- 앱 전역에 "모든 투자 판단과 그 결과에 대한 책임은 사용자 본인에게 있습니다"를 상시 노출한다.
  - 온보딩 시 1회 명시적 동의
  - AI 의견/리서치 카드 하단에 고정 문구
  - 앱 전역 푸터 또는 설정 화면
- 이 UI 레이어가 면책을 전담하므로, AI 프롬프트에는 면책·회피 관련 제약을 넣지 않는다.

## 4. 사용자 플로우 (핵심 시나리오)

1. 사용자가 관심 종목에 대해 투자 노트를 작성 — 가설 + 시나리오(시점 포함) 입력
2. AI가 초기 리서치를 수행해 참고할 만한 배경 자료를 정리해서 첨부
3. 시스템이 리마인드 일정을 자동 생성
4. 시간이 지나며 AI가 지속적으로 관련 뉴스를 모니터링, 유의미한 소식은 즉시 카드로 정리해 노트에 첨부
5. 리마인드 시점이 되면 알림 → 사용자는 "과거 나의 관점 + 그동안의 새 정보"를 한 화면에서 확인
6. 사용자는 시나리오 확률을 조정하거나, 시나리오의 결과를 정하거나, 새 시나리오를 추가
7. 필요하면 AI 어드바이저에게 "지금 어떻게 해야 할까?"를 물어 구체적인 매수/홀드/매도 의견과
   근거·철회 조건을 받고, 그 의견을 노트에 기록
8. 시나리오의 목표 시점 도달 시, 결과 회고 작성 유도 (내 판단과 AI 의견 모두 사후 평가)

## 5. 데이터 모델 (초안)

```
User
 └─ Note (투자 노트)
     ├─ target: { type: ticker|asset|theme, symbol, name }
     ├─ thesis_summary: string
     ├─ thesis_detail: text
     ├─ created_at, updated_at
     ├─ sources: [Source]  (사용자가 첨부한 근거 자료)
     ├─ scenarios: [Scenario]
     ├─ remind_schedule: ReminderRule
     ├─ research_items: [ResearchItem]  (AI가 수집)
     ├─ advisor_opinions: [AdvisorOpinion]  (AI가 제시한 액션 의견)
     ├─ conversation: Conversation  (노트를 만들어낸 원본 대화, 수정·삭제 불가)
     ├─ color: string  (홈 타임라인에서 노트를 식별하는 고정 색상)
     └─ is_complete: boolean  (필수 항목 충족 여부. false면 리마인드 제외)

Conversation (원본 대화 — 수정·삭제 불가)
 ├─ note_id
 └─ messages: [{ role: user|assistant, content, created_at }]

ContentBlock (노트 본문을 구성하는 블록)
 ├─ note_id, section: thesis|scenario|...
 ├─ content: text
 ├─ authorship: ai|user          ← user일 때만 UI에 [사용자] 표기
 └─ quoted_from: message_id (nullable, 사용자 발화 직접 인용 시)

Scenario
 ├─ note_id
 ├─ name, description
 ├─ target_timeframe: { type: date|range, value }
 ├─ trigger_conditions: text
 ├─ probability_history: [{ value, updated_at, source: user|ai_suggested, reason: text }]
 ├─ status: active|pending_judgment|confirmed|rejected
 ├─ status_reason (결과를 그렇게 정한 이유)
 ├─ is_residual: boolean  (`그 외 예상 못한 전개`. 삭제 불가, 최소 5%)
 ├─ indicators: [Indicator]
 ├─ indicator_logic: all|any|at_least   (기본 all)
 ├─ indicator_threshold: int            (at_least일 때 M)
 └─ timeframe_reset_history: [{ from, to, reset_at, reason }]
      (시점을 다시 잡은 기록 — 회고용. 카드나 홈에는 드러내지 않음)

Indicator (판단 지표)
 ├─ scenario_id
 ├─ kind: leading|outcome        (근거 지표 / 결과 지표 — §2.3)
 ├─ type: numeric|event          (수치형 / 사건형)
 ├─ series: { provider: fred|ecos|kis|manual, code, label }
 │     예) { provider:"fred", code:"DFF",        label:"미국 기준금리" }
 │         { provider:"kis",  code:"005930.KS",  label:"삼성전자" }
 ├─ comparator: gte|lte|between|change_pct   (numeric일 때)
 ├─ target_value / target_range / baseline_date
 ├─ observation_rule: {
 │     mode: any_touch|consecutive_close|point_in_time,
 │     intraday_ok: boolean,     (any_touch일 때 장중 터치 인정 여부)
 │     consecutive_days: int     (consecutive_close일 때)
 │   }
 ├─ status: not_met|met
 ├─ met_at: date (nullable)
 ├─ progress: float  (목표까지 얼마나 왔는지 0~1. 부분 달성 표시용)
 └─ edit_history: [{ field, from, to, edited_at, reason }]
       (사후에 목표값을 유리하게 낮추는 것을 막기 위한 이력. 복기 화면에 노출된다)

IndicatorSnapshot (일별 관측값 — 전역 캐시)
 ├─ provider, code, date        ← (provider, code, date)가 유니크 키
 ├─ value: number
 └─ fetched_at
   ※ 사용자별로 저장하지 않는다. 같은 종목·지표는 모든 사용자가 공유한다.

Source (사용자 첨부)
 ├─ type: link|text|file|image
 ├─ content / url
 └─ created_at

ResearchItem (AI 수집)
 ├─ note_id, scenario_id (nullable, 노트 전체와 연관될 수도 있음)
 ├─ title, summary, url, published_at
 ├─ relation: supports|contradicts|neutral
 ├─ relevance_score
 └─ user_feedback: adopted|dismissed|none

AdvisorOpinion (AI의 액션 의견)
 ├─ note_id
 ├─ stance: buy|add|hold|trim|sell
 ├─ rationale: text (근거 요약)
 ├─ referenced_scenarios: [scenario_id]
 ├─ referenced_research: [research_item_id]
 ├─ target_price / target_timeframe (nullable)
 ├─ invalidation_condition: text (이 의견이 틀렸다고 볼 조건)
 ├─ created_at
 └─ user_action: followed|partially_followed|ignored|none  (사후 기록)

ReminderRule
 ├─ type: interval|scenario_deadline|pending_judgment|event_triggered
 ├─ config
 ├─ next_trigger_at
 ├─ consecutive_unopened: int  (빈도 자동 조절용 내부 값 — 화면에 절대 노출하지 않음)
 └─ current_interval_weeks: int  (연속 미열람 시 2배씩 증가, 최대 12주)
```

## 6. 시스템 아키텍처 (초안)

```
[Client: Web App / (향후 Mobile)]
        │
        ▼
[Backend API Server]
   ├─ Notes/Scenarios CRUD
   ├─ Reminder Scheduler (cron/queue 기반)
   └─ Auth / User
        │
        ├──────────────────────────────┐
        ▼                              ▼
[AI Orchestration Layer]      [Indicator Service]
   ├─ Research Agent             ├─ 일 1회 배치 수집 (장 마감 후)
   │    ├─ 뉴스/웹 검색           ├─ 달성 여부 평가 (관측 규칙별)
   │    ├─ 관련성 판단 & 요약      ├─ 전역 스냅샷 캐시
   │    └─ 시나리오 연결          │   (provider, code, date) 유니크
   ├─ Reminder Curation Agent    ├─ 상태 전이 시 리마인드 트리거
   ├─ Thesis Builder Agent       └─ 지표 카탈로그 검색
   │    └─ 대화 → 지표 후보 제안       (사용자 표현 → 실제 계열 코드 매핑)
   └─ Advisor Agent
        │                              │
        ▼                              ▼
[Data Store]
   ├─ RDB (Notes, Scenarios, Indicators, IndicatorSnapshot, Users)
   ├─ Vector DB (노트/뉴스 임베딩 → 유사도 기반 관련 뉴스 매칭, 향후)
   └─ Object Storage (첨부 파일/이미지)
        │
        ▼
[External Integrations]
   ├─ 뉴스/검색 API
   ├─ 시세·거시지표 API (FRED / 한국은행 ECOS / 한국투자증권)
   └─ 알림 (Push / Email)
```

**Indicator Service를 별도 축으로 두는 이유**: AI 리서치와 완전히 다른 성질의 작업이다.
리서치는 비결정적이고 온디맨드이며 비용이 LLM 호출에 비례하지만, 지표 수집은 결정적이고
스케줄 기반이며 비용이 외부 API 쿼터에 걸린다. 실패 시 재시도 전략도 다르다.
(지표는 하루치를 놓쳐도 다음 배치에서 소급 수집하면 되지만, 리서치는 그렇지 않다.)

### 외부 데이터 소스 선정

> 아래 수치는 2026년 8월 기준 확인값이다. 무료 티어 정책은 자주 바뀌므로 착수 시 재확인할 것.

**채택**

| 소스 | 범위 | 조건 | 비고 |
|---|---|---|---|
| **FRED** | 미국·글로벌 거시 (금리, CPI, 실업률, GDP) | 무료, API 키 발급 | 공공 데이터, 상용 이용 제약 없음 |
| **한국은행 ECOS** | 한국 거시 (기준금리, 물가, 환율, 수출입) | 무료, API 키 발급 | 공공 데이터 |
| **한국투자증권 Open API** | 국내·해외 주식 및 지수 시세 | 이용료 없음, 계좌 개설 필요 | REST + WebSocket, 초당 20건 제한, 리눅스 서버에서 동작 |

**배제 — 이유가 각기 다르다**

| 소스 | 배제 사유 |
|---|---|
| **yfinance** | Yahoo의 비공식 엔드포인트를 긁는 방식이고, Yahoo API 약관은 수익을 얻는 용도의 사용을 금지한다. 개인 학습·프로토타입용이며 이 앱이 유료화되는 순간 쓸 수 없다. 엔드포인트가 예고 없이 바뀌어 깨지는 문제도 있다. |
| **Alpha Vantage** | 무료 티어가 **하루 25요청**(분당 5요청)으로 축소되어 실사용이 불가능하다. 지표 수십 개를 매일 수집하는 이 앱의 요구를 충족할 수 없다. |
| **Finnhub** | 무료 티어(분당 60요청)가 **비상업 용도로 제한**된다. 유료화 시 사용 불가라 yfinance와 같은 문제를 안는다. |
| **Polygon.io** | 무료 플랜이 분당 5요청 + 장 마감/15분 지연 데이터로 좁고, 무료 티어 유지 여부에 대한 정보가 엇갈린다. 유료 전환 시 후보로 재검토. |
| **키움증권 Open API** | Windows 32bit COM 객체 방식이라 리눅스 백엔드에서 쓸 수 없다. |

**프로토타입 단계의 예외**: 개발 초기에 `yfinance`로 빠르게 데이터 파이프라인을 검증하는 것은
가능하다. 단 **출시 전 반드시 교체한다는 전제**로만 쓰고, 데이터 소스 인터페이스를 추상화해
교체 비용을 낮춰 둔다. 프로토타입 코드가 그대로 상용에 남는 것이 가장 흔한 사고다.

**설계상 유리한 점**: 이 앱은 **실시간 시세가 필요 없다.** 지표는 종가 기준으로 하루 1회
평가하면 충분하고, 거시 통계는 월·분기 단위로 갱신된다. 실시간 요구가 없으면 위 무료 소스만으로
충분히 상용 서비스를 운영할 수 있다. 이것이 이 기능의 비용 구조를 결정한다.

|---|---|
| 프론트엔드 | Next.js (React) + TypeScript |
| 백엔드 | Node.js (NestJS) 또는 Python (FastAPI) |
| DB | PostgreSQL |
| 벡터 검색 | pgvector 또는 별도 Vector DB (향후 도입) |
| AI/LLM | Claude API (Messages API, 도구 사용을 통한 웹 검색/리서치 에이전트) |
| 스케줄링 | 백엔드 내 cron 또는 메시지 큐 (예: BullMQ) |
| 시세·지표 | FRED + 한국은행 ECOS + 한국투자증권 Open API |
| 배포 | Docker 기반, 클라우드 (Vercel/AWS 등) |

> 스택은 확정이 아니라 논의를 위한 출발점. 실제 개발 착수 전 재검토 필요.

## 7. AI 기능 상세 설계

### 7.1 Research Agent
- **입력**: 노트의 target, thesis_summary, 각 시나리오의 description/trigger_conditions
- **동작**:
  1. 키워드/엔티티 추출
  2. 웹/뉴스 검색 실행
  3. 검색 결과 중 관련성 높은 것만 필터링 (relevance_score 산출)
  4. 각 결과를 요약하고, 어떤 시나리오를 지지/반박하는지 분류
  5. 노트에 ResearchItem으로 저장, 유의미도가 높으면 즉시 알림 트리거
- **실행 주기**: 기본 주기(예: 매일 1회) + 사용자 온디맨드 요청

### 7.2 Reminder Curation Agent
- 여러 경로에서 발생한 리마인드(정기/시점/새 정보)를 모아 우선순위를 정하고 한 번에 묶어 보내,
  알림이 과도해지지 않게 한다
- 리마인드 시 "과거 관점 요약 + 새 정보 요약 + 재평가 유도 질문" 형태로 콘텐츠 구성

### 7.3 Thesis Builder Agent (대화형 노트 작성)
노트 작성의 보조가 아니라 **작성 수단 그 자체**다. 대화를 통해 필수 항목을 확보하고
노트를 작성한다.

- **대화 단계**: 대상 파악 → 관심 이유 → 핵심 가설 → 반대 시나리오 → 판단 시점 → 확인 지표
- **질문 예시**
  - "반대로 흘러간다면 어떤 모습일까요?"
  - "이건 언제쯤 판가름 날까요?" (시점 확보 — 가장 집요하게)
  - "무엇을 보면 그렇게 되고 있다는 걸 알 수 있을까요?"
  - "이 판단이 틀렸다는 건 뭘로 알 수 있을까요?" (반증 가능성)
- **턴 수 목표: 5~8턴.** 심문처럼 느껴지면 작성을 포기하게 되므로 길이 관리가 중요하다.
- **노트 생성**: 대화 종료 시 구조화된 노트 초안을 작성. 사용자 발화를 직접 인용한 부분은
  `[사용자]`로 표기해 AI 문장과 구분한다.
- **원본 대화 보존**: 대화 전문을 수정·삭제 불가로 저장. AI가 노트를 쓰는 구조이므로,
  "실제로 내가 한 말"에 대한 접근 경로가 반드시 유지되어야 한다.

### 7.4 Advisor Agent (직접 의견 제시)
- 사용자가 요청하면(또는 리마인드/리서치 결과와 함께) 현재 가설·시나리오·최신 정보를 종합해
  **명확한 액션 의견**을 제시한다.
  - 매수 / 추가매수 / 홀드 / 일부익절 / 전량매도 등 구체적 스탠스
  - 근거가 되는 시나리오와 정보, 목표 가격대·기간(가능한 경우)
  - 이 의견이 틀렸다고 판단할 조건(손절/철회 트리거)
- **프롬프트 원칙**: "투자 조언을 할 수 없다", "전문가와 상담하라" 류의 회피성 문구를 넣지 않는다.
  근거가 부족하면 회피하는 대신 "무엇을 더 알면 판단이 명확해지는지"를 말한다.
- **일관성 체크**: 사용자의 과거 가설과 현재 제시하는 의견이 상충하면 그 사실을 명시적으로 지적한다.
  (메멘토 컨셉의 핵심 — 과거의 나와 지금의 판단을 대조)
- 면책 문구는 AI 응답 본문이 아니라 UI 레이어에서 일괄 처리한다. (AI 출력에 매번 면책을 섞으면
  가독성과 신뢰도가 떨어지므로)

## 8. MVP 범위

투자 판단 보조라는 핵심 가치를 가장 빠르게 검증할 수 있는 범위로 제한한다.

**MVP 포함:**
- 홈: 가까운 미래 판단 시점 타임라인 + 리마인드 피드
- 대화형 노트 작성 (Thesis Builder Agent) → 노트 초안 생성 → 미리보기·수정 → 저장
- 원본 대화 전문 보존 및 열람
- 노트 상세: 좌(나의 관점) / 우(새 정보) 분리 레이아웃, 시나리오 보드
- 시나리오별 확률 입력(합 100%, `그 외 예상 못한 전개` 포함) 및 변경 이력 조회(리스트)
- 시나리오 상태 변화 및 네 가지 선택지
- 판단 지표 설정(대화 중), 일 1회 수집·평가, 달성 현황 표시
- 지표 데이터 소스: FRED + ECOS + 한국투자증권
- 리마인드 상세 3단 화면 (과거의 나 → 그동안의 일 → 지금은?)
- 기본 주기 리마인드 + 시점 기반 리마인드, 이메일 알림
- AI 리서치: 온디맨드 실행 (노트 상세 화면 "지금 다시 조사하기") — 자동 주기 실행은 이후 단계
- 수집한 정보에 뒷받침/어긋남 표시, 사용자 피드백(반영/무시)
- AI 어드바이저: 온디맨드로 매수/홀드/매도 스탠스와 근거를 받아보고 `AdvisorOpinion`으로 기록
- `[사용자]` 저작 표기
- 면책 고지 UI (온보딩 동의 + 전역 상시 노출)
- 반응형 웹 (데스크톱 전체 → 모바일 리마인드 확인 플로우 순으로 구현)

**MVP 제외 (이후 단계로 이연):**
- 자동 주기적 백그라운드 리서치 크롤링, 이벤트 기반 즉시 알림
- 벡터 검색 기반 정교한 관련성 매칭
- 확률 변화 그래프 시각화 (MVP는 이력 리스트로 대체)
- 회고/패턴 분석 리포트
- PWA 푸시 알림, 네이티브 모바일 앱, 소셜/공유 기능
- 시세 연동, 포트폴리오 관리 기능 (보유 수량·단가 등 실제 포지션 입력 일체)

## 10. 리스크 및 고려사항

- **투자자문 규제 리스크**: AI 프롬프트 자체는 매수/매도 의견을 자유롭게 낼 수 있도록 열어두는 대신,
  "최종 투자 판단과 그 책임은 사용자 본인에게 있다"는 면책 고지를 UI 전반(온보딩, 노트/리서치
  화면, 추천 카드 등)에 상시 노출한다. 다만 이는 제품 방향에 대한 결정이며, 실제 서비스 지역/약관에
  따라 투자자문업 관련 법적 리스크가 있을 수 있으므로 정식 출시 전 법률 검토가 필요하다.
- **정보 신뢰성**: AI가 수집한 뉴스/요약의 출처를 항상 함께 제공하여 사용자가 검증 가능하게 함.
- **알림 피로 / 죄책감**: 리마인드가 과도하거나 부채감을 주면 앱 자체를 안 열게 된다.
  미룬 횟수·달성률·스트릭·배지 카운트 같은 압박 장치는 제품 차원에서 금지하고, 반복해서 열리지
  않는 리마인드는 벌 대신 노출 빈도를 자동으로 낮춘다. (UX 설계 원칙 P5)
- **데이터 프라이버시**: 개인의 투자 관점/포지션은 민감 정보이므로 저장/전송 시 보안 설계 필요.
- **AI 비용**: 리서치 에이전트의 실행 빈도가 늘어날수록 API 비용 증가 → 사용자별/노트별 실행 정책 필요.
- **지표 데이터 소스 의존**: 무료 API의 티어 정책은 예고 없이 축소된다(Alpha Vantage가 하루
  500요청에서 25요청으로 줄어든 것이 실례다). 데이터 소스를 추상화 계층 뒤에 두어 교체 가능하게
  설계하고, 특정 제공자에 종속되는 코드를 만들지 않는다.
- **지표의 오용**: 결과 지표만 달면 가설 검증이 아니라 동어반복이 된다(§2.3). AI가 대화에서
  근거 지표를 확보하지 못하면 이 기능 전체가 형식만 남는다. 대화 설계의 품질이 곧 기능의 품질이다.
- **지표 사후 조작**: 목표값을 나중에 유리하게 낮추면 복기가 무의미해진다. 수정 이력을 반드시
  보존하고 복기 화면에 노출한다.

## 11. 확정된 결정 사항

UX 설계 과정에서 확정된 항목들. 상세 근거는 [`ux-design.md`](./ux-design.md) 참조.

| 항목 | 결정 |
|---|---|
| 플랫폼 | 반응형 웹. 데스크톱 전체 → 모바일 리마인드 확인 플로우 순으로 구현 |
| 홈 화면 | 가까운 미래 판단 시점 타임라인 + 리마인드 피드 (노트 목록은 별도 탭) |
| 노트 작성 | AI와의 대화 → AI가 노트 작성. 폼 입력 방식은 쓰지 않음 |
| 동시 관리 노트 수 | 10개 내외 전제. 폴더/태그 없이 단순 리스트 + 검색 |
| 리마인드 강제성 | 없음. 미룸 횟수 기록·노출 금지, 스트릭/달성률 금지 |
| 누가 쓴 글인지 | AI가 쓴 글은 표시 없음, 사용자가 쓴 부분에만 `[사용자]` 표기 |
| 내 사고 ↔ 외부 정보 | 공간적으로 분리. 리마인드 화면에서만 의도적으로 대비 |
| 포지션 입력 | MVP 제외 (관점 기록과 자산 관리는 별개 제품으로 봄) |
| 확률 표현 | 한 노트 안에서 합 100%, 5% 단위로만 조정 |
| AI 의견 강도 | "적극 제안" 고정. 매수/매도 의견에 제약 없음 |
| 반증 가능성 | 모든 시나리오에 수치 조건(판단 지표)을 필수로 붙인다 |
| 지표 종류 | 근거 지표 / 결과 지표로 구분, 근거 지표 최소 1개 권장 |
| 지표 결합 | 전부(AND) / 하나라도(OR) / N개 중 M개 — AND 강요하지 않음 |
| 지표 판정 | 앱은 제안만 한다. 자동으로 적중/실패를 확정하지 않는다 |
| 시세 데이터 | 실시간 불필요. 일 1회 종가 기준 배치 + 전역 캐시 |

## 12. 오픈 이슈 (추후 논의 필요)

- 어떤 자산군까지 지원할지 (주식/코인/부동산/거시경제 테마 등)
- 지표 카탈로그를 어디까지 미리 등록할지. 사용자가 말한 표현("유동성")을 실제 계열로 매핑하는
  일이 이 기능의 사용성을 좌우하는데, 전부 AI에 맡길지 사전 사전(辭典)을 만들지 미정
- 암호화폐 지표를 넣을 경우의 데이터 소스 (현재 채택한 셋으로는 커버되지 않음)
- 지표 달성 알림을 이벤트 기반 즉시 알림으로 볼지, 일일 배칭에 포함할지
- 뉴스/데이터 소스 API 선정
- 무료/유료 정책 (AI 리서치 실행 횟수 제한 등)
- 노트 작성 대화의 적정 턴 수 (목표 5~8턴, 실측 필요)
- 타임라인 구간 경계값(`이번 주 / ~1개월 / ~3개월 / ~6개월 / 그 이후`)의 실사용 적합성
- 노트 간 거시 변수 연결을 언제 도입할지 (가치는 크나 내비게이션 단순성과 충돌)
- AI 의견 강도를 사용자가 조절 가능하게 할지
