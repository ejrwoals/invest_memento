## 1. 설계 원칙

이 앱의 모든 화면과 조작은 아래 8개 원칙을 따른다.
개별 화면 설계에서 판단이 갈릴 때는 이 원칙으로 되돌아온다.

### P1. 앱을 열면 "지금 봐야 할 것"이 먼저 나온다
노트 목록이 홈이면 이 앱은 메모장이 된다. 사용자가 스스로 찾아 열어야만 작동하는 도구는
메멘토 컨셉을 달성하지 못한다. 홈은 **가까운 미래의 타임라인 + 리마인드 피드**이고,
노트 목록은 별도 탭이다.

### P2. 원본 대화는 고치지 않는다
노트 본문은 AI가 대화를 바탕으로 작성한다. 이 구조에서 "과거의 나의 관점"이 엄밀히는
AI의 문장이 되므로, **사용자가 실제로 말한 원본 대화 전문은 절대 수정·요약·삭제되지 않고
그대로 보존**된다. 노트는 그 위에 얹힌 읽기 좋은 렌더링일 뿐이며, 사용자는 언제든
"내가 실제로 뭐라고 말했는지" 원문으로 내려갈 수 있다. 이것이 이 앱의 신뢰 기반이다.

### P3. 사용자가 쓴 것을 표시한다 (AI가 아니라)
노트 내용의 대부분은 AI가 작성하므로, `[AI]` 태그를 붙이면 화면이 태그로 뒤덮인다.
**드문 쪽인 사용자가 쓴 부분에만 `[사용자]` 표기를 붙인다.** (§9 참조)

### P4. 내 사고와 외부 정보는 섞이지 않는다
과거의 내 관점과 AI가 새로 가져온 정보가 한 덩어리로 뒤섞이면, 시간이 지났을 때
"내가 원래 뭘 생각했는지"가 오염된다. 두 영역은 화면상 **공간적으로 분리**되며,
리마인드 화면에서만 의도적으로 나란히 대비시킨다.

### P5. 죄책감을 유발하지 않는다
강제성 있는 리마인드는 스트레스가 되고, 스트레스는 앱을 안 열게 만든다.
다음을 **금지**한다:
- 미룬 횟수 / 무시한 횟수의 기록 및 노출
- 연속 달성(스트릭), 완료율, 점수, 등급
- 빨간 배지 카운트, 밀린 항목 누적 표시
- "확인하지 않으셨습니다", "N일째 방치 중" 류의 문구

미뤄진 리마인드는 조용히 큐로 돌아가고, 반복적으로 열리지 않으면 **벌이 아니라 적응**으로서
노출 빈도를 낮춘다.

### P6. 기록의 진입장벽을 최소화한다
가설·시나리오·시점을 폼으로 강제하면 데이터는 깔끔해지지만 작성이 귀찮아져 기록이 안 쌓인다.
기록이 없으면 이 앱은 가치가 0이다. 따라서 **작성은 AI와의 대화로 이루어지고, 구조화는
AI가 책임진다.**

### P7. 깊고 풍부한 노트, 단순한 내비게이션
동시 관리 노트는 10개 내외를 전제한다. 폴더·태그·복잡한 필터에 화면을 쓰지 않고,
**개별 노트를 깊게 보여주는 데 화면 예산을 집중**한다.

### P8. 우리끼리 쓰는 말을 화면에 내보내지 않는다
설계 과정에서 만든 용어는 팀 안에서는 편하지만, 사용자에게는 아무 의미가 없다.
사용자는 앱을 배우러 온 것이 아니라 자기 생각을 기록하러 온 것이다.
**화면에 나가는 모든 문구는 이 앱을 처음 여는 사람이 설명 없이 이해할 수 있어야 한다.**

- 전문용어처럼 보이는 말, 새로 만든 합성어, 영어 약어를 화면에 쓰지 않는다.
- 상태나 기능의 이름은 **그 상태에서 사용자가 할 일**로 짓는다.
  (`판정 대기` ✗ → `결과 확인 필요` ○ — 무슨 상태인지가 아니라 무엇을 하면 되는지를 말한다)
- 개발상의 이름(`pending_judgment`)과 화면에 나가는 말은 별개다. 코드에서 쓰는 식별자를
  그대로 번역해서 화면에 올리지 않는다. (§9.4 대응표 참조)
- **설계 근거도 우리끼리 쓰는 말이다.** 왜 이렇게 만들었는지는 사용자가 궁금해하지 않고,
  하지도 않은 일의 이유를 읽으면 오히려 무슨 말인지 알 수 없다. 화면에는 무슨 일이
  일어나는지만 적는다. (§9.3)
- 문서 안에서도 마찬가지다. 개념에 이름을 붙이기 전에, 그냥 풀어 쓰면 되는지 먼저 확인한다.

이 앱의 고유 개념 중 화면에 드러내도 되는 것은 **메멘토**(제품 컨셉 자체)뿐이다.

## 2. 정보 구조 (IA)

```
┌─ 홈 (타임라인 + 리마인드 피드)          ← 기본 진입점
│
├─ 노트
│   ├─ 노트 목록
│   ├─ 보유 종목                          ← 노트 목록 상단에서 전환, 홈 넛지로도 진입
│   └─ 노트 상세
│        ├─ 가설 & 시나리오 보드
│        ├─ 새 정보 서랍 (AI 리서치)
│        ├─ 원본 대화 기록
│        ├─ 생각이 바뀐 기록
│        └─ 회고록 (결과 확정 후)
│
├─ 새 노트 작성
│   ├─ 1단계 · AI 대화 (논리)             ← 전역 진입 가능
│   ├─ 노트 초안 확인 (AI가 채운 칸을 검토)
│   └─ 2단계 · 확인 방법 설정 (폼, 건너뛰기 가능)
│
├─ 리마인드 상세                          ← 홈/알림에서 진입
│
└─ 설정
     ├─ 리마인드 주기 / 알림 채널
     └─ 계정
```

**전역 내비게이션은 3개로 고정한다: `홈` / `노트` / `+ 새 노트`**
설정은 우상단 아바타 메뉴로 밀어낸다. 탭이 늘어나면 P7에 위배된다.
보유 종목도 탭으로 만들지 않는다 — 등록·수정할 때나 들어가는 화면이라 방문 빈도가
낮고, 이 화면의 진짜 산출물(노트 없는 종목 넛지)은 홈 피드가 대신 나른다.
노트 탭 안의 전환 뷰로 둔다. (§3.7)

#### 타임라인 상세 규칙

**시간축은 세로다.** 눈에 보이는 선을 하나 긋고, 그 위에 판단 시점마다 점을 찍고,
점과 카드를 짧은 선으로 잇는다.

**구간 이름(`이번 주`, `~1개월`)은 구분선을 가로질러 한가운데 놓는다.** 축 왼쪽에 붙이면
날짜·D-day와 같은 열에 놓여 서로 섞여 읽힌다. 구분선은 화면 폭 전체를 가로지르며 축과도
교차하므로, 라벨이 가운데 있어야 "이 선이 구간을 나눈다"는 것이 즉시 읽힌다.

- **왜 세로인가**: 가로축은 항목이 늘어나면 구간마다 마커가 쌓여 무너진다. 노트 10개에
  시나리오가 2~3개씩이면 마커가 20~30개인데, 고정 폭 5구간에 그걸 담을 수 없다.
  세로축은 스크롤로 얼마든지 늘어나므로 개수 증가를 그대로 감당한다.
  §11.1의 축 원칙과도 맞는다 — **타임라인은 비교가 아니라 순서이므로 세로가 제자리다.**
- **데스크톱과 모바일이 같은 구조를 쓴다.** 방향이 같으므로 폭만 달라진다.
  넓은 화면에서는 축 왼쪽 여백에 날짜와 D-day를 놓고, 좁은 화면에서는 축을 왼쪽 끝에
  붙이고 날짜를 카드 안으로 넣는다.
- **압축은 필요 없어졌다.** 가로축일 때는 가까운 미래를 넓게 잡아야 시선이 갔지만,
  세로축에서는 **가까운 것이 먼저 나오는 것만으로 충분하다.** 구간 사이 간격을 인위적으로
  조절하지 않는다.
- **마커 표현**:
  - 특정 시점 → 축 위의 점(`●`). 채워진 점은 임박, 빈 점은 여유 있음
  - 기간형("2026 Q4까지") → 점 대신 **축을 따라 흐르는 구간 막대**.
    세로축에서는 기간이 길이로 자연스럽게 읽힌다
- **침전**: 먼 시점의 항목은 채도와 투명도를 낮춘다(P3 원칙 — `saturate(.5)` `opacity(.78)`).
  가까운 것과 먼 것이 같은 무게로 보이지 않게 한다.
- **밀집 처리**: 한 구간에 항목이 5개를 넘으면 `+N개 더 보기`로 접는다.
- **지나간 것은 표시하지 않는다.** 확인이 밀린 시나리오는 타임라인이 아니라 리마인드 피드에서
  `결과 확인 필요` 카드로 다룬다. (지나간 항목이 축 위쪽에 쌓이면 P5 위반)
- **피드와 타임라인은 같은 시나리오를 공유한다.** 지금 확인이 필요한 항목은 피드에도 뜨고
  축에서도 강조색 점으로 표시되어, 두 영역이 같은 것을 가리키고 있음이 보인다.

#### 왜 피드가 위, 타임라인이 아래인가

둘은 서로 다른 질문에 답한다.

| | 질문 | 정렬 |
|---|---|---|
| 리마인드 피드 | 지금 무엇을 봐야 하나 | 우선순위 순 |
| 타임라인 | 앞으로 무엇이 오나 | 시간 순 |

앱을 여는 이유는 대개 전자다(P1). 그래서 피드가 먼저 오고, 조망은 그 아래에서 스크롤로 본다.

#### 리마인드 피드 상세 규칙

- **기본 3장까지만 노출**, 나머지는 `더 보기`. (알림 피로 방지)
- 카드 우선순위: `결과 확인 필요 > auto 조건 달성 > 시점 임박 > 새 정보 > 정기 리마인드`
- **카드에는 "닫기(X)"가 없다.** 대신 카드를 열지 않고 넘기면 자동으로 뒤로 밀린다.
  명시적 "무시" 액션을 두면 무시했다는 사실이 인지되고, 그것이 곧 부채감이 된다. (P5)
- 각 카드는 **왜 지금 이게 떴는지를 한 줄로 반드시 설명**한다. 이유 없는 알림은 소음이다.
- **빈 상태**: 볼 것이 없을 때 "모두 완료!" 같은 성취 문구를 쓰지 않는다.
  ```
  지금 다시 볼 것은 없습니다.

  마지막으로 기록한 지 3주가 지났습니다.
  요즘 생각하고 계신 것이 있나요?          [ 새 노트 ]
  ```

### 3.2 새 노트 작성 — 1단계: AI와의 대화

폼이 아니라 대화다. 사용자는 생각나는 대로 말하고, AI가 필요한 구조를 끌어낸다. (P6)

**작성은 두 단계로 나뉜다.** 여기 1단계는 사고를 끌어내는 대화이고, 수치 설정은
노트 저장 후 2단계 폼(§3.3)에서 따로 받는다. 한 대화에서 둘 다 받으면 질문이 열 번을
넘어가 사용자가 이탈한다.

> **논리는 대화로, 수치 설정은 폼으로.**
> 대화는 "왜"를 끌어내는 데 강하고, 폼은 "얼마"를 받는 데 강하다.

```
┌────────────────────────────────────────────────────────────┐
│  ← 나가기                              새 노트 · 대화 중    │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  AI  요즘 어떤 투자 아이디어를 생각하고 계신가요?            │
│      종목이든 테마든, 편하게 말씀해 주세요.                  │
│                                                            │
│                          삼성전자 HBM 때문에 관심 보는 중   │
│                          근데 아직 확신은 없어              │
│                                                            │
│  AI  HBM 쪽을 보시는군요. 어떤 점 때문에                    │
│      관심이 가셨는지 조금 더 들려주시겠어요?                 │
│                                                            │
│                     ... (대화 계속) ...                    │
│                                                            │
│  ┌──────────────────────────────────────────────────┐     │
│  │  지금까지 정리된 내용                             │     │
│  │  ✓ 투자 대상      ✓ 핵심 가설                     │     │
│  │  ✓ 시나리오 2개   ✓ 판단 시점                     │     │
│  │  ⚠ 근거 항목 1개 비었음                           │     │
│  └──────────────────────────────────────────────────┘     │
│                                                            │
│  [ 메시지 입력...                          ] [보내기]      │
│                                     [ 여기까지 정리하기 ]  │
└────────────────────────────────────────────────────────────┘
```

#### 대화가 끌어내야 할 것 (AI의 목표)

우선순위 순으로, 자연스러운 대화 안에서 확보한다. 심문처럼 느껴지면 안 된다.

| 항목 | 필수 | AI의 접근 |
|---|---|---|
| 투자 대상 | ✔ | 첫 발화에서 대개 확보됨 |
| 핵심 가설 | ✔ | "그래서 결국 어떻게 될 거라고 보시는 거죠?" |
| 시나리오 (2개 이상) | ✔ | "반대로 흘러간다면 어떤 모습일까요?" |
| 갈래의 **질문** | ✔ | "그날 무엇이 확인되면 답이 나오나요?" |
| 갈래의 **판단 시점** | ✔ | "이건 언제쯤 판가름 날까요?" — 갈래마다 하나 |
| 가설의 **근거 항목** | ✔ | "그렇게 되려면 그 전에 무슨 일이 먼저 일어나야 할까요?" — 노트에 한 벌 |
| 근거 자료 | 선택 | 사용자가 링크를 붙이면 수집 |
| 반증 조건 | 권장 | "이 판단이 틀렸다는 건 뭘로 알 수 있을까요?" |

**판단 시점과 근거 항목, 이 둘에 대해서만 AI가 끈질기다.** 시점이 없으면 리마인드가
불가능하고, 근거 항목이 없으면 나중에 회고할 대상이 없어진다. 다만 강요하지는 않고,
막연하면 범위("올해 안", "다음 실적 발표쯤")로라도 받아낸다.

**확인 방법은 여기서 묻지 않는다.** 목표값·비교 방식 같은 것은 2단계 폼으로 넘긴다.
다만 대화 중에 숫자가 나오면("3.5% 아래로는 가야지") 조용히 기억해 두었다가
2단계 폼의 초기값으로 채운다. 되묻지 않는다.

#### 근거 항목을 끌어내는 대화 — 이건 반드시 1단계에서 받는다

판정 조건만 있으면 "예상한 일이 일어났는가"는 알 수 있지만 **"그게 내 논리 때문이었는가"는
알 수 없다.** 주가가 올랐어도 시장 전체가 올라서일 수 있다. 그래서 내 논리의 중간 고리를
따로 받아둔다.

**이것만은 2단계로 미루지 않는다.** 논리는 사용자가 자기 생각을 말하는 흐름 속에서 받아야
진짜가 나온다. 나중에 폼으로 따로 물으면 이미 정리된 결론에 맞춰 사후 합리화된 답만
돌아온다. 숫자를 묻지 않으므로 한 턴이면 끝나 대화 길이에도 부담이 적다.

정말 중요한 중간 고리들(DRAM 현물가, HBM 매출 비중 같은 것)은 유료 산업 데이터라 API로
가져올 수 없다. **그래서 여기서는 수치화를 시도하지 않는다.** 사용자가 말로 설명한 그대로
받아두고, 나중에 회고할 때 AI가 자료를 조사한다.

```
  AI  마지막으로 하나만요.
      말씀하신 대로 되려면, 그 전에 무슨 일이 먼저 일어나야 할까요?

                    HBM 공급 부족이 계속돼야 하고
                    삼성이 엔비디아 퀄 테스트를 통과해야지

  AI  적어두겠습니다. 나중에 결과가 나오면 이 두 가지가
      실제로 일어났는지 제가 찾아서 정리해 드릴게요.

      ┌────────────────────────────────────────┐
      │ 이 판단이 성립하려면          [사용자]  │
      │ 1. HBM 공급 부족이 2026년 내내 지속     │
      │ 2. 삼성전자가 엔비디아 퀄 테스트 통과   │
      └────────────────────────────────────────┘
```

- **수치나 데이터 출처를 되묻지 않는다.** "그건 어디서 확인하나요?"라고 물으면 사용자는
  막히고 대화가 늘어진다. 자동 추적이 목적이 아니라 검증할 대상을 남기는 것이 목적이다.
- 근거 항목은 사용자의 말이므로 `[사용자]` 저작으로 표기한다.
- 근거 항목 중 마침 FRED·ECOS로 추적 가능한 것(금리, 환율, 수출 증가율 등)이 있으면
  AI가 조용히 지켜보는 수치로 담아둔다. 판정하지 않고, 사용자에게 되묻지 않는다.
- AI는 "나중에 제가 찾아서 정리해 드리겠다"고 **약속을 명시한다.** 지금 답을 못 주는
  질문을 던지는 이유를 사용자가 이해해야 성의 있게 답한다.

#### 대화 종료 → 노트 초안 확인

- 사용자가 `여기까지 정리하기`를 누르거나, AI가 필수 항목을 다 확보하면 제안한다.
- AI는 **자유 형식으로 글을 쓰지 않는다. 정해진 칸을 채운다.** 미리보기 화면은 그 칸들을
  그대로 보여주는 화면이다.

```
  대상          삼성전자 005930
  ──────────────────────────────────────────────────────────
  핵심 가설      HBM 공급 부족으로 후발주자 점유율 확보
                HBM 공급이 수요를 따라가지 못하는 상태가 이어지면…
                │ [사용자] "공급이 수요를 못 따라가니까 결국…"
  ──────────────────────────────────────────────────────────
  갈래 1        올해 안에 엔비디아 HBM4 공급사로 진입하는가?
                [ 판단 시점 2026.12.31 · "올해 안"을 이렇게 읽었습니다  고치기 ]
                01 진입한다    02 진입하지 못한다
  갈래 2        2027년 상반기까지 선두와의 기술 격차가 좁혀지는가?
                [ 판단 시점 2027.06.30 · "내년 상반기"를…        고치기 ]
                01 좁혀진다    02 좁혀지지 않는다
                답이 나오는 날이 달라 갈래 1과 나눠 두었습니다
  ──────────────────────────────────────────────────────────
  이 판단이      1  HBM 공급 부족이 계속돼야 한다
  성립하려면     2  삼성이 엔비디아 퀄 테스트를 통과해야 한다
                [사용자] 말씀하신 그대로 옮겼습니다. 다듬지 않습니다.
  ──────────────────────────────────────────────────────────
  확률          아직 비어 있습니다 · 다음 단계에서 정합니다
  확인 방법      아직 비어 있습니다 · 다음 단계에서 정합니다
```

- **AI가 해석한 값은 숨기지 않고 드러낸다.** "올해 안"을 `2026.12.31`로 읽었다는 사실을
  칸 옆에 적고 `고치기`를 붙인다. 조용히 날짜만 넣으면 사용자는 앱이 자기 말을 어떻게
  알아들었는지 모른 채 저장하게 된다.
- **빈 칸은 비운 채로 보여준다.** AI가 대화에 없는 내용을 지어내 채우면, 몇 달 뒤 되돌아볼
  "과거의 나"가 하지도 않은 생각이 된다. 이 앱의 존재 이유가 무너진다.
- 각 칸은 `수정` 가능하고, 직접 고친 블록은 `[사용자]`로 표기된다. (§9)
- "이건 내가 말한 뜻과 다른데" → 그 자리에서 대화로 되돌아가 보정 가능.
- `다시 만들기`는 **저장 전에만** 가능하고, 사용자가 손댄 블록은 보존한다.
  저장 후 재생성은 과거 기록을 바꾸는 일이므로 허용하지 않는다.
- 저장 시 **원본 대화 전문이 노트에 영구 첨부**된다. (P2)

> 각 칸의 작성 규칙(길이, 누가 채우는지, 원문을 얼마나 보존하는지)과 검증 방식은
> [`development-plan.md`](./development-plan.md) §3.1 '노트 생성 계약' · '노트 검증'에
> 정의되어 있다.

#### 이탈과 재개

- 대화 중 이탈해도 임시 저장(draft)되며, 홈 상단에 조용히 재개 링크가 뜬다.
- 필수 항목이 덜 찬 상태로도 저장 가능. 단 이 노트는 **미완성 상태**가 되어
  리마인드 대상에서 제외되고, 노트 상세 상단에 "판단 시점을 정하면 리마인드가 시작됩니다"
  라는 안내가 붙는다. (차단이 아니라 안내 — P5)

### 3.3 확인 방법 설정 — 2단계 (건너뛸 수 있음)

노트 저장 직후 이어지는 화면이다. **대화가 아니라 폼이고, 빈 폼이 아니라 채워진 폼이다.**

이 화면이 정하는 것은 **갈래마다 어느 답이 기계로 확인되는가**다. 시나리오 밑에 조건을
여러 개 다는 자리가 아니다. 한 답의 auto 조건은 하나뿐이고, 여집합인 답과
`그 외 예상 못한 전개`는 `complement`라 조건을 갖지 않으므로 화면에 나타나지 않는다.

목표값·비교 방식 같은 것은 대화로 물으면 사고의 흐름을 끊는다. 폼에서는 눈으로 보고
고르면 되므로 훨씬 빠르다.

```
┌──────────────────────────────────────────────────────────────┐
│  노트가 저장되었습니다                                          │
│                                                              │
│  결과를 자동으로 확인해 드릴까요?                                │
│  정해두면 조건이 충족되는 날 알려드립니다.                        │
│  ────────────────────────────────────────────────────────    │
│                                                              │
│  갈래 1 · 엔비디아 HBM4 공급사로 진입하는가 · 2026.12.31까지     │
│  ┌────────────────────────────────────────────────────┐     │
│  │ 이 질문은 수치로 확인할 수 없습니다                   │     │
│  │ 판단 시점이 오면 제가 여쭙겠습니다.                    │     │
│  │                                                    │     │
│  │ 대신 지켜볼 수치를 담아둘까요?                        │     │
│  │  · 삼성전자 주가 (한국투자증권)          [ 담기 ]     │     │
│  │    판정에는 쓰지 않고 추이만 보여드립니다              │     │
│  └────────────────────────────────────────────────────┘     │
│                                                              │
│  갈래 2 · 기준금리가 3.5% 이하로 내려가는가 · 2027 Q2까지        │
│  01 내려간다                                                  │
│  ┌────────────────────────────────────────────────────┐     │
│  │ 미국 기준금리 (FRED · DFF)                [바꾸기]  │     │
│  │                                                    │     │
│  │  [ 이하 ▾ ]  [ 3.5 ] %                             │     │
│  │                                                    │     │
│  │  ⓘ 기간 중 한 번이라도 닿으면 달성입니다.             │     │
│  │    이 기준은 바꿀 수 없습니다.                        │     │
│  └────────────────────────────────────────────────────┘     │
│  02 내려가지 않는다 — 여집합이라 조건을 두지 않습니다            │
│                                                              │
│  ────────────────────────────────────────────────────────    │
│  ▸ 근거 항목 중에 지켜볼 수 있는 게 하나 있습니다                 │
│    "HBM 공급 부족 지속" → 관련 계열을 찾지 못했습니다            │
│    "금리 인하"          → 미국 기준금리 (FRED)      [ 담기 ]   │
│                                                              │
│                              [ 나중에 하기 ]  [ 저장 ]        │
└──────────────────────────────────────────────────────────────┘
```

#### 화면 규칙

- **AI가 후보를 미리 채워둔다.** 갈래의 질문에서 종목·지수·거시 계열을 추출해 데이터
  소스와 함께 올리고, 대화에 숫자가 나왔으면(`3.5% 아래로는 가야지`) 목표값도 채워 둔다.
  사용자는 확인하고 고치기만 하면 된다.
- **질문이 수치에 관한 것이 아니면 auto를 권하지 않는다.** `HBM4 공급사로 진입하는가`에
  주가를 붙이라고 하지 않는다. 주가가 올랐다고 수주를 받은 것이 아니다. 대신 **지켜볼
  수치**로 담을지 묻고, 담아도 판정에는 쓰지 않는다. 이 구분이 무너지면 결과 확인 화면이
  "주가가 올랐으니 맞은 것 같다"고 말하기 시작하고, 그건 이 앱이 잡으려던 소 뒷걸음질을
  판정 단계에서 미리 만들어내는 것이다.
- **관측 규칙은 묻지 않는다.** `기간 중 한 번이라도 닿으면 달성 · 장중 포함`으로 고정하고
  안내 문장 한 줄만 둔다. 선택지로 내놓으면 사용자가 답할 준비가 안 된 질문 앞에 서게 되고,
  거기서 이탈한다.
- **여집합인 답과 `그 외 예상 못한 전개`는 이 화면에 나오지 않는다.** 조건을 가질 수 없기
  때문이다. `+ 추가` 버튼도 붙이지 않는다 — 붙이면 둘 다 달성인 상태를 만들 수 있다.
- **근거 항목 중 지켜볼 수 있는 것을 하단에 따로 제안한다.** 대부분은 찾지 못하는데,
  그 사실도 그대로 보여준다. 숨기면 사용자는 앱이 뭘 하는지 모른다. 담아도 판정하지
  않는다 — 근거가 맞았는지는 회고에서 따진다.

#### 건너뛰어도 앱은 정상 동작한다

`나중에 하기`가 **1급 선택지**다. 흐릿하게 처리하거나 구석에 두지 않는다.

| 빠진 것 | 결과 |
|---|---|
| 판단 시점 | 미완성 노트. 리마인드에서 제외 |
| auto 조건 | **정상 노트.** 시점 리마인드·회고록 모두 작동. 자동 제안만 없다 |

- auto 조건이 없는 노트는 판단 시점이 되면 그냥 `결과 확인 필요`가 되고, 사용자가 직접
  표시한다. `HBM4 공급사로 진입하는가`처럼 계열로 살 수 없는 질문이 오히려 흔하므로
  이것이 예외가 아니라 기본에 가깝다.
- 노트 상세에는 `판단 시점이 오면 여쭙겠습니다`라는 안내 한 줄이 조용히 붙는다.
  **설정하지 않은 노트의 개수를 세거나 배지를 띄우지 않는다.** (P5)
- 나중에 설정하려면 노트 상세의 갈래 머리에서 바로 들어간다.

### 3.4 노트 상세 — 나의 사고가 본문, 새 정보는 서랍

**이 화면의 본문은 나의 사고다.** 세상이 가져온 정보는 오른쪽 가장자리의 **책갈피**를 당겨
여는 서랍에 들어 있다.

처음에는 좌우 6:4 두 열로 놓았다. 두 가지가 문제였다.

1. **왼쪽이 훨씬 길다.** 가설·근거 항목·갈래·추이 차트가 쌓이는 왼쪽에 비해 새 정보는
   서너 건이라, 오른쪽 열 아래로 화면 절반이 늘 비었다.
2. **새 정보가 늘 눈에 있으면 본문을 읽는 데 방해가 된다.** 노트 상세는 *내가 무슨 생각을
   했는지 읽는 자리*다. 최신 뉴스가 옆에서 계속 말을 걸면 그 프레임으로 과거를 읽게 된다.

서랍으로 바꾸면 **P4가 약해지는 게 아니라 오히려 분명해진다.** 두 영역이 같은 평면에
나란히 있는 대신, 새 정보는 *의도적으로 열어야 나오는 다른 공간*이 된다.
과거와 현재를 나란히 놓고 대비시키는 일은 리마인드 화면(§3.5)이 전담한다.

#### 구성 요소

**좌측 — 나의 관점 (변화가 느리고, 내가 소유하는 영역)**
- 핵심 가설: AI가 작성한 요약. 사용자 원문 인용은 `[사용자]`로 구분 표시.
- **갈래 머리에 질문과 판단 시점**: 갈래는 하나의 질문이다. 그 질문을 도넛 위에 그대로
  적고, 답이 나오는 날을 바로 아래 한 번만 적는다. 질문이 없으면 시나리오 목록이 무엇의
  답인지 알 수 없고, `그 외 예상 못한 전개`가 무엇의 여집합인지도 읽히지 않는다.
- **판단 시점은 갈래에 하나뿐이다.** 시나리오 카드마다 날짜를 적으면 배타적인 답들이
  서로 다른 날 갈리는 것처럼 보인다. 날짜가 실제로 다르다면 그건 한 갈래가 아니라 질문
  둘이므로, 화면에도 갈래 블록을 둘로 나눠 보여준다.
- **시나리오 제목은 질문에 대한 답만 담는다.** 이유와 경로는 제목 아래 한 줄로 내린다.
  제목에 원인이 섞이면(`증설로 공급이 풀려 기술 격차만 확인`) 답들끼리 축이 어긋나
  60% 대 30%가 무엇 대 무엇인지 읽히지 않는다.
- **갈래 헤더에 도넛**: 갈래 안 시나리오들의 구성비를 한 번에 보여준다(§6).
  조각 경계는 흐리게 그려 확률의 범위를 나타낸다.
- 시나리오 카드: 확률 숫자 + **판정 방법에 따른 현황** + 상태. 판단 시점은 카드가 아니라
  갈래 머리에 한 번만 적는다 — 한 갈래는 같은 날 한꺼번에 갈리기 때문이다.
  제목 앞에 도넛 조각과 같은 색 표식을 붙여 카드 ↔ 조각을 잇는다. `다시 판단하기` 버튼 포함.
  - 확률은 큰 숫자 + 조각 색으로 보여주고, 변화는 그 옆에 문장으로 적는다(§6).
  - auto 답은 `95,000원까지 · 지금 92,800`처럼 목표까지의 거리를 적고, 그 아래에
    **축약 추이 그림**을 놓는다(§7). 목표선과 띠만 남긴 형태라 "띠를 벗어났는가"로
    달성 여부가 즉시 읽힌다. 부분 달성은 그 자체로 강한 신호이므로 판정 전에도 계속 노출한다.
  - **manual 답**은 `판단 시점이 오면 여쭙겠습니다`라고만 적는다. 계열로 살 수 없는
    질문이 오히려 흔하므로 이것은 결함 표시가 아니다.
  - **complement 답**(여집합·`그 외`)은 `01이 달성되지 않으면 이 답입니다`라고 적고
    조건을 붙일 자리를 만들지 않는다.
  - **auto를 설정하지 않은 시나리오**는 그 자리에 `조건을 정하면 자동으로 확인해 드립니다`
    안내와 진입 링크가 대신 놓인다(§3.3). 경고색을 쓰지 않고, 개수를 세지 않는다. (P5)
  - **노트 전체에 auto 조건도 지켜보는 수치도 하나도 없으면 이 안내를 갈래마다 반복하지
    않는다.** 2단계를 통째로 건너뛴 직후(방금 저장한 노트 대부분이 이 상태다)라면 시나리오
    카드마다 같은 문장이 두세 번 찍혀 화면이 안내문으로 뒤덮인다. 이 경우 시나리오 카드
    안의 반복 안내를 접고, 가설 바로 아래에 한 번만 `아직 지켜볼 수치가 없습니다 · 확인
    방법을 정하면 여기에 그림이 생깁니다`와 `확인 방법 정하기` 진입 링크를 놓는다.
    빈 차트를 그리는 대신, 채우면 무엇이 생기는지를 말해준다.
  - 근거 항목은 갈래가 아니라 **가설에 붙는다.** 화면에서도 가설 바로 아래, 갈래보다 위에
    둔다. 한 노트에 갈래가 둘이어도 밑에 깔린 논리 사슬은 하나이므로 갈래마다 되풀이하지
    않는다. 반대 시나리오에 붙는 `이렇게 흘러간다면 이런 모습입니다` 목록은 근거 항목이
    아니다 — AI가 조사해 담은 서술이고, 회고에서 검증하지 않는다.
  - 노트 상세에는 `이 판단이 성립하려면` 섹션으로 근거 항목이 함께 보인다. 자동 추적되지
    않으므로 체크 표시가 붙지 않고, 결과 확정 후 회고록에서 조사 결과가 채워진다.
- `그 외 예상 못한 전개` 항목 (§6 참조)
- **다음에 살펴볼 것**: AI가 언제 무엇을 다시 볼지 평범한 문장으로 미리 적어 둔다.
  ```
  다음에 살펴볼 것
  8.31 · CPI 발표
    발표되면 이 갈래의 전제와 맞는지 확인합니다
  9.13 · WTI 유가
    지켜보는 수치를 다시 확인합니다
  ```
  - 날짜가 발표 캘린더에서 왔는지 재확인 주기에서 왔는지는 화면에서 구분하지 않는다.
    사용자에게 중요한 건 "다음에 언제 다시 보는가" 하나뿐이다(개발 문서 §3.3).
  - 문구는 언제나 `확인합니다`까지만 적는다. `알려드립니다`라고 적지 않는다 — 특이사항이
    없으면 그날 아무 알림도 오지 않는데, 알려준다고 적어두면 그 조용함이 "왜 안 왔지"가
    된다. 이 목록은 리마인드를 예약하는 화면이 아니라 **AI가 지켜보고 있다는 증거**다.
  - 점검이 끝나면 항목은 조용히 다음 예정일로 넘어간다. "봤는데 별일 없었다"는 따로
    보고하지 않는다(P5).
  - 판단 시점, 지켜보는 수치, auto 조건이 하나도 없는 노트는 이 섹션 자체가 비어 있다 —
    개수를 세거나 비었다고 경고하지 않는다.
  - 홈 타임라인에는 올리지 않는다. 홈의 세로 타임라인은 "내가 결론 내야 하는 날"(판단
    시점)만 다루는 축으로 이미 자리를 잡았고, 여기에 "AI가 대신 보는 날"까지 섞으면
    두 성격이 뒤섞여 정작 사용자가 뭔가 해야 하는 날의 신호가 흐려진다(§3.1).
- 접히는 섹션: 내가 붙인 자료 / 원본 대화 기록 / 생각이 바뀐 기록

**우측 — 새로 들어온 정보 (변화가 빠르고, 외부에서 오는 영역)**
- 시간 역순 피드. 각 항목은 요약 1~2줄 + 관계 태그 + 원문 링크.
- 관계 표시: `↗ 뒷받침함` / `↘ 어긋남` / `— 관련 있음` — 어느 시나리오에 대한 것인지 함께 적는다.
- `반영` 버튼: 이 정보를 근거로 시나리오를 다시 판단하는 화면으로 이동.
- `지금 다시 조사하기`: 온디맨드 리서치 실행. (MVP의 주 실행 경로)

#### 책갈피

```
  ┌──────────────────────────────────────┬──┐
  │  핵심 가설                            │ 3│  ← 새 정보 개수
  │  ...                                 │새│
  │  갈래                                 │정│
  │  ...                                 │보│
  │                                      │ ›│
  └──────────────────────────────────────┴──┘
```

- 오른쪽 가장자리에 붙어 **일부만 삐져나온 형태**다. 책에 끼운 책갈피처럼 읽는다.
- 표시하는 것은 **개수 하나뿐**이다. 빨간 배지를 쓰지 않고, 0이면 숫자 없이 조용히 둔다. (P5)
- 누르면 서랍이 열리고 책갈피가 함께 밀려나며 화살표가 `‹`로 바뀐다.
  같은 자리에서 닫을 수 있으므로 별도 닫기 버튼이 없다.
- **기본은 닫힘이다.** 새 정보를 먼저 보면 그 프레임으로 과거를 해석하게 된다.


#### 덜 채워진 노트는 무엇이 없는지 말한다

실제 대화가 늘 필요한 걸 다 내주지는 않는다. 반대 시나리오를 묻는 대목이 없었던 대화라면
시나리오가 하나만 남는다. **AI는 나머지를 지어내지 않는다.**

```
  ┌────────────────────────────────────────────────────┐
  │ ⓘ 반대 시나리오가 없습니다                           │
  │   대화에서 "이 판단이 틀린다면 어떤 모습일까" 하는     │
  │   이야기가 나오지 않아 비워 두었습니다. 대안이 없는    │
  │   가설은 나중에 맞았는지 틀렸는지 가리기 어렵습니다.   │
  │                                    [지금 추가하기]   │
  └────────────────────────────────────────────────────┘
```

- **무엇이 왜 비었는지**를 함께 적는다. "필수 항목 누락" 같은 표시만으로는 사용자가
  자기가 뭘 안 했는지 모른다.
- 시나리오가 하나뿐이면 **갈래가 성립하지 않으므로 확률도 비운다.**
  카드에는 `—`와 함께 "확률은 반대 시나리오가 생긴 뒤에 나눕니다"를 적는다.
  (혼자인 시나리오에 100%를 채워 넣으면 확신을 앱이 부추기는 꼴이 된다)
- 그래도 **판단 시점이 있으면 리마인드는 정상 작동한다.** 덜 채워졌다고 노트를 잠그지 않는다.
- 경고색은 이 안내 하나에만 쓰고, 홈이나 목록에서 개수를 세지 않는다. (P5)

#### 반응형 — 구조가 같아졌다

서랍으로 바꾸면서 **데스크톱과 모바일이 같은 구조**가 되었다. 폭만 다르다.

| | 본문 | 서랍 |
|---|---|---|
| 넓은 화면 | 최대 820px | 오른쪽 340px. 본문을 가리지 않도록 폭을 맞춘다 |
| 좁은 화면 | 전체 폭 | 전체 폭 시트. 책갈피는 제자리에 남아 닫기 역할을 한다 |

이전의 모바일 탭 전환은 없앤다. 같은 일을 하는 장치가 둘일 이유가 없다.
상세는 [§11.3 노트 상세](#노트-상세--서랍-하나로-통일했다) 참조.

### 3.5 리마인드 상세 — 이 앱의 핵심 화면

홈의 리마인드 카드를 열면 도달한다. **3단 구성이 고정**이며 순서가 중요하다.
반드시 "과거의 나"를 먼저 읽고, 그 다음에 "그동안의 일"을 본다.

```

  당시 확률 수치까지 그대로 보여준다 — 지금과의 차이가 스스로 드러나야 한다.
- `당시 대화 전문 보기`로 언제나 원본 대화까지 내려갈 수 있다.
- **②는 ①을 읽은 다음에 온다.** 순서가 바뀌면 최신 뉴스의 프레임으로 과거를 읽게 되고,
  그것이 바로 이 앱이 막으려는 문제다.
- **③에서 AI는 소신 있게 의견을 낸다.** 확률 조정, 매수/매도 판단, 타이밍 견해 모두
  제약 없이 제시한다. 면책은 UI 하단 고지가 담당한다.
- **`그대로 봅니다`는 읽었고, 안 바꿨다는 뜻이다.** AI가 확률 조정을 제안했어도 사용자
  판단이 그대로면 조정 화면을 열 필요가 없다. `다시 판단하기`와 달리 확률 이력에 새
  항목을 남기지 않는다 — 바뀐 값이 없으니 남길 것도 없다. 다만 노트의 `마지막 검토`
  시점은 지금으로 갱신된다.
  `나중에`와의 차이는 이것 하나다: `나중에`는 안 본 것이고 `그대로 봅니다`는 보고 나서
  안 바꾼 것이다. 이 구분이 없으면 리마인드 노출 빈도 조정 로직(P5 — "반복적으로 열리지
  않으면 노출 빈도를 낮춘다")이 "무시당함"과 "매번 확인하지만 결론이 같음"을 구분하지
  못해, 성실하게 재확인하는 사용자의 리마인드 빈도까지 함께 줄어든다.
- `나중에`는 아무 기록도 남기지 않는다. 미룬 횟수를 세지 않는다. (P5)

### 3.7 보유 종목과 매매 기록

노트 목록 상단에서 `노트 | 보유 종목`으로 전환한다. 원본은 매매 기록이고 잔고는
파생이다. 자산 현황판이 아니라 **"내 판단 중 기록 안 된 것"을 찾아내고, 판단의
성적(수익률)을 종목·포트폴리오 단위로 보여주는 화면**이다. (dev-plan §3.9)

```
┌──────────────────────────────────────────────────────────────┐
│  노트 · 보유 종목                        [ + 매매 기록 ]      │
│                          전체 수익률(XIRR) 연 +12.4%  ←크게  │

├──────────────────────────────────────────────────────────────┤
│  매매 기록                                                   │
│  12.15  환전 $→₩  1,432.50원 × $500    실현 +47,250원        │
│  12.10  삼성전자  매수  84,000원 × 15  “실적 보고 추가 매수” │
│  11.20  삼성전자  배당  361원 × 30                           │
│  11.02  한화오션  매수  71,200원 × 12  “MRO 수주 기대”       │

- **탭은 `국내 | 미국 | 환전` 셋이다.** 국내·미국은 통화(원/달러)와 거래 시간대가 달라
  한 목록에 섞으면 가격을 같은 자로 읽게 되어서, 환전은 "환전에만 집중해서 보고 싶을
  때"가 있어서다(사용자 결정). 종목 탭 이름 옆에는 종목 수를 붙인다(`국내 2 · 미국 1`).
- **매매 기록 목록은 탭을 따른다.** 국내 탭 = 국내 거래·배당, 미국 탭 = 미국 거래·배당,
  환전 탭 = 환전. 각 탭은 자기 기록만 보여준다.
- **어느 탭에 들어갈지는 사용자가 고르지 않는다.** 매매 기록의 티커 정규화에서 시장이
  자동으로 정해진다. 노트 연결과 같은 원칙이다 — 분류 작업을 사용자에게 시키지 않는다.
- **매매 기록 추가는 모달이다.** 입력 폼을 목록 아래에 두면 기록이 늘수록 폼이 아래로
  밀려 스크롤 끝까지 내려가야 나온다. 진입점은 상단의 `+ 매매 기록` 버튼 하나로
  고정하고, 모달에서 매수/매도, 종목, 날짜, 단가, 수량, 코멘트(선택)를 받는다.
  별도의 "종목 추가"는 없다 — 새 종목의 첫 매수 기록이 곧 종목 추가다.
- **수량을 직접 입력받지 않는다.** 잔고는 매매 기록의 합(Σ매수 − Σ매도)으로만 만들어져,
  기록과 잔고가 어긋날 길이 없다. 앱 도입 전부터 보유하던 종목은 과거 날짜의 매수
  기록으로 등록하되, 당시 단가를 모르면 비워 둔다 — 그 종목의 수익률 칸은 `단가 없음`
  으로 남는다. 지어낸 단가로 계산한 수익률은 하지도 않은 판단이다.
- **코멘트는 그때의 판단 한 줄이다.** 매매 기록 목록에 원문 그대로 보여주고,
  `[사용자]` 저작 표기 원칙을 따른다(9.1절 — 사용자가 쓴 글이므로 별도 태그는 없다).
  몇 달 뒤 이 줄이 "그때 나는 왜 샀는가"의 최소 단위 기록이 된다.
- **현재가는 화면을 열 때 조회하고, 조회 시점을 가격 옆에 항상 표기한다.** 실시간이
  아니라는 사실을 숨기지 않는다. 수동 새로고침 버튼 하나만 둔다. 장중인지 폐장인지
  화면은 구분하지 않는다 — 폐장이면 마지막 체결가가 보일 뿐이고, 조회 시점 표기가
  그 사실을 감당한다.
- **조회에 실패해도 목록은 그대로 산다.** 가격·평가금액 칸만 `조회 실패 · 다시 시도`로
  바뀌고, 종목·수량·노트 연결·넛지는 정상 동작한다.
- **종목별로 평단·평가금액·수익률을 표시한다.** 수익률은 상승/하락 색(기존 rise/fall
  팔레트)을 쓰되 숫자에만 칠한다 — 행 전체를 물들이면 목록이 손익판이 된다.
  매도 기록 줄에는 실현 손익을 함께 적는다.
- **전체 수익률은 탭 위에, 탭별 수익률은 각 탭 첫 줄에.** 탭 위에는 `전체 수익률(XIRR)
  연 +12.4%` 한 줄 — 모든 탭에 걸친 숫자라 탭 밖에 살고, 우측 정렬에 숫자를 큰 글자로
  둔다(이 화면의 결론 숫자다). 각 탭의 첫 줄에는 그 탭의 성적 —
  국내: `국내 수익률(XIRR) · 평가손익 합 · 실현 합`, 미국: `미국 수익률(XIRR·달러) ·
  평가손익 합($)`, 환전: 환차손익 평가·실현과 취득 환율 대비 %. 탭 안은 단일 통화라
  손익 금액 합산이 성립한다 — 금지하는 것은 통화를 섞는 합산(총자산)뿐이다.
  단가 없음 종목이 제외됐으면 그 사실을 옆에 작게 적는다.
- **손익 추이는 요약 줄의 버튼으로 여는 우측 시트다.** 각 탭 첫 줄(수익률 요약) 우측에
  `과거 수익률 차트 보기` 버튼을 두고, 누르면 오른쪽에서 시트가 열리며 그 탭의 날짜별
  누적 손익(국내: 원, 미국: 달러, 환전: 환차손익 원)을 종가 기준 라인차트로 보여준다.
  목록 화면에 상시로 깔지 않는 이유: 추이는 가끔 확인하는 정보라, 상시 노출하면 목록이
  길어지고 손익 곡선이 화면의 주인공이 된다. 사용자가 수익 스냅샷을 찍지 않는다 —
  장부와 일별 종가·환율로 시스템이 과거 전 구간을 재구성한다. 추이선에 색을 쓰지
  않고(§7), 0선을 점선으로 깐다. 기간 선택은 없다 — 기록이 시작된 날부터 전부.
- **미국 주식의 손익은 달러로만 적는다.** 원화 환산 평가금액은 현재 환율 기준 참고
  표기로 평가금액 아래 작게만 붙인다 — 재환전 전까지 원화 손익은 미실현이라는 사실을
  화면 위계가 그대로 말한다. (dev-plan §3.9 외화와 환전)
- **환전과 배당도 매매 기록의 한 줄이다.** `환전 ₩→$`는 달러 매수, `환전 $→₩`는 달러
  매도, `배당`은 주당 배당액 × 수량으로 같은 목록에 시간순으로 섞여 흐른다. 재환전
  줄에는 실현 환차손익이 붙는다. 배당 기준일 같은 예정 정보는 장부에 넣지 않는다.
- **환전 탭이 달러의 자리다.** 종목 행 대신 달러 요약이 산다 — 예수금(장부에서 파생),
  환전 원금 잔량, 평균 취득 환율과 현재 환율(조회 시점), 환차손익 평가·실현.
  미실현 환차손익은 **환전 원금 잔량** 기준이다 — 주식으로 번 달러에는 취득 환율이
  없으므로 환차손익을 주장하지 않는다. 예수금이 음수로 계산되면 숫자 대신
  `기록이 맞지 않습니다 — 빠진 매매나 환전이 있는지 확인해 주세요`를 보여준다.
  입력을 막지는 않는다.
- **노트 연결은 자동이다.** 종목 티커가 같은 노트를 세어 `노트 N개`로 보여주고,
  누르면 해당 노트(여럿이면 목록 필터)로 간다. 사용자가 수동으로 연결하게 하지 않는다.
- **노트 바로가기는 고정 폭 열이다.** 노트가 없는 행에도 빈 자리를 그대로 남긴다.
  버튼 유무에 따라 행마다 수치가 밀리면 수량·현재가·평가금액을 세로로 훑어 읽을 수 없다.
- **노트 없는 종목이 이 화면의 주인공이다.** 노트 바로가기가 비는 자리에 `+ 노트 추가`
  버튼을 세운다 — 행 아래에 전체 폭 안내 띠를 깔지 않는다. 목록이 번잡해지고,
  버튼이 없는 행과의 정렬도 깨지기 때문이다. `아직 기록된 판단이 없습니다 — 어떤
  생각으로 들고 계신가요?` 문장은 버튼에 마우스를 올렸을 때 툴팁으로만 띄운다.
  호버가 없는 모바일에서는 버튼만 남는다 — 문장은 홈 피드의 넛지 카드가 대신 나른다.
  버튼을 누르면 그 종목이 대화의 출발점으로 넘어간 채 1단계 대화가 시작된다 —
  AI의 첫 질문이 "요즘 어떤 투자 아이디어를…"이 아니라 "한화오션을 보유 중이시네요.
  어떤 생각으로 들고 계신가요?"가 된다.
- 같은 넛지를 홈 피드에도 카드로 얹되, 리마인드 카드보다 항상 아래에 둔다.
  "기록 안 된 종목 N개" 같은 개수 압박은 하지 않는다. (P5)
- 정렬: 각 탭 안에서 노트 없는 종목이 위, 나머지는 종목명 순. 평가금액 순 정렬은 두지
  않는다 — 이 목록의 주인공은 큰 포지션이 아니라 기록 안 된 판단이다.

## 4. 시나리오의 상태 변화

시나리오가 어떤 상태를 거치는지는 이 앱의 핵심 로직이다.
**앱이 알아서 "틀렸다"고 정리해버리는 경우는 없다. 결론은 항상 사용자가 낸다.**

```
                      ┌────────────┐
     노트 생성  ─────▶ │  지켜보는 중 │
                      └─────┬──────┘
                            │  판단 시점이 됨
                            ▼
                    ┌───────────────┐
                    │ 결과 확인 필요  │  ← 리마인드가 뜬다
                    └──┬────┬────┬──┘     (앱이 결론 내지 않음)
          사용자가 선택 │    │    │
          ┌────────────┘    │    └────────────┐
          ▼                 ▼                 ▼
    ┌───────────┐    ┌───────────┐    ┌──────────────┐
    │ 그대로 됨  │    │  틀렸음   │    │  시점을 다시  │
    │           │    │           │    │ → 지켜보는 중 │
    └───────────┘    └───────────┘    └──────────────┘
```

### 상태 정의

화면에 나가는 말과 개발상의 이름을 분리한다. (P8)

| 화면 표기 | 내부 식별자 | 의미 | 진입 조건 |
|---|---|---|---|
| 지켜보는 중 | `active` | 아직 판단 시점이 오지 않음 | 생성 시 기본값 / 시점을 다시 정했을 때 |
| 결과 확인 필요 | `pending_judgment` | 시점이 지났거나 auto 조건이 달성되어 사용자 확인을 기다림 | 판단 시점 경과, 또는 auto 조건 충족 (시스템 자동) |
| 그대로 됨 | `confirmed` | 시나리오대로 전개됨 | 사용자가 선택 |
| 틀렸음 | `rejected` | 시나리오가 틀렸음 | 사용자가 선택 |

### 결과를 정하는 화면 — 수치 현황을 먼저 보여준다

판정 전에 **그때 수치가 실제로 어땠는지**를 먼저 보여준다. 기억이 아니라 기록으로
판단하게 하는 것이 이 앱의 목적이다.

auto 답과 지켜보는 수치마다 **기록 시점부터 판단 시점까지의 추이 그림**(§7)을 먼저 놓고, 그 아래에 달성 여부를
요약한다. 숫자만 보면 "95,000을 넘었다"만 남지만, 그림을 보면 **어떻게 넘었는지**가 남는다.

```
┌──────────────────────────────────────────────────────┐
│  판단 시점이 지났습니다 · 2026.12.31                   │
│  엔비디아 HBM4 공급사로 진입하는가?                     │
│                                                      │
│  01 진입한다        수치로 확인할 수 없는 답입니다       │
│  02 진입하지 못한다  01이 아니면 이 답입니다             │
│                                                      │
│  지켜보던 수치 (판정에는 쓰지 않습니다)                  │
│   · 삼성전자   77,463 → 97,400                        │
│   · 코스피      2,780 →  3,050                        │
│  ────────────────────────────────────────────────    │
│  ⚠ 갈래 2의 목표값을 3,400 → 3,200으로 낮춘 적 있음     │
│                                                      │
│  예상하신 일이 일어났나요?                              │
│  [ 그대로 되었다 ]  [ 틀렸다 ]                          │
│  [ 방향은 맞지만 시기를 다시 본다 ]                      │
│                                                      │
│  * 이 판단이 정말 내 논리 때문이었는지는                  │
│    다음 단계에서 자료를 찾아 함께 봅니다.                 │
└──────────────────────────────────────────────────────┘
```

**이 화면은 "예상한 일이 일어났는가"만 묻는다.** "그게 내 논리 때문이었는가"는 자료를
조사해봐야 알 수 있어서 이 자리에서 물으면 사용자가 답할 수 없다. 그 질문은 다음 단계인
회고록(§5)이 담당한다. 두 질문을 한 화면에 섞으면 둘 다 대충 답하게 된다.

**앱은 판정하지 않는다.** auto 조건이 달성되어도 "적중"으로 확정하지 않고 사용자에게 묻는다.
조건이 서로 어긋나면 제안 자체를 하지 않고 양쪽 현황을 나란히 보여준다.

- 세 번째를 고르면 새 판단 시점을 입력받고 `지켜보는 중`으로 돌아간다.
  목표에 근접해 있으면(위 예시의 95%) 이 선택지가 시각적으로 먼저 눈에 띄게 한다.
  **시점을 다시 잡은 기록은 남는다** — 벌점이 아니라, 나중에 되돌아볼 때
  "나는 늘 너무 빠르게 예상한다"는 버릇을 발견하기 위한 자료다.
  이 기록은 노트 안쪽 이력에서만 보이고, 카드나 홈에는 드러내지 않는다. (P5)
- 어느 것을 고르든 **이유를 한 줄 남기도록 권한다** (선택 사항).
- 목표값을 도중에 수정한 적이 있으면 이 화면에 반드시 표시한다.
  숨기면 복기가 자기기만이 된다.
- `그대로 되었다` 또는 `틀렸다`를 고르면 **회고록으로 이어진다.**

## 5. 회고록 — 제대로 맞췄는가, 소 뒷걸음질인가

결과가 확정되면 열리는 화면이다. **이 앱의 최종 산출물이자 존재 이유다.**
앞의 모든 기능 — 원본 대화 보존, 근거 항목 기록, 수치 추적, 리마인드 — 은 전부
이 한 화면을 위한 준비다.

```
┌────────────────────────────────────────────────────────────┐
│  ← 노트                        삼성전자 · 회고               │
│                        2026.03.02 기록 → 2026.12.31 확정     │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  ①  당시 당신의 논리                            [사용자]    │
│  ┌──────────────────────────────────────────────────┐     │
│  │ HBM 공급 부족 지속                                │     │
│  │        ↓                                         │     │
│  │ 삼성전자가 후발주자로 점유율 확보                   │     │
│  │        ↓                                         │     │
│  │ 주가 상승                                         │     │
│  └──────────────────────────────────────────────────┘     │
│                                    ▸ 당시 대화 전문 보기    │
│                                                            │
│  ②  실제로는 이랬습니다                                     │
│  ┌──────────────────────────────────────────────────┐     │
│  │ ✗ HBM 공급 부족 지속        일어나지 않음          │     │
│  │   SK하이닉스 HBM4 양산이 앞당겨지며 하반기부터     │     │
│  │   공급이 풀렸습니다.                    [출처 2건] │     │
│  │                                                  │     │
│  │ ? 삼성전자 점유율 확보      확인 불가              │     │
│  │   점유율을 공개한 자료를 찾지 못했습니다.          │     │
│  │                                                  │     │
│  │ ✓ 주가 95,000원 이상        달성 (11.18)          │     │
│  └──────────────────────────────────────────────────┘     │
│                                                            │
│  ┌──────────────────────────────────────────────────┐     │
│  │ 같은 기간 비교                                    │     │
│  │   삼성전자      +15%  ▓▓▓▓▓▓▓▓░░░░               │     │
│  │   반도체 업종   +21%  ▓▓▓▓▓▓▓▓▓▓▓░               │     │
│  │   코스피        +18%  ▓▓▓▓▓▓▓▓▓▓░░               │     │
│  └──────────────────────────────────────────────────┘     │
│                                                            │
│  ③  그래서, 제대로 맞춘 건가요?                             │
│  ┌──────────────────────────────────────────────────┐     │
│  │  [ 논리대로 맞았다 ]      [ 결과만 맞았다 ]        │     │
│  │  [ 논리는 맞았는데        [ 둘 다 틀렸다 ]        │     │
│  │    결과가 안 나왔다 ]                             │     │
│  │                                                  │     │
│  │  무엇을 놓쳤고, 다음엔 무엇을 다르게 보시겠어요?    │     │
│  │  ┌────────────────────────────────────────────┐  │     │
│  │  │                                            │  │     │
│  │  └────────────────────────────────────────────┘  │     │
│  │                              [ 나중에 ] [ 저장 ] │     │
│  └──────────────────────────────────────────────────┘     │
└────────────────────────────────────────────────────────────┘
```

### 핵심: 결과 축과 논리 축은 별개다

|  | 논리가 맞았다 | 논리가 틀렸다 |
|---|---|---|
| **결과가 맞았다** | 논리대로 맞았다 | **결과만 맞았다** — 가장 위험한 성공 |
| **결과가 틀렸다** | 논리는 맞았는데 결과가 안 나왔다 | 둘 다 틀렸다 |

오른쪽 위 칸을 잡아내는 것이 이 화면의 목적이다. 다른 앱은 이걸 그냥 "적중"으로 기록한다.
틀린 논리로 운 좋게 번 것을 실력으로 착각하면, 다음에 같은 논리로 더 큰 돈을 넣는다.

왼쪽 아래 칸도 중요하다. 논리가 옳았는데 시기를 잘못 봤다면 그 논리는 버릴 게 아니라
다시 쓸 자산이다.

### 화면 규칙

- **②는 AI가 미리 채워둔다.** 빈 화면에 "회고를 쓰세요"라고 두면 아무도 쓰지 않는다.
  사용자는 이미 정리된 사실 위에 판단만 얹으면 된다.
- **AI는 "이건 운이었습니다"라고 말하지 않는다.** 사실과 대비만 제시한다. 위 예시에서
  삼성전자(+15%)가 업종(+21%)을 밑돈 것은 강한 신호지만, 결론은 사용자가 내린다.
  AI가 논리의 옳고 그름을 선언하면 사용자는 스스로 생각하지 않게 되고, 그러면 이 앱은
  판단력을 기르는 도구가 아니라 대신 판단해주는 도구가 된다.
- **`확인 불가`를 숨기지 않는다.** 자료를 못 찾았으면 못 찾았다고 표시한다.
  ②에서 `확인 불가`가 대부분이면 회고의 가치가 떨어지지만, 그 사실 자체도 정보다
  ("내 논리는 애초에 확인할 방법이 없는 것이었다").
- **벤치마크 비교는 언제나 제공한다.** 근거 항목 조사가 전부 실패해도 이것만은 계산된다.
  "그냥 시장이 올라서"를 거르는 가장 확실한 장치이자, 무료 API로 가능한 유일한 자동 검증이다.
- ①은 원본 그대로다. AI가 각색하지 않는다. (P2)
- 사용자 서술은 `[사용자]` 저작으로 표기된다. (P3)

### 강요하지 않는다

- `나중에`를 누르면 조용히 닫힌다. **안 쓴 회고록의 개수를 세지 않고, 배지도 띄우지 않는다.** (P5)
- AI 초안과 수치 기록은 그대로 남으므로 언제든 다시 열어 쓸 수 있다.
- 대신 **같은 대상으로 새 노트를 만들 때 조용히 꺼내 보여준다.**
  ```
  이 종목으로 지난번에 이렇게 판단하셨습니다.
  "HBM 공급 부족 지속" → 실제로는 일어나지 않았습니다.
                                          [ 그때 회고 보기 ]
  ```
  회고록이 가장 필요한 순간은 같은 실수를 반복하려는 바로 그때다.
  이건 압박이 아니라 메멘토 원칙 그 자체다 — 과거의 내가 지금의 나를 찾아오는 것.

## 6. 확률 입력 UX

### 갈래 안의 확률은 모두 합쳐서 100%

한 갈래 안의 시나리오들은 **동시에 일어날 수 없는 경우들로 본다.** 확률 합은 항상 100%이고,
하나를 올리면 나머지가 자동으로 줄어든다.

이유: 각각 따로 확률을 매기면 "A도 70%, B도 60%" 같은 앞뒤가 안 맞는 입력이 나온다.
무엇보다 **무언가를 포기하는 감각이 사라진다.** 하나를 올리려면 다른 것을 내려야 한다는
제약이 있어야 생각이 정직해진다.

화면에서는 이 규칙을 설명하지 않는다. 조각이 서로 밀고 당기는 것을 보고 스스로 알아차린다.

### 자료는 답마다 갈라 주고, 숫자는 사용자만 낸다

AI가 확률을 제안하고 사용자가 승인하는 방식은 쓰지 않는다. 앵커가 걸려 노트에 남는 것이
AI의 판단이 되고, 회고에서 `내 논리가 맞았는가`를 물을 대상이 사라진다(개발 문서 §3.4).

**남의 견해를 확률로 환산하지도 않는다.** `증권사 12곳 중 7곳이 연내 진입 가능`은 자료이고
`58%`는 자료가 아니다. 이것을 사용자의 확률 옆에 나란히 세우면 셋이 같은 종류의 값처럼
읽히는데, 실제로 확률인 것은 사용자가 낸 하나뿐이다.

대신 **각 답을 뒷받침하는 자료를 갈라 놓는다.** 사용자는 양쪽 더미의 무게를 재서 나눈다.

```
┌──────────────────────────────────────────────────────────────┐
│  갈래 1 · 올해 안에 엔비디아 HBM4 공급사로 진입하는가?           │
│                                                              │
│  판단에 참고하실 자료                                          │
│                                                              │
│  ▪ 01 진입한다 쪽                                             │
│    엔비디아, 공급사 다변화 검토 착수         5일 전 · 출처 3곳  │
│    증권사 12곳 중 7곳이 "연내 진입 가능" 의견        출처 4곳   │
│                                                              │
│  ▪ 02 진입하지 못한다 쪽                                       │
│    SK하이닉스 HBM4 양산 일정 단축           2일 전 · 출처 2곳  │
│    삼성 퀄 테스트 3차 지연 보도             3주 전 · 출처 2곳  │
│                                                              │
│  ▫ 어느 쪽도 아닌 것                                          │
│    최근 5년간 신규 공급사 진입이 발표 후 2분기 안에            │
│    확정된 사례 7건 중 3건                          출처 2곳   │
│                                                     ▸ 더 찾기 │
│  ────────────────────────────────────────────────────────    │
│  어떻게 나눠 보시나요                                          │
│   ╭───────╮   01 진입한다        ├──────●───┤   60%          │
│   │ 100%  │   02 진입하지 못한다  ├────●─────┤   35%          │
│   ╰───────╯   03 그 외                          5%  🔒        │
│               희박         반반         유력                   │
└──────────────────────────────────────────────────────────────┘
```

#### 화면 규칙

- **자료는 배분보다 위에 온다.** 숫자가 아니라 읽을거리이므로 먼저 읽고 나서 나누는 것이
  자연스럽다. 확정한 뒤에 무언가를 공개하는 단계는 없다 — 공개할 숫자가 없다.
- **`↗ 뒷받침` 표시는 노트 상세의 새 정보 서랍과 같은 어휘를 쓴다.** 같은 것을 두 이름으로
  부르지 않는다(§9.4).
- **기저율은 어느 답의 편도 아니므로 따로 묶는다.** 분모와 분자를 문장에 그대로 담는다 —
  `7건 중 3건`이지 `43%`가 아니다. 퍼센트로 줄이면 표본이 7건이라는 사실이 사라진다.
- **한쪽이 비어도 채우지 않는다.** `찾은 자료가 없습니다`라고 적는다. 한쪽에만 쌓이는 것
  자체가 사용자에게 정보다.
- **자료 개수로 확률을 암시하지 않는다.** `3 대 1`처럼 세어 보여주면 그것이 곧 숫자 제안이
  된다. 뉴스가 많이 난 쪽이 맞는 쪽은 아니다.
- **못 매기겠으면 넘어갈 수 있다.** 도넛이 빈 고리로 남고, 노트는 정상 동작한다.
- 값을 바꾸면 **최초값과 조정값이 둘 다 남는다.** 노트 상세의 `생각이 바뀐 기록`에
  `처음 매긴 값 65% → 60%`로 보인다.

#### 숫자를 직접 묻지 않는다

`65`를 입력하라고 하면 대부분 멈춘다. 눈금 위의 위치로 받고 시스템이 %로 옮긴다.
눈금 아래에 `희박 · 반반 · 유력`을 적어 감각과 숫자를 잇는다. 5% 단위로만 움직이는 것도
같은 이유다 — 63%와 65%의 차이를 진지하게 고민하게 만들면 안 된다.

좁은 화면에서는 슬라이더 대신 `−` / `＋` 스테퍼를 쓴다. 손가락으로 5% 단위를 정확히
집는 것은 슬라이더로는 어렵다.

### 갈래는 도넛으로, 시나리오는 막대로

가로 막대를 나란히 놓으면 각 시나리오의 크기는 보이지만 **"다 합치면 하나"라는 사실이
보이지 않는다.** 합이 100%라는 것은 구성비이고, 구성비를 읽는 형식은 파이다.

그래서 두 형식을 역할로 나눈다.

| | 형식 | 답하는 질문 | 놓이는 곳 |
|---|---|---|---|
| **구성비** | 도넛 | 이 갈래를 어떻게 나눠 보고 있나 | 갈래 헤더에 한 번 |
| **변화** | 문장 | 지난번보다 올랐나 내렸나 | 시나리오 카드마다 |

#### 시나리오 카드에서는 막대를 쓰지 않는다

처음에는 카드마다 눈금 막대를 두고 지난 확률을 점선 사각형으로 겹쳐 놓았다. **읽히지
않았다.** 흐릿한 덩어리 옆의 점선 사각형이 무엇을 뜻하는지 설명 없이는 알 수 없고,
설명이 필요한 그래픽은 실패한 그래픽이다.

카드에서는 **숫자를 크게 쓰고 도넛 조각과 같은 계열의 색을 입힌다.**

```
  ▪ HBM 수주 확대 성공                     [초읽기]

    60~70% 안팎      지난번 55~65% 에서 올림
    ^^^^^^^^^ 24px, 조각과 같은 색
                     ^^^^^^^^^^^^^^^^ 캡션, 무채색
```

변화는 그림이 아니라 **문장으로 적는다.** "지난번 55~65%에서 올림"은 점선 사각형보다
짧고 정확하며, 설명이 필요 없다. 지난 확률 고스트는 폐기한다.

막대는 **2단계 설정 화면에만 남긴다.** 거기서는 슬라이더를 움직이면 띠가 따라 움직이므로
막대가 스스로를 설명한다. 조작 없이 결과만 보여주는 자리에서는 쓰지 않는다.
(새 노트에는 지난 확률이 없으므로 그 화면의 고스트도 없앤다.)

```
      ╭───────╮      01 HBM 수주 확대 성공      60~70%
     ╱  100%   ╲     02 기술 격차가 지속된다     20~30%
    │   합계    │    ▫ 그 외 예상 못한 전개       10%
     ╲         ╱
      ╰───────╯      조각 경계가 흐린 폭이 곧 확률의 범위입니다
```

#### 도넛이 가짜 정밀함이 되지 않게

파이는 본래 정밀해 보이는 형식이다. 깔끔하게 떨어지는 조각은 "이 값은 정확하다"는 인상을
주는데, 이는 **확률은 어림이라는 원칙**과 정면으로 충돌한다.

그래서 **조각 사이 경계를 선이 아니라 그라데이션으로 그린다. 그 흐린 폭이 곧 확률의 범위다.**
`60~70%`인 시나리오는 그 10%p 구간에 걸쳐 옆 조각으로 번져 들어간다. 경계가 또렷한 파이는
이 앱에 존재하지 않는다.

#### 색만으로 조각을 구분하지 않는다

- 범례에 **시나리오 번호**(`01`, `02`)를 함께 적어, 색을 구분하지 못해도 매칭이 된다.
- 각 시나리오 카드 제목 앞에 같은 색 표식을 붙여 카드 ↔ 조각을 잇는다.
- 조각의 순서는 시계 방향이고 범례의 순서와 같다. 크기 차이(65% / 25% / 10%)도 단서가 된다.
- 조각 색은 원색이 아니라 **종이 톤에 섞은 색**을 쓴다. 도넛이 화면에서 가장 큰 색 덩어리가
  되면 강조 예산을 혼자 다 써버린다.

#### `그 외 예상 못한 전개`가 도넛에서 제 역할을 한다

막대로 볼 때는 그저 작은 항목 하나였지만, 도넛에서는 **내가 채우지 못한 몫**으로 보인다.
"내가 생각한 경우가 전부가 아니다"라는 메시지가 형식 자체에 담긴다.

### `그 외 예상 못한 전개`

모든 노트에 **자동으로 만들어지고 지울 수 없는** 시나리오를 하나 둔다.

```
  그 외 예상 못한 전개                    10%
  ▓▓░░░░░░░░░░░░░░░░░░
```

- 사용자가 적은 시나리오들의 합이 100%에 못 미치면 남는 몫이 여기로 간다.
- 최소 5%는 반드시 남긴다 — **"내가 생각한 경우가 전부다"라는 착각을 구조적으로 막는다.**
- 실제로 예상 못한 일이 벌어지면, 사용자는 이를 계기로 새 시나리오를 추가하거나
  노트를 다시 쓴다.

### 입력 방식

- 확률은 5% 단위로만 조정된다. (1% 단위는 정밀해 보이지만 실제로는 근거 없는 숫자다)
- 조정 화면에서 **데스크톱은 드래그 슬라이더, 모바일은 `[−] 65% [+]` 버튼**을 쓴다.
  좁은 화면에서는 5% 한 칸이 17px밖에 안 돼 손가락으로 집기 어렵고, 가로로 끄는 동작이
  세로 스크롤과 부딪힌다. ([§11.4](#114-터치-입력-고려) 참조)
- 하나를 조정하면 나머지가 비율에 맞춰 자동으로 조정된다. 건드리고 싶지 않은 시나리오는
  `고정`해둘 수 있다.
- 조정할 때 **바꾼 이유를 한 줄 남기도록 권한다** (선택 사항, 하지만 강하게 권장).
  나중에 돌아볼 때 "왜 그때 생각을 바꿨는지"가 숫자보다 훨씬 중요하다.

## 7. 수치 추이 — 가격 데이터를 어떻게 보여줄 것인가

계열을 API로 가져오면 시계열이 생긴다. 이걸 그냥 주가 차트로 그리면 안 된다.
**캔들·이동평균·보조지표가 붙은 차트는 기술적 분석을 부르고, 그건 이 앱이 막으려는
충동적 판단 그 자체다.** (디자인 시스템도 캔들·화살표·로켓·곰/황소 아이콘을 금지한다)

이 차트가 답해야 할 질문은 셋뿐이다.

1. 내가 기록할 때는 어디였나
2. 목표는 어디인가
3. 그 사이를 얼마나 지나왔나

### 형태

```
  삼성전자 · 95,000원 이상                          97,400
  기록 2026.03.02 · 판단 시점 2026.12.31        오늘 · 목표 넘김
  ┌──────────────────────────────────────────────────────┐
  │                                    11.18 목표 넘김     │
  │ 목표 95,000 ──────────────────────────────○──╮──── ●▨ │
  │ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒╱▔╲▒▒▒▒▒▒▒▒▒▒▒▒▨ │
  │ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒╱▔▔╲╱▔▔▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▨ │
  │ 기록 78,000 ┈┈╱▔╲╱▔┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈▨ │
  └──────────────────────────────────────────────────────┘
   2026.03.02 · 기록                    2026.12.31 · 판단 시점
```

| 요소 | 표현 | 이유 |
|---|---|---|
| **기록 시점 값** | 점선 가로선 | 이 앱에서 **점선은 이미 "과거의 기준"**이다 (확률 게이지의 지난 확률 고스트와 같은 언어) |
| **목표값** | 실선 가로선 | 지금 유효한 기준이므로 실선 |
| **그 사이 띠** | 연한 면 | **가야 했던 거리.** 선이 이 띠를 벗어나는 순간이 곧 달성이다 |
| **추이** | 2px 실선, 무채색 | 데이터일 뿐 신호가 아니다. 색을 쓰지 않는다 |
| **목표를 넘은 지점** | 빈 원 + 날짜 라벨 | 언제 넘었는지가 판정의 핵심 사실 |
| **오늘** | 채운 원 (유일한 색) | 한 화면에 색은 여기 하나뿐 |
| **오늘 이후** | 빗금 영역 | 판단 시점까지 **남은 시간**. 남은 거리와 남은 시간이 한 그림에 있다 |

### 왜 추이선에 색을 쓰지 않는가

색을 쓰려면 "올랐다/내렸다"가 아니라 **"목표에 가까워졌다/멀어졌다"**로 칠해야 한다.
이 앱의 색은 가격 방향이 아니라 가설의 강화·약화를 뜻하기 때문이다(`--rise`=강화).

그런데 `금리 3.5% 이하` 같은 조건에서는 **내려가는 선이 강화**가 되어 빨간색이 된다.
주가 차트에 익숙한 눈에는 정반대로 읽힌다.

그래서 **선 자체는 칠하지 않는다.** 색은 `오늘` 점 하나에만 쓰고, 달성 여부는
"선이 띠를 벗어났는가"라는 **위치**로 읽게 한다. 강조 예산도 지켜지고,
`이상`/`이하` 조건이 같은 규칙으로 읽힌다.

### 축약형 — 노트 상세에서

시나리오 카드 안에서는 auto 조건과 지켜보는 수치마다 한 줄씩, 오른쪽에 작은 그림을 놓는다.
지켜보는 수치에는 목표선을 그리지 않는다 — 목표가 없기 때문이다.
축·라벨·범례를 모두 걷어내고 **띠 · 목표선 · 추이 · 오늘 점**만 남긴다.

```
  삼성전자 95,000원 이상          ┌──────────────┐
  달성 11.18 · 지금 97,400       │▒▒▒▒▒▒▒╱▔▔● │ ← 띠를 벗어남
                                 └──────────────┘
  코스피 3,200 이상               ┌──────────────┐
  아직 · 지금 3,050 · 목표의 95%  │▒▒▒▒▒╱▔▔○▒▒▒│ ← 아직 띠 안
                                 └──────────────┘
```

달성은 **채운 점**, 미달성은 **빈 점**이다. 색을 못 봐도 구분된다.

### 수치는 종가 기준이다

**추이선은 종가를 잇는다.** 장중 값을 실시간으로 보여주면 그 순간 시세 앱이 되고,
사용자는 하루에도 몇 번씩 앱을 열게 된다. 이 앱이 막으려는 행동이 정확히 그것이다.

| 상황 | 처리 |
|---|---|
| 아직 장이 안 끝난 오늘 | **그리지 않는다.** 차트의 마지막 점은 언제나 *확정된 마지막 종가* |
| 해외 계열 | 그 시장의 마감 기준. 한국 시간으로 환산하지 않고 **현지 거래일**로 찍는다 |
| 금리·물가 같은 거시 계열 | 애초에 장중이라는 게 없다. 발표된 값 하나가 곧 그날의 값 |

### 고가~저가 띠는 항상 그린다

달성 기준이 `한 번이라도 닿으면 · 장중 포함`으로 고정이므로, **종가만 그리면 화면이
모순된다.** 앱은 `달성`이라 표시하는데 종가선은 목표선 아래에 머무는 날이 실제로 생긴다.

그래서 **그날의 고가~저가를 연한 띠로 종가선 뒤에 깐다.** 이건 선택이 아니라 필수다.
종가선이 목표선을 넘지 않아도 띠가 닿는 것이 보이면 판정이 설명된다.

```
  목표 95,000 ─────────────●───────────○
                           ╿  (종가는 나중에 따라 올라옴)
                    ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒
                      11.02 달성
```

- **목표에 처음 닿은 날**에 색이 들어간 점을 찍고, 종가까지 짧은 세로선으로 잇는다.
  점이 종가선에서 떠 있는 이유가 그 선으로 설명된다.
- 그 아래 한 줄로 **왜 그날인지** 적는다.
  "11.02에 장중 고가가 96,000까지 닿아 그날을 달성일로 기록했습니다. 그날 종가는
  93,198이었지만 한 번이라도 닿으면 달성이 기준입니다."
- **색은 이 점 하나에만 쓴다.** 오늘 지점은 빈 원이다. 한 화면에 강조는 하나뿐이라는
  원칙이 여기서도 그대로 적용된다.
- 거시 계열에는 띠가 없다. 값이 하나뿐이라 그릴 것이 없다.

### 규칙

- **눈금선을 촘촘히 넣지 않는다.** 가로선은 기록선과 목표선 둘뿐이다.
  격자를 깔면 "이 값이 얼마인지" 읽게 되고, 그건 이 차트의 질문이 아니다.
- **점마다 숫자를 찍지 않는다.** 직접 라벨은 목표·기록·오늘·달성 지점까지만.
  나머지 값은 크로스헤어 툴팁과 `값으로 보기` 표에서 읽는다.
- **표를 반드시 함께 제공한다.** 차트만으로 값에 접근할 수 없으면 안 된다.
- **줌·기간 변경·기술 지표를 붙이지 않는다.** 기간은 언제나 `기록 시점 → 판단 시점`
  하나로 고정이다. 사용자가 기간을 바꾸기 시작하면 그 순간 트레이딩 앱이 된다.
- SVG를 비균등 스케일로 늘이므로 **라벨은 SVG 안이 아니라 HTML 오버레이**로 얹는다.
  안에 넣으면 글자가 함께 늘어난다.

### 회고록에서의 쓰임

회고록의 벤치마크 비교(§5)와 같은 기간을 공유한다. 추이 차트가 "내 목표에 닿았나"를,
벤치마크 비교가 "그게 시장 덕분은 아니었나"를 답한다. 둘을 나란히 두면
**목표는 넘겼는데 업종 평균은 밑돈** 경우가 한눈에 보인다.

## 8. 리마인드가 뜨는 조건과 순서

### 리마인드가 뜨는 경우

| 경우 | 조건 | 기본 설정 |
|---|---|---|
| 결과 확인 필요 | 갈래의 판단 시점이 지남 | 즉시, 이후 주 1회 |
| 시점 임박 | 판단 시점 7일 전 | 1회 |
| 조건 달성 | 시나리오의 auto 조건이 충족됨 | 즉시 (하루 1회로 묶어서) |
| 새 정보 | AI가 찾은 정보의 관련도가 기준을 넘음 | 즉시 (하루 1회로 묶어서) |
| 정기 리마인드 | 마지막으로 본 지 N주 경과 | 기본 4주 |

### 자주 안 열면 알아서 뜸해진다

같은 노트의 리마인드가 **연속 3번 열리지 않으면 주기를 2배로 늘린다.**
그 뒤로도 계속 열리지 않으면 다시 2배(최대 12주까지).
사용자가 한 번이라도 열면 원래 주기로 즉시 돌아온다.

이는 벌이 아니라 **실제 관심 수준에 앱이 맞춰가는 것**이다. 이 동작은 사용자에게
드러내지 않는다 — "안 보셔서 빈도를 줄였습니다" 같은 안내는 P5 위반이다.

### 하루에 보내는 양

- 홈 화면 기본 노출: 3장
- 푸시/이메일 알림: **하루 1통.** 여러 건은 한 통에 묶는다.
- 보내는 시각: 사용자 설정 (기본값 = 장 마감 이후, 예: 평일 18:00)
  장중 알림은 충동적인 판단을 부르므로 기본값에서 뺀다.

## 9. 화면에 쓰는 말

### 9.1 누가 쓴 글인지 구분하기

노트 내용은 대부분 AI가 쓰므로 **AI가 쓴 글에는 아무 표시도 하지 않고**,
사용자가 쓴 부분에만 `[사용자]`를 붙인다. (P3)

#### `[사용자]`가 붙는 것

| 대상 | 표기 |
|---|---|
| 대화 중 사용자가 한 말이 노트에 그대로 인용된 문장 | `[사용자]` + 왼쪽 선 강조 |
| 사용자가 직접 고쳐 쓴 부분 | `[사용자]` |
| 사용자가 직접 붙인 링크/파일/메모 | 섹션 제목에 `[사용자]` |
| 확률을 바꾼 이유 | `[사용자]` |
| 시나리오 결과를 정한 이유 | `[사용자]` |

#### 붙이지 않는 것

- AI가 쓴 가설 요약, 시나리오 설명, 정보 요약, 조언 — 전부 표시 없음.
- 단, **AI의 주관적 의견(매수/매도 의견, 확률 조정 제안)은 따로 묶어
  "AI의 견해"라는 제목을 붙인다.** 이건 누가 썼는지의 문제가 아니라 사실과 의견의 구분이다.

### 9.2 원본 대화 보기

모든 노트에서 `원본 대화 기록`을 열어 대화 전체를 볼 수 있다.
이 기록은 **읽기만 가능하며 고치거나 지울 수 없다.** (P2)

### 9.3 문구 작성 규칙

P8을 실제 문구로 옮기면 다음과 같다.

- **상태가 아니라 할 일을 말한다.** `결과 확인 필요`(○) / `판정 대기`(✗)
- **명사보다 동사.** `지금 다시 조사하기`(○) / `리서치 실행`(✗)
- **앱이 아니라 사용자를 주어로.** `이 시나리오는 어떻게 되었나요?`(○) /
  `시나리오 상태를 갱신하세요`(✗)
- **숫자와 기간은 그대로.** `5일 남음`(○) / `D-5`(✗)
- **영어 약어를 쓰지 않는다.** 다만 종목명·기술명(HBM, FSD 등 사용자가 이미 쓰는 말)은 예외다.
- **평가하는 말을 쓰지 않는다.** `한동안 보지 않으셨습니다`(○) /
  `3주째 방치 중`(✗) — P5와 직결된다.
- **설계 근거를 화면에 쓰지 않는다.** 앞으로 무슨 일이 일어나는지는 적고, 우리가 왜 이렇게
  만들었는지는 적지 않는다.
  - `판단 시점이 오면 여쭙겠습니다`(○)
  - `주가를 붙여드리지 않는 이유는, 주가가 올랐다고 수주를 받은 것이 아니기 때문입니다`(✗)

  처음 쓰는 사용자는 "주가를 붙이지 않았다"는 사실 자체를 모른다. 하지도 않은 일의 이유를
  읽히면 무슨 말인지 알 수 없고, 알고 싶어하지도 않는다. **없는 것을 변명하지 않는다.**
  설계 근거를 남기고 싶으면 문서에 쓰고, 화면에는 결과만 남긴다.
- **내부 개념어를 이유로 쓰지 않는다.** `여집합이라 조건을 두지 않습니다`(✗) /
  `01 진입한다가 아니면 이 답입니다`(○) — 앞은 우리 어휘로 규칙을 설명하고,
  뒤는 사용자의 말로 사실을 말한다. §9.4의 대응표가 이것을 위해 있다.

## 11. 화면 비율에 따른 설계

### 11.0 출발점: 세로는 같고, 가로만 다르다

반응형을 "좁아지니까 줄인다"로 접근하면 데스크톱 레이아웃을 그냥 세로로 무너뜨리게 되고,
그 결과 두 화면 모두에서 어색한 물건이 나온다. 실제 수치를 보면 문제의 성격이 다르다.

| | 콘텐츠 영역(대략) | 가로:세로 |
|---|---|---|
| 데스크톱 | 1440 × 750 | 약 **1.9 : 1** (가로로 누움) |
| 모바일 | 390 × 750 | 약 **0.5 : 1** (세로로 섬) |

**세로 예산은 사실상 같고, 가로만 약 3.7배 차이가 난다.**
따라서 설계 문제는 "모바일에서 무엇을 뺄까"가 아니라 다음 두 가지다.

1. 데스크톱의 **남는 가로 폭으로 무엇을 할 것인가**
2. 그 폭이 사라졌을 때 거기 있던 것을 **어디로 옮길 것인가** (세로로 미루면 안 된다)

### 11.1 가로와 세로가 하는 일이 다르다

이 앱에서 두 축은 서로 다른 의미를 담당한다. 이 원칙이 모든 변환의 기준이 된다.

> **가로축 = 비교. 세로축 = 순서와 흐름.**

- **비교해야 하는 것**(과거의 나 ↔ 지금의 정보, 시나리오 A ↔ B)은 가로로 나란히 둘 때
  가장 잘 읽힌다. 시선이 두 대상을 왕복할 수 있기 때문이다.
- **순서가 있는 것**(①→②→③, 우선순위 목록, **시간축**)은 세로로 쌓을 때 가장 잘 읽힌다.
  세로는 스크롤로 무한히 늘어나므로 항목이 몇 개든 감당한다.
- 모바일에는 가로축이 없다. 따라서 **비교를 세로 스택으로 대체하면 안 된다** — 세로 스택은
  "다음 내용"을 의미하지 "대비되는 것"을 의미하지 않는다.
  대신 **탭으로 전환하거나, 스크롤에 따라 차례로 보여주어** 비교의 의미를 살린다.

### 11.2 데스크톱: 가로 폭은 세로를 줄이는 데 쓴다

넓은 화면이 생겼을 때 흔한 실수는 **열을 늘리는 것**이다. 하지만 홈 피드처럼
**우선순위가 있는 목록은 세로로 유지되어야** 한다(9.1). 3열 그리드로 만들면 1순위와
3순위가 같은 높이에 놓여 우선순위가 사라진다.

> 넓은 화면에서는 **열을 늘리지 말고, 각 항목을 가로로 눕혀 높이를 줄인다.**

데스크톱 뷰포트는 세로로 짧으므로(750px), 항목 하나가 140px면 3개에 420px + 타임라인
200px = 스크롤이 발생한다. 같은 카드를 가로로 눕혀 90px로 만들면 270px + 200px = 470px로
**모든 것이 첫 화면 안에 들어온다.** 이것이 넓은 화면의 진짜 이득이다.

```
데스크톱 — 카드를 눕혀 높이를 줄임 (90px)
┌──────────────────────────────────────────────────────────────┐
│ 📅 │ 판단 시점이 다가옵니다 · 5일 남음                        │
│    │ 삼성전자 "HBM 수주 확대" — 6주 전 확률 60%   [열어보기]  │
└──────────────────────────────────────────────────────────────┘

모바일 — 세로로 자연스럽게 흐름 (140px, 세로는 저렴하므로 허용)
┌────────────────────────┐
│ 📅 판단 시점이 다가옵니다│
│    5일 남음             │
│ 삼성전자                │
│ "HBM 수주 확대"         │
│ 6주 전 확률 60%         │
│           [ 열어보기 ]  │
└────────────────────────┘
```

### 11.3 화면별 대응

#### 홈 타임라인 — 양쪽 모두 세로축이다

타임라인은 데스크톱·모바일 구분 없이 **세로축 하나로 통일한다.** 축 방향을 화면마다
바꾸지 않는다.

이유는 두 가지다.

1. **가로축은 항목 수에 무너진다.** 노트 10개 × 시나리오 2~3개면 마커가 20~30개인데,
   고정 폭 5구간에 담을 수 없다. 세로축은 스크롤로 얼마든지 늘어난다.
2. **축 원칙(§11.1)이 세로를 가리킨다.** 가로는 비교, 세로는 순서다.
   타임라인은 비교가 아니라 순서이므로 세로가 제자리다.

따라서 이 컴포넌트는 폭에 따라 **구조가 아니라 여백만 달라진다.**

```
데스크톱 — 축 왼쪽 여백에 날짜를 놓는다
   12.31 ●─── ┌────────────────────────────────┐
     D-5 │    │ 삼성전자 · HBM 수주 확대 성공    │
         │    └────────────────────────────────┘

모바일 — 축을 왼쪽 끝에 붙이고 날짜를 카드 안으로
  ●─ ┌──────────────────────────┐
  │  │ 12.31 · D-5              │
  │  │ 삼성전자 · HBM 수주 확대   │
  │  └──────────────────────────┘
```

- 가로축을 쓸 때 필요했던 **비선형 압축은 폐기한다.** 세로에서는 가까운 것이 먼저
  나오는 것만으로 충분하고, 간격을 인위적으로 조절하면 시간 감각만 왜곡된다.
- 기간형 시나리오는 축을 따라 흐르는 구간 막대가 된다. 세로축에서는 기간이 길이로 읽힌다.

#### 홈 전체 구성 — 모바일에서는 피드가 주인공

데스크톱에서는 타임라인(200px) + 피드(270px)가 한 화면에 공존한다.
모바일에서는 둘 다 세로를 요구해 서로 경쟁하고, 그대로 쌓으면 화면 3개 길이가 된다.

**모바일 홈은 피드를 기본으로 하고, 타임라인은 세그먼트 전환으로 분리한다.**

```
┌────────────────────────┐
│  Investment Memento 👤 │
├────────────────────────┤
│ ┌────────┬───────────┐ │
│ │다시 볼 시점│ 타임라인 │ │  ← 세그먼트 (기본: 다시 볼 시점)
│ └────────┴───────────┘ │
├────────────────────────┤
│  다음 판단 시점          │
│  삼성전자 HBM · 5일 후 → │  ← 타임라인 요약 한 줄
├────────────────────────┤
│  ┌──────────────────┐  │
│  │ 📅 판단 시점 임박  │  │
│  │ ...              │  │
│  └──────────────────┘  │
│  ┌──────────────────┐  │
│  │ 📰 새 소식 3건     │  │
│  └──────────────────┘  │
└────────────────────────┘
```

근거: 모바일 진입은 대개 **알림을 받고 들어오는 경우**다. 이때 사용자가 원하는 것은
"지금 봐야 할 것"이지 전체 조망이 아니다. 조망은 데스크톱에서 앉아 볼 때의 행위다.
타임라인이 완전히 사라지지 않도록 **다음 판단 시점 한 줄 요약**은 상시 노출한다. (P1)

#### 노트 상세 — 서랍 하나로 통일했다

이 화면은 폭에 따라 구조를 바꾸지 않는다. **양쪽 모두 본문 + 서랍**이고, 서랍의 폭만
다르다(넓은 화면 340px, 좁은 화면 전체 폭).

이전에는 데스크톱 좌우 2단 / 모바일 탭으로 나눴다. 서랍이 두 경우를 모두 대신한다.
**세로 스택만은 여전히 금지다.** 이어 붙이면 두 영역이 "하나의 연속된 문서"로 읽혀
분리의 의미가 사라진다.

> **분리는 "다른 공간"으로 표현한다. 서랍은 열기 전까지 존재하지 않는 공간이므로
> 이 조건을 가장 강하게 만족한다.**

```
┌────────────────────────┐
│ ← 삼성전자              │
│   마지막 검토 6주 전     │
├──────────────────────┬─┤
│                      │3│ ← 책갈피. 누르면 전체 폭 시트
│                      │새│
├──────────────────────┴─┤
│ 핵심 가설                │
│ HBM 공급 부족이 2026년   │
│ 까지 이어지며...         │
│                        │
│ [사용자] "결국 공급이    │
│  못 따라가는 게 핵심"    │
│                        │
│ 시나리오                 │
│ ┌────────────────────┐ │
│ │ A. 수주 확대   65%  │ │
│ │ ▓▓▓▓▓▓▓▓▓▓░░░░    │ │
│ │ 📅 2026 Q4까지     │ │
│ │  [다시 판단하기]   │ │
│ └────────────────────┘ │
│ ...                    │
├────────────────────────┤
│ ⚠ 판단과 책임은 본인에게 │
└────────────────────────┘
```

- **서랍은 기본이 닫힘이다.** 새 정보를 먼저 보면 그 프레임으로 과거를 해석하게 되어
  이 앱의 목적 자체가 무너진다.
- 책갈피에는 개수만 적는다. 빨간 배지는 쓰지 않는다. (P5)
- 서랍을 여닫아도 본문 스크롤 위치는 유지한다 — 초기화되면 왕복이 불가능해진다.

#### 리마인드 상세 — 대비를 만드는 방식이 다르다

이 화면의 목적은 **과거의 나와 그동안의 일을 대비시키는 것**이다.
대비는 가로축의 일이므로(§11.1), 데스크톱에서는 오히려 현재의 3단 세로 배치가 낭비다.

```
데스크톱 — ①과 ②를 나란히 두어 대비를 물리적으로 만든다
┌───────────────────────────────┬────────────────────────┐
│ ① 6주 전, 당신은 이렇게 생각    │ ② 그동안 이런 일이       │
│    했습니다                    │    있었습니다            │
│                               │                        │
│  HBM 공급 부족이 2026년까지    │  ↘ SK하이닉스 HBM4      │
│  이어지며...                   │    양산 일정 단축        │
│                               │                        │
│  [사용자] "누가 만들든 팔린다"  │  ↗ 엔비디아 공급사       │
│                               │    다변화 검토           │
│  A. 수주 확대 성공  60%        │                        │
│  B. 기술 격차 지속  30%        │  — 메모리 가격 반등      │
│         (폭 7)                │        (폭 5)          │
├───────────────────────────────┴────────────────────────┤
│ ③ 지금은 어떻게 보시나요?            (전체 폭)           │
│    AI의 견해 / 되짚어볼 질문                             │
│         [ 다시 판단하기 ]   [ 나중에 ]                   │
└─────────────────────────────────────────────────────────┘

모바일 — 스크롤에 따라 차례로 보여주며 대비를 만든다
  ① 과거의 나  →  (스크롤)  →  ② 그동안의 일  →  (스크롤)  →  ③ 지금은?
```

- **데스크톱**: ①과 ②가 한 시야에 들어와 차이가 즉각적으로 보인다.
  ①을 더 넓게(7:5) 두어 시선이 왼쪽에서 시작하도록 하고, 읽기 순서는 좌→우 배치로 보장한다.
- **모바일**: 가로가 없으므로 대비를 **시간차로 만든다.** ①을 먼저 읽고 스크롤해야
  ②가 나타나는 구조는 오히려 순서 강제가 확실하다는 장점이 있다.
- **③은 두 화면 모두 전체 폭**이다. 결론과 액션은 비교 대상이 아니라 귀결이므로 나누지 않는다.
- 트레이드오프: 데스크톱의 나란한 배치는 "①을 먼저 읽는다"는 순서 강제가 모바일보다 약하다.
  대비의 즉각성이라는 이득이 더 크다고 판단해 이 배치를 택하되, ①의 시각적 우위(폭·강조)로
  보완한다.

#### 노트 작성 대화 — 남는 폭에 노트를 실시간으로 짓는다

채팅 UI는 세로로 긴 화면에 이미 최적화된 형태다. 문제는 데스크톱이다.
1440px 화면 한가운데 700px짜리 대화창만 두면 양옆이 그냥 빈다.

**데스크톱의 남는 폭에는 "지금 만들어지고 있는 노트"를 실시간으로 보여준다.**

```
데스크톱
┌─────────────────────────────┬──────────────────────────┐
│  AI  요즘 어떤 투자 아이디어를 │  만들어지는 노트          │
│      생각하고 계신가요?       │                          │
│                             │  대상   삼성전자      ✓   │
│      삼성전자 HBM 때문에      │  가설   HBM 공급 부족...  │
│      관심 보는 중             │                          │
│                             │  시나리오                 │
│  AI  어떤 점 때문에 관심이     │   A 수주 확대 성공    ✓   │
│      가셨는지...              │     📅 2026 Q4          │
│                             │   B 기술 격차 지속        │
│                             │     📅 시점 미정  ⚠      │
│  [메시지 입력...    ] [전송]  │                          │
│                             │      [ 여기까지 정리하기 ] │
└─────────────────────────────┴──────────────────────────┘

모바일 — 정리된 내용은 접히는 상단 바로 축약
┌────────────────────────┐
│ ← 새 노트               │
│ ▾ 대상✓ 가설✓ 시나리오 2 │  ← 탭하면 펼쳐짐
│  근거 항목 1개 비었음 ⚠ │
├────────────────────────┤
│                        │
│  AI  요즘 어떤 투자      │
│      아이디어를...       │
│                        │
│       삼성전자 HBM 때문에│
│       관심 보는 중       │
│                        │
├────────────────────────┤
│ [메시지 입력...  ] [전송]│
└────────────────────────┘
```

- 데스크톱 오른쪽 패널은 단순한 진행률 표시가 아니라 **결과물의 미리보기**다.
  대화가 어떻게 구조로 번역되고 있는지 보이면 사용자가 부족한 부분을 스스로 채운다.
- 모바일에서는 이 패널이 들어갈 폭이 없다. 접히는 상단 바로 축약하되,
  **빠진 항목(특히 판단 시점)은 접힌 상태에서도 보이게** 한다.
- 입력창은 모바일에서 하단 고정(엄지 도달 범위), 키보드 노출 시 대화가 밀려 올라간다.

#### 노트 목록 — 행을 눕혀 전부 보이게

노트는 10개 내외 전제이므로(P7), 데스크톱에서는 **스크롤 없이 전부 보이는 것**이 목표다.

- **데스크톱**: 한 행에 `노트명 · 가설 요약 · 시나리오 수 · 다음 판단 시점 · 새 정보`를
  가로로 전부 배치. 행 높이 약 56px × 10개 = 560px로 한 화면에 들어온다.
- **모바일**: 한 항목이 카드가 되며 3줄로 접힌다(노트명+시점 / 가설 요약 / 시나리오·새 정보).
  높이 약 96px, 스크롤 발생하지만 세로는 저렴하므로 허용한다.

### 11.4 터치 입력 고려

가로 폭 축소는 레이아웃만이 아니라 **조작 방식**도 바꾼다.

**확률 슬라이더가 대표적인 문제다.** 5% 단위면 조절 칸이 20개인데, 모바일 폭 340px에서는
한 칸이 17px밖에 안 된다. 손가락으로 정확히 집기 어렵고, 가로로 끄는 동작이 페이지
세로 스크롤과 부딪힌다.

> **모바일에서는 슬라이더 대신 `−` / `+` 버튼을 쓴다.**

```
데스크톱          A. 수주 확대 성공                    65%
                 ●━━━━━━━━━━━━━━━━━━━━━━━━━━  (드래그)

모바일            A. 수주 확대 성공
                 ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░  (표시 전용)
                 [  −  ]    65%    [  +  ]   (5% 단위)
```

그 외 규칙:
- 손가락으로 누르는 영역은 최소 44×44px. 시나리오 카드의 `다시 판단하기`,
  새 정보의 `반영` 등이 해당.
- 주요 버튼(`열어보기`, `다시 판단하기`)은 화면 아래쪽 1/3 안에 둔다 — 엄지가 닿는 범위.
- hover에만 의존하는 정보를 두지 않는다. 데스크톱 타임라인의 마커 툴팁은 모바일에서
  탭으로 열리는 시트가 된다.
- 가로 드래그 제스처는 확률 조정 외에도 전면 회피한다. 세로 스크롤과 충돌한다.

### 11.5 브레이크포인트

| 구간 | 폭 | 레이아웃 |
|---|---|---|
| Wide | ≥ 1280px | 완전한 2단 구성. 노트 상세 좌우 분리, 리마인드 ①②나란히, 작성 시 노트 패널 |
| Medium | 768 ~ 1279px | 단일 열. 노트 상세는 탭, 리마인드는 세로 3단 |
| Narrow | < 768px | 모바일 규칙 전면 적용. 타임라인 세로축, `−`/`+` 버튼 입력, 하단 고정 입력창 |

Medium 구간은 **모바일 규칙을 그대로 따른다.** 노트 상세의 좌우 분리는 각 열이 380px 이하로
좁아져 실용성이 없기 때문이다. 타임라인은 어느 구간에서든 세로축이므로 분기가 필요 없다.

### 11.6 금지 패턴

아래는 반응형 작업에서 흔히 나오지만 이 앱에서는 명시적으로 금지한다.

| 금지 | 이유 |
|---|---|
| 분리된 두 영역을 세로 스택으로 변환 | 분리(P4)가 "연속된 문서"로 읽혀 의미가 소실됨 |
| 넓은 화면에서 우선순위 목록을 다열 그리드로 변환 | 우선순위가 사라짐 (9.1) |
| 타임라인을 축 없는 단순 목록으로 만들기 | 눈에 보이는 축·점·연결선이 없으면 시간 조망이라는 고유 가치를 잃는다 |
| 새 정보 피드를 모바일 하단 접힘 섹션으로 밀기 | 사실상 미노출과 같음 |
| 데스크톱에서 세로 스크롤을 전제한 배치 | 뷰포트가 세로로 짧음(750px). 가로 폭으로 높이를 줄일 것 |
| 모바일에서 데스크톱과 다른 정보를 삭제 | 정보 삭제가 아니라 배치 변경으로 해결. 기록 접근성은 이 앱의 핵심 |

### 11.7 구현 순서

**작성은 데스크톱, 확인은 모바일**이라는 실사용 패턴을 전제로 한다.

1. 데스크톱 전체 (Wide) — 작성·조회의 주 환경
2. 모바일 리마인드 확인 흐름 (홈 → 리마인드 상세 → 다시 판단하기)
3. 모바일 전체 (작성 대화 포함)
4. Medium 구간 정리

3. 면책 고지 + 동의
4. **바로 대화 시작**: "요즘 어떤 투자 아이디어를 생각하고 계신가요?"
5. 첫 노트 저장 직후, 리마인드가 언제 올지 안내:
   > "4주 뒤, 그리고 A 시나리오의 판단 시점(2026 Q4)이 다가올 때
   >  이 노트를 다시 보여드리겠습니다."

이 마지막 안내가 앱의 핵심 약속이므로 반드시 노출한다.

## 13. MVP UX 범위

### 포함
- 홈: 타임라인 + 리마인드 피드 (기본 3장)
- 대화형 노트 작성 → AI 노트 생성 → 미리보기/수정 → 저장
- 노트 상세: 좌우 분리 구조, 시나리오 보드, 확률 조정, 원본 대화 열람
- 리마인드 상세 3단 화면
- 시나리오 상태 변화 (네 가지 선택지 포함)
- 1단계 대화(근거 항목 포함) → 노트 초안 확인 → 2단계 확인 방법 설정 폼 (건너뛰기 가능)
- auto 조건 일 1회 수집·평가, 목표까지의 거리 표시
- 지켜보는 수치 등록과 추이 차트 (판정하지 않음)
- 회고록 (AI 초안 + 벤치마크 비교 + 사용자 서술)
- `[사용자]` 저작 표기
- 온디맨드 AI 리서치 (`지금 다시 조사하기`)
- 정기 / 시점 기반 리마인드, 이메일 알림
- 노트 목록, 검색
- Wide / Narrow 두 구간의 반응형 대응 (§11.7 구현 순서에 따름)

### 이연
- 자동 주기 백그라운드 리서치 → Phase 2
- 이벤트 기반 즉시 알림 → Phase 2
- 확률 변화 그래프 시각화 → Phase 3 (MVP는 이력 리스트로 대체)
- 회고 리포트 / 판단 패턴 분석 → Phase 3
- 푸시 알림(PWA) → Phase 2
- 종료된 노트 아카이브 뷰 → Phase 2
- Medium 구간(768~1279px) 세부 정리 → Phase 2 (MVP는 Narrow 규칙으로 근사)

## 14. 남은 오픈 이슈

- **타임라인 구간 경계값**: `이번 주 / ~1개월 / ~3개월 / ~6개월 / 그 이후`가 실제 투자
  판단 주기와 맞는지 검증 필요.
- **타임라인 길이**: 세로축은 항목 수를 감당하지만 그만큼 페이지가 길어진다. 노트가 10개를
  넘어가면 먼 구간을 기본 접힘으로 둘지 검토 필요.
- **대화 길이 관리**: AI가 필수 항목을 확보하기까지 몇 턴이 적정한가. 너무 길면 P6에 위배.
  목표치를 5~8턴으로 잡고 실측 필요.
- **노트 간 연결**: 여러 노트가 같은 거시 변수(예: 금리)에 걸려 있을 때 이를 연결해 보여줄
  것인가. 가치는 크지만 P7(단순한 내비게이션)과 충돌 — Phase 3에서 재검토.
- **AI 견해의 강도 조절**: 사용자가 AI 의견의 적극성을 설정할 수 있게 할 것인가
  (정보만 / 의견 포함 / 적극 제안). 현재는 "적극 제안" 고정으로 설계.
- **알림 중복**: 이메일과 푸시가 함께 켜졌을 때 어떻게 묶어 보낼지.
- **2단계 확인 방법 설정의 이탈률**: 건너뛸 수 있게 만든 대가로 대부분의 사용자가 이를 영영
  설정하지 않을 수 있다. 앱은 동작하지만 자동 판정이라는 차별점이 사라진다.
  2단계 진입률·완료율을 초기 계측값으로 측정하고, 낮으면 1단계 말미에 최소 1개만 받는
  절충안을 검토한다. **이 기능에서 가장 큰 위험이다.**
- **2단계 재유도 동선**: 설정하지 않은 노트에 압박 없이 다시 권하는 방법. 현재는 노트 상세의
  안내 한 줄뿐인데 이것만으로 충분한지 미지수.
- **회고록의 재방문 동선**: 같은 대상으로 새 노트를 만들 때 과거 회고를 소환하는 것 외에,
  노트 목록에서 종료된 노트의 회고를 어떻게 다시 만나게 할지 미정.
- **계열 이름의 번역 품질**: 사용자가 말한 "유동성"을 FRED의 어느 계열로 매핑할지가
  이 기능의 사용성을 좌우한다. AI가 틀린 계열을 제안했을 때 사용자가 알아차릴 수 있는지,
  대안을 어떻게 보여줄지 미정.
- **확정되지 않은 미래 이벤트를 시점으로 잡은 경우**: "다음 실적 발표 시점"처럼 날짜가 아직
  공시되지 않은 것을 AI가 추정 날짜로 바꿔 넣는다. 실제 공시일이 나오면 자동으로 갱신할지,
  갱신 사실을 사용자에게 알릴지 미정. 추정 날짜로 리마인드가 잘못 뜨는 문제가 생길 수 있다.
- **auto가 하나도 안 잡히는 노트가 흔하다**: 정성적 판단(경영진 신뢰도, 브랜드 가치)만으로
  이루어진 가설은 전부 manual이 된다. 설계상 정상 동작이지만, 이런 노트에서 수집·평가
  기능이 아무 일도 하지 않는 것처럼 보이지 않게 지켜보는 수치를 얼마나 적극적으로
  권할지 검토 필요.
- **모바일 홈의 기본 세그먼트**: 피드를 기본으로 두었으나, 실제로는 타임라인부터 보고 싶어하는
  사용자가 있을 수 있다. 마지막 선택을 기억하게 할지 검토 필요.
- **데스크톱 리마인드 화면의 읽기 순서**: ①②를 나란히 두면 대비는 강해지지만 "①을 먼저 읽는다"는
  강제가 약해진다. 실사용에서 ②를 먼저 읽는 비율이 높으면 세로 배치로 전환을 검토.
- **가로 모드 태블릿**: 세로가 짧고 가로가 넓은 형태(예: 1024×768)는 Medium 구간에 속하지만
  데스크톱에 가까운 모양이다. 폭이 아니라 화면 비율로 나눠야 하는지 검토 필요.
