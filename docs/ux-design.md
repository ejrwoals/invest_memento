# Investment Memento — UX 설계 문서

> 본 문서는 UI 디자인(비주얼) 이전 단계의 **UX 설계**를 다룬다.
> 화면 구조, 정보 위계, 사용자 흐름, 상태 전이, 인터랙션 규칙을 정의하며
> 색상·타이포그래피·컴포넌트 스타일은 다루지 않는다.
>
> 선행 문서: [`development-plan.md`](./development-plan.md)

## 1. 설계 원칙

이 앱의 모든 화면과 인터랙션은 아래 7개 원칙을 따른다.
개별 화면 설계에서 판단이 갈릴 때는 이 원칙으로 되돌아온다.

### P1. 앱을 열면 "지금 봐야 할 것"이 먼저 나온다
노트 목록이 홈이면 이 앱은 메모장이 된다. 사용자가 스스로 찾아 열어야만 작동하는 도구는
메멘토 컨셉을 달성하지 못한다. 홈은 **가까운 미래의 타임라인 + 리마인드 피드**이고,
노트 목록은 별도 탭이다.

### P2. 원본 대화는 불변이다 (Immutable Source of Truth)
노트 본문은 AI가 대화를 바탕으로 작성한다. 이 구조에서 "과거의 나의 관점"이 엄밀히는
AI의 문장이 되므로, **사용자가 실제로 말한 원본 대화 전문은 절대 수정·요약·삭제되지 않고
그대로 보존**된다. 노트는 그 위에 얹힌 읽기 좋은 렌더링일 뿐이며, 사용자는 언제든
"내가 실제로 뭐라고 말했는지" 원문으로 내려갈 수 있다. 이것이 이 앱의 신뢰 기반이다.

### P3. 사용자가 쓴 것을 표시한다 (AI가 아니라)
노트 콘텐츠의 대부분은 AI가 작성하므로, `[AI]` 태그는 노이즈가 된다.
**희소한 쪽인 사용자 저작 콘텐츠에 `[사용자]` 표기를 붙인다.** (§7 참조)

### P4. 내 사고와 외부 정보는 섞이지 않는다
과거의 내 관점과 AI가 새로 가져온 정보가 한 덩어리로 뒤섞이면, 시간이 지났을 때
"내가 원래 뭘 생각했는지"가 오염된다. 두 영역은 화면상 **공간적으로 분리**되며,
리마인드 화면에서만 의도적으로 나란히 대비시킨다.

### P5. 죄책감을 유발하지 않는다 (Guilt-Free)
강제성 있는 리마인드는 스트레스가 되고, 스트레스는 앱을 안 열게 만든다.
다음을 **금지**한다:
- 미룬 횟수 / 무시한 횟수의 기록 및 노출
- 연속 달성(스트릭), 완료율, 점수, 등급
- 빨간 배지 카운트, 밀린 항목 누적 표시
- "확인하지 않으셨습니다", "N일째 방치 중" 류의 문구

미뤄진 리마인드는 조용히 큐로 돌아가고, 반복적으로 열리지 않으면 **벌이 아니라 적응**으로서
노출 빈도를 낮춘다.

### P6. 기록의 진입장벽을 최소화한다
가설·시나리오·시점을 폼으로 강제하면 데이터는 깔끔해지지만 작성이 귀찮아져 기록이 안 쌓인다.
기록이 없으면 이 앱은 가치가 0이다. 따라서 **작성은 AI와의 대화로 이루어지고, 구조화는
AI가 책임진다.**

### P7. 깊고 풍부한 노트, 단순한 내비게이션
동시 관리 노트는 10개 내외를 전제한다. 폴더·태그·복잡한 필터에 화면을 쓰지 않고,
**개별 노트를 깊게 보여주는 데 화면 예산을 집중**한다.

## 2. 정보 구조 (IA)

```
┌─ 홈 (타임라인 + 리마인드 피드)          ← 기본 진입점
│
├─ 노트
│   ├─ 노트 목록
│   └─ 노트 상세
│        ├─ 가설 & 시나리오 보드
│        ├─ 새 정보 피드 (AI 리서치)
│        ├─ 원본 대화 기록
│        └─ 재평가 이력
│
├─ 새 노트 작성 (AI 대화)                 ← 전역 진입 가능
│
├─ 리마인드 상세                          ← 홈/알림에서 진입
│
└─ 설정
     ├─ 리마인드 주기 / 알림 채널
     └─ 계정
```

**전역 내비게이션은 3개로 고정한다: `홈` / `노트` / `+ 새 노트`**
설정은 우상단 아바타 메뉴로 밀어낸다. 탭이 늘어나면 P7에 위배된다.

## 3. 화면 설계

### 3.1 홈 — 타임라인 + 리마인드 피드

홈은 두 개의 층으로 구성된다. 위쪽은 **미래를 향한 시선**(타임라인), 아래쪽은
**지금 해야 할 일**(리마인드 피드)이다.

```
┌────────────────────────────────────────────────────────────┐
│  Investment Memento                            [👤]        │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  다가오는 판단 시점                                          │
│  ┌──────────┬──────────┬──────────┬──────────┬──────────┐  │
│  │  이번 주  │ ~1개월   │ ~3개월   │ ~6개월   │ 그 이후  │  │
│  │          │          │          │          │          │  │
│  │  ● 삼성전자│ ● 테슬라 │ ▬▬▬▬ 금리│ ● 엔비디아│ ● 부동산 │  │
│  │    HBM수주│   FSD인가│   인하    │   실적    │   금리   │  │
│  │          │          │          │          │          │  │
```

#### 타임라인 상세 규칙

- **비선형 압축**: 각 구간의 시각적 폭은 동일하지만 담는 기간은 다르다.
  `이번 주(7일) | ~1개월 | ~3개월 | ~6개월 | 그 이후`
  → 가까운 미래일수록 넓게 표시되어, 임박한 판단에 시선이 간다. (P1)
- **마커 표현**:
  - 특정 시점 시나리오 → 점(`●`)
  - 기간형 시나리오("2026 Q4까지") → 막대(`▬▬▬`)로 구간 전체에 걸쳐 표시
- **색상**: 노트별로 고정 색상을 배정. 같은 노트의 시나리오는 같은 색.
  노트 10개 내외 전제이므로 색상 구분이 실제로 작동한다. (P7)
- **밀집 처리**: 한 구간에 마커가 4개를 넘으면 상위 3개 + `+N` 로 접는다.
  우선순위는 시점 임박 > 확률 높음 순.
- **과거는 표시하지 않는다.** 판정이 밀린 시나리오는 타임라인이 아니라 리마인드 피드에서
  "판정 대기" 카드로 다룬다. (지나간 항목이 타임라인 왼쪽에 쌓이면 P5 위반)
- **인터랙션**: 마커 hover 시 시나리오 요약 툴팁, 클릭 시 해당 노트의 시나리오로 직행.

#### 리마인드 피드 상세 규칙

- **기본 3장까지만 노출**, 나머지는 `더 보기`. (알림 피로 방지)
- 카드 우선순위: `판정 대기 > 시점 임박 > 새 정보 > 정기 리마인드`
- **카드에는 "닫기(X)"가 없다.** 대신 카드를 열지 않고 넘기면 자동으로 뒤로 밀린다.
  명시적 "무시" 액션을 두면 무시했다는 사실이 인지되고, 그것이 곧 부채감이 된다. (P5)
- 각 카드는 **왜 지금 이게 떴는지를 한 줄로 반드시 설명**한다. 이유 없는 알림은 소음이다.
- **빈 상태**: 볼 것이 없을 때 "모두 완료!" 같은 성취 문구를 쓰지 않는다.
  ```
  지금 다시 볼 것은 없습니다.

  마지막으로 기록한 지 3주가 지났습니다.
  요즘 생각하고 계신 것이 있나요?          [ 새 노트 ]
  ```

### 3.2 새 노트 작성 — AI와의 대화

폼이 아니라 대화다. 사용자는 생각나는 대로 말하고, AI가 필요한 구조를 끌어낸다. (P6)

```
┌────────────────────────────────────────────────────────────┐
│  ← 나가기                              새 노트 · 대화 중    │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  AI  요즘 어떤 투자 아이디어를 생각하고 계신가요?            │
│      종목이든 테마든, 편하게 말씀해 주세요.                  │
│                                                            │
│                          삼성전자 HBM 때문에 관심 보는 중   │
│                          근데 아직 확신은 없어              │
│                                                            │
│  AI  HBM 쪽을 보시는군요. 어떤 점 때문에                    │
│      관심이 가셨는지 조금 더 들려주시겠어요?                 │
│                                                            │
│                     ... (대화 계속) ...                    │
│                                                            │
│  ┌──────────────────────────────────────────────────┐     │
│  │  구성 현황                                        │     │
│  │  ✓ 투자 대상      ✓ 핵심 가설                     │     │
│  │  ✓ 시나리오 2개   ⚠ 판단 시점 1개 누락            │     │
│  └──────────────────────────────────────────────────┘     │
│                                                            │
│  [ 메시지 입력...                          ] [보내기]      │
│                                     [ 여기까지 정리하기 ]  │
└────────────────────────────────────────────────────────────┘
```

#### 대화가 끌어내야 할 것 (AI의 목표)

우선순위 순으로, 자연스러운 대화 안에서 확보한다. 심문처럼 느껴지면 안 된다.

| 항목 | 필수 | AI의 접근 |
|---|---|---|
| 투자 대상 | ✔ | 첫 발화에서 대개 확보됨 |
| 핵심 가설 | ✔ | "그래서 결국 어떻게 될 거라고 보시는 거죠?" |
| 시나리오 (2개 이상) | ✔ | "반대로 흘러간다면 어떤 모습일까요?" |
| 각 시나리오의 **판단 시점** | ✔ | "이건 언제쯤 판가름 날까요?" — 가장 중요 |
| 확인 지표 | 권장 | "무엇을 보면 그렇게 되고 있다는 걸 알 수 있을까요?" |
| 근거 자료 | 선택 | 사용자가 링크를 붙이면 수집 |
| 반증 조건 | 권장 | "이 판단이 틀렸다는 건 뭘로 알 수 있을까요?" |

**시점(timeframe)에 대해서만 AI가 끈질기다.** 시점 없는 시나리오는 검증도 리마인드도
불가능해서 이 앱의 존재 이유 자체가 사라지기 때문이다. 다만 강요하지는 않고,
막연하면 범위("올해 안", "다음 실적 발표쯤")로라도 받아낸다.

#### 대화 종료 → 노트 생성

- 사용자가 `여기까지 정리하기`를 누르거나, AI가 필수 항목을 다 확보하면 제안한다.
- AI가 노트 초안을 생성 → **미리보기 화면**에서 사용자가 확인.
  - 각 섹션마다 `수정` 가능. 직접 수정한 블록은 `[사용자]`로 표기된다. (§7)
  - "이건 내가 말한 뜻과 다른데" → 그 자리에서 대화로 되돌아가 보정 가능.
- 저장 시 **원본 대화 전문이 노트에 영구 첨부**된다. (P2)

#### 이탈과 재개

- 대화 중 이탈해도 임시 저장(draft)되며, 홈 상단에 조용히 재개 링크가 뜬다.
- 필수 항목이 덜 찬 상태로도 저장 가능. 단 이 노트는 **미완성 상태**가 되어
  리마인드 대상에서 제외되고, 노트 상세 상단에 "판단 시점을 정하면 리마인드가 시작됩니다"
  라는 안내가 붙는다. (차단이 아니라 안내 — P5)

### 3.3 노트 상세 — 좌우 분리 구조

**이 화면의 레이아웃 자체가 P4(내 사고 ↔ 외부 정보 분리)의 구현체다.**
왼쪽은 나의 사고, 오른쪽은 세상이 가져온 정보. 이 경계는 시각적으로 명확해야 한다.

#### 구성 요소

**좌측 — 나의 관점 (변화가 느리고, 내가 소유하는 영역)**
- 핵심 가설: AI가 작성한 요약. 사용자 원문 인용은 `[사용자]`로 구분 표시.
- 시나리오 카드: 확률 게이지 + 판단 시점 + 확인 지표 + 상태. `재평가` 액션 내장.
- `그 외 예상 못한 전개` 슬롯 (§5 참조)
- 접힘 섹션: 내가 붙인 자료 / 원본 대화 기록 / 재평가 이력

**우측 — 새로 들어온 정보 (변화가 빠르고, 외부에서 오는 영역)**
- 시간 역순 피드. 각 항목은 요약 1~2줄 + 관계 태그 + 원문 링크.
- 관계 태그: `↗ 지지` / `↘ 약화` / `— 중립` — 어느 시나리오에 대한 것인지 명시.
- `반영` 버튼: 이 정보를 근거로 시나리오 재평가로 진입.
- `지금 다시 조사하기`: 온디맨드 리서치 실행. (MVP의 주 실행 경로)

#### 반응형

- 데스크톱(≥1024px): 위 2단 레이아웃. 좌측 비중 6 : 우측 4.
- 태블릿/모바일: 세로 스택. **좌측(나의 관점)이 항상 먼저** 온다 — 새 정보를 먼저 보면
  과거의 내 관점을 그 프레임으로 읽게 되어 P4의 취지가 깨진다.
  우측은 `새로 들어온 정보 (3)` 접힘 섹션으로 아래에 배치.

  제약 없이 제시한다. 면책은 UI 하단 고지가 담당한다.
- `나중에`는 아무 기록도 남기지 않는다. 미룬 횟수를 세지 않는다. (P5)

## 4. 시나리오 라이프사이클

시나리오의 상태 전이는 이 앱의 핵심 로직이다. **자동으로 폐기되는 상태는 없다.**

```
                    ┌──────────┐
     노트 생성  ───▶ │  active  │
                    └────┬─────┘
                         │  판단 시점 도래
                         ▼
                 ┌───────────────┐
                 │ pending_      │  ← 리마인드 발생
                 │ judgment      │     (자동 판정 없음)
                 └───┬───┬───┬───┘
            사용자 판정 │   │   │
          ┌───────────┘   │   └───────────┐
          ▼               ▼               ▼
    ┌───────────┐  ┌───────────┐   ┌──────────────┐
    │ confirmed │  │ rejected  │   │ 시점 재설정   │
    │  (적중)   │  │  (기각)   │   │ → active로   │
    └───────────┘  └───────────┘   └──────────────┘
```

### 상태 정의

| 상태 | 의미 | 진입 조건 |
|---|---|---|
| `active` | 검증 진행 중 | 생성 시 기본값 / 시점 재설정 시 |
| `pending_judgment` | 시점이 도래했으나 사용자 판정 전 | 판단 시점 경과 (시스템 자동) |
| `confirmed` | 시나리오대로 전개됨 | 사용자 판정 |
| `rejected` | 시나리오가 틀렸음 | 사용자 판정 |

### 설계 판단: "시점 재설정"을 1급 선택지로 둔다

현실에서 흔한 경우는 **"방향은 맞았는데 시기를 잘못 봤다"**이다.
이때 `rejected`만 강요하면 사용자는 판정을 회피하고 시나리오를 방치하게 된다.
따라서 판정 UI는 세 갈래를 동등하게 제시한다:

```
  이 시나리오는 어떻게 되었나요?

  [ 그대로 되었다 ]  [ 틀렸다 ]  [ 방향은 맞지만 시기를 다시 본다 ]
```

- `시점 재설정` 선택 시 새 판단 시점을 입력받고 `active`로 복귀.
  **단, 재설정 이력은 시나리오에 남는다** — 벌점이 아니라, 회고 시
  "나는 늘 너무 빠르게 예상한다"는 패턴을 발견하기 위한 데이터다.
  이 이력은 재평가 이력 섹션 안에서만 보이고, 카드 표면이나 홈에는 노출하지 않는다. (P5)
- `confirmed` / `rejected` 선택 시 **사유를 한 줄 남기도록 권한다** (선택 사항).
  이것이 나중에 가장 값진 회고 자료가 된다.

## 5. 확률 입력 UX

### 상호배타 전제 + 정규화

한 노트의 시나리오들은 **상호배타적 분기로 취급**하고, 확률 합이 항상 100%가 되도록 한다.
하나를 올리면 나머지가 자동으로 줄어든다.

이유: 절대 확률을 따로 매기면 "A도 70%, B도 60%" 같은 비일관적 입력이 나오고,
무엇보다 **트레이드오프 사고를 강제하지 못한다.** 하나를 올리려면 무언가를 내려야 한다는
제약이 있어야 사고가 정직해진다.

### `그 외 예상 못한 전개` 슬롯

모든 노트에 **자동으로 생성되며 삭제할 수 없는** 시나리오 슬롯을 둔다.

```
  그 외 예상 못한 전개                    10%
  ▓▓░░░░░░░░░░░░░░░░░░
```

- 사용자가 상정한 시나리오들의 합이 100%가 되지 않도록, 이 슬롯이 잔여분을 흡수한다.
- 최소값 5%를 강제한다 — **"내가 생각한 경우의 수가 전부다"라는 착각을 구조적으로 차단**한다.
- 이 슬롯이 실제로 실현되면(= 예상 못한 일이 벌어지면) 사용자는 이를 근거로
  새 시나리오를 추가하거나 노트 자체를 재작성한다.

### 입력 방식

- 슬라이더로 조정하되, 눈금은 5% 단위로 스냅. (1% 단위의 가짜 정밀도를 피한다)
- 조정 시 다른 시나리오들이 비례 배분으로 자동 조정되며, 특정 시나리오는 `잠금`으로 고정 가능.
- 조정 시 **변경 사유를 한 줄 남기도록 권한다** (선택 사항, 하지만 강하게 권장).
  확률 변화 이력에서 "왜 그때 생각을 바꿨는지"가 남는 것이 숫자보다 훨씬 중요하다.

## 6. 리마인드 트리거 & 우선순위

### 트리거 종류

| 종류 | 발생 조건 | 기본 설정 |
|---|---|---|
| 판정 대기 | 시나리오 판단 시점 경과 | 즉시, 이후 주 1회 |
| 시점 임박 | 판단 시점 D-7 도달 | 1회 |
| 새 정보 | AI 리서치에서 `relevance_score` 임계 초과 | 즉시 (일 1회로 배칭) |
| 정기 리마인드 | 마지막 검토로부터 N주 경과 | 기본 4주 |

### 감쇠 규칙 (Guilt-Free 구현)

동일 노트의 리마인드가 **연속 3회 열리지 않으면 주기를 2배로 늘린다.**
그 이후에도 계속 열리지 않으면 다시 2배(최대 12주까지).
사용자가 한 번이라도 열면 기본 주기로 즉시 복귀한다.

이는 처벌이 아니라 **관심의 실제 수준에 시스템이 맞춰가는 것**이다. 사용자에게는
이 로직이 노출되지 않는다 — "당신이 무시해서 빈도를 줄였습니다"라는 메시지는 P5 위반이다.

### 일일 총량 제한

- 홈 피드 기본 노출: 3장
- 푸시/이메일 알림: **하루 1회로 배칭.** 여러 건은 한 통에 묶는다.
- 알림 발송 시각: 사용자 설정 (기본값 = 장 마감 이후, 예: 평일 18:00)
  장중 알림은 충동적 판단을 유발하므로 기본값에서 배제한다.

## 7. 저작자 표기 규칙

노트 콘텐츠의 대부분은 AI가 작성하므로 **AI 콘텐츠는 무표기가 기본값**이고,
사용자 저작 콘텐츠에만 `[사용자]`를 붙인다. (P3)

### `[사용자]`가 붙는 대상

| 대상 | 표기 |
|---|---|
| 대화 중 사용자 발화가 노트에 직접 인용된 문장 | `[사용자]` + 좌측 보더 강조 |
| 사용자가 노트를 직접 편집한 블록 | `[사용자]` |
| 사용자가 직접 첨부한 링크/파일/메모 | 섹션 헤더에 `[사용자]` |
| 시나리오 확률 변경 사유 | `[사용자]` |
| 시나리오 판정 사유 | `[사용자]` |

### 표기하지 않는 대상

- AI가 작성한 가설 요약, 시나리오 설명, 리서치 요약, 조언 — 전부 무표기.
- 단, **AI의 주관적 견해(매수/매도 의견, 확률 조정 제안)는 별도 블록으로 감싸
  "AI의 견해"라는 헤더를 붙인다.** 이는 저작자 표기가 아니라 사실과 의견의 구분이다.

### 원본 대화 접근

모든 노트에서 `원본 대화 기록` 섹션을 통해 전체 대화 전문에 접근할 수 있다.
이 기록은 **읽기 전용이며 수정·삭제 불가**다. (P2)

## 8. 면책 고지 배치

AI가 매수/매도 의견을 자유롭게 제시하는 대신, 면책 고지를 UI 레벨에서 상시 노출한다.

| 위치 | 형태 |
|---|---|
| 온보딩 마지막 단계 | 전체 화면 고지 + 명시적 동의 |
| 노트 상세 하단 | 고정 푸터 (스크롤과 무관하게 상시) |
| 리마인드 상세 하단 | 고정 푸터 |
| AI가 매수/매도 의견을 낸 블록 | 블록 하단에 축약 고지 1줄 |
| 설정 | 전문 상시 열람 가능 |

문구는 짧고 명확하게, 그러나 반복 노출되므로 시각적으로는 절제한다:
> ⚠ 최종 투자 판단과 그 책임은 사용자 본인에게 있습니다.

## 9. 반응형 대응

| 화면 | 데스크톱 (≥1024px) | 모바일 (<768px) |
|---|---|---|
| 홈 타임라인 | 가로 5구간 축 | 구간별 세로 섹션 리스트 |
| 홈 피드 | 카드 3장 세로 | 동일 (카드 폭 100%) |
| 노트 상세 | 2단 (좌 6 : 우 4) | 세로 스택, **좌측 콘텐츠 우선** |
| 새 정보 피드 | 우측 상시 노출 | 접힘 섹션 |
| 노트 작성 대화 | 중앙 정렬 대화창 + 우측 구성 현황 | 대화창 전체 폭, 구성 현황은 상단 축약 바 |
| 리마인드 상세 | 3단 세로 (폭 제한) | 동일 |

**작성은 데스크톱, 확인은 모바일**이라는 실사용 패턴을 전제한다.
따라서 개발 순서는 `데스크톱 전체 → 모바일 리마인드 확인 플로우 → 모바일 전체`로 잡는다.

## 10. 온보딩

첫 사용자는 노트가 없어 이 앱의 가치를 전혀 체감할 수 없다.
설명 대신 **첫 노트를 즉시 만들게 하는 것**이 유일한 온보딩이다.

1. 로그인
2. 한 화면짜리 컨셉 설명 (3문장 이내) — "과거의 당신을 잊지 않게 돕습니다"
3. 면책 고지 + 동의
4. **바로 대화 시작**: "요즘 어떤 투자 아이디어를 생각하고 계신가요?"
5. 첫 노트 저장 직후, 리마인드가 언제 올지 안내:
   > "4주 뒤, 그리고 A 시나리오의 판단 시점(2026 Q4)이 다가올 때
   >  이 노트를 다시 보여드리겠습니다."

이 마지막 안내가 앱의 핵심 약속이므로 반드시 노출한다.

## 11. MVP UX 범위

### 포함
- 홈: 타임라인 + 리마인드 피드 (기본 3장)
- 대화형 노트 작성 → AI 노트 생성 → 미리보기/수정 → 저장
- 노트 상세: 좌우 분리 구조, 시나리오 보드, 확률 조정, 원본 대화 열람
- 리마인드 상세 3단 화면
- 시나리오 라이프사이클 (3갈래 판정 포함)
- `[사용자]` 저작 표기
- 온디맨드 AI 리서치 (`지금 다시 조사하기`)
- 정기 / 시점 기반 리마인드, 이메일 알림
- 노트 목록, 검색

### 이연
- 자동 주기 백그라운드 리서치 → Phase 2
- 이벤트 기반 즉시 알림 → Phase 2
- 확률 변화 그래프 시각화 → Phase 3 (MVP는 이력 리스트로 대체)
- 회고 리포트 / 판단 패턴 분석 → Phase 3
- 푸시 알림(PWA) → Phase 2
- 종료된 노트 아카이브 뷰 → Phase 2

## 12. 남은 오픈 이슈

- **타임라인 구간 경계값**: `이번 주 / ~1개월 / ~3개월 / ~6개월 / 그 이후`가 실제 투자
  판단 주기와 맞는지 프로토타입으로 검증 필요.
- **대화 길이 관리**: AI가 필수 항목을 확보하기까지 몇 턴이 적정한가. 너무 길면 P6에 위배.
  목표치를 5~8턴으로 잡고 실측 필요.
- **노트 간 연결**: 여러 노트가 같은 거시 변수(예: 금리)에 걸려 있을 때 이를 연결해 보여줄
  것인가. 가치는 크지만 P7(단순한 내비게이션)과 충돌 — Phase 3에서 재검토.
- **AI 견해의 강도 조절**: 사용자가 AI 의견의 적극성을 설정할 수 있게 할 것인가
  (정보만 / 의견 포함 / 적극 제안). 현재는 "적극 제안" 고정으로 설계.
- **다중 기기 알림 중복**: 이메일과 푸시가 함께 켜졌을 때의 배칭 정책.
