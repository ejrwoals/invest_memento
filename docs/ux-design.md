# Investment Memento — UX 설계 문서

> 본 문서는 UI 디자인(비주얼) 이전 단계의 **UX 설계**를 다룬다.
> 화면 구조, 정보의 우선순위, 사용자 흐름, 상태 변화, 조작 규칙을 정의하며
> 색상·타이포그래피·컴포넌트 스타일은 다루지 않는다.
>
> 선행 문서: [`development-plan.md`](./development-plan.md)

## 1. 설계 원칙

이 앱의 모든 화면과 조작은 아래 8개 원칙을 따른다.
개별 화면 설계에서 판단이 갈릴 때는 이 원칙으로 되돌아온다.

### P1. 앱을 열면 "지금 봐야 할 것"이 먼저 나온다
노트 목록이 홈이면 이 앱은 메모장이 된다. 사용자가 스스로 찾아 열어야만 작동하는 도구는
메멘토 컨셉을 달성하지 못한다. 홈은 **가까운 미래의 타임라인 + 리마인드 피드**이고,
노트 목록은 별도 탭이다.

### P2. 원본 대화는 고치지 않는다
노트 본문은 AI가 대화를 바탕으로 작성한다. 이 구조에서 "과거의 나의 관점"이 엄밀히는
AI의 문장이 되므로, **사용자가 실제로 말한 원본 대화 전문은 절대 수정·요약·삭제되지 않고
그대로 보존**된다. 노트는 그 위에 얹힌 읽기 좋은 렌더링일 뿐이며, 사용자는 언제든
"내가 실제로 뭐라고 말했는지" 원문으로 내려갈 수 있다. 이것이 이 앱의 신뢰 기반이다.

### P3. 사용자가 쓴 것을 표시한다 (AI가 아니라)
노트 내용의 대부분은 AI가 작성하므로, `[AI]` 태그를 붙이면 화면이 태그로 뒤덮인다.
**드문 쪽인 사용자가 쓴 부분에만 `[사용자]` 표기를 붙인다.** (§8 참조)

### P4. 내 사고와 외부 정보는 섞이지 않는다
과거의 내 관점과 AI가 새로 가져온 정보가 한 덩어리로 뒤섞이면, 시간이 지났을 때
"내가 원래 뭘 생각했는지"가 오염된다. 두 영역은 화면상 **공간적으로 분리**되며,
리마인드 화면에서만 의도적으로 나란히 대비시킨다.

### P5. 죄책감을 유발하지 않는다
강제성 있는 리마인드는 스트레스가 되고, 스트레스는 앱을 안 열게 만든다.
다음을 **금지**한다:
- 미룬 횟수 / 무시한 횟수의 기록 및 노출
- 연속 달성(스트릭), 완료율, 점수, 등급
- 빨간 배지 카운트, 밀린 항목 누적 표시
- "확인하지 않으셨습니다", "N일째 방치 중" 류의 문구

미뤄진 리마인드는 조용히 큐로 돌아가고, 반복적으로 열리지 않으면 **벌이 아니라 적응**으로서
노출 빈도를 낮춘다.

### P6. 기록의 진입장벽을 최소화한다
가설·시나리오·시점을 폼으로 강제하면 데이터는 깔끔해지지만 작성이 귀찮아져 기록이 안 쌓인다.
기록이 없으면 이 앱은 가치가 0이다. 따라서 **작성은 AI와의 대화로 이루어지고, 구조화는
AI가 책임진다.**

### P7. 깊고 풍부한 노트, 단순한 내비게이션
동시 관리 노트는 10개 내외를 전제한다. 폴더·태그·복잡한 필터에 화면을 쓰지 않고,
**개별 노트를 깊게 보여주는 데 화면 예산을 집중**한다.

### P8. 우리끼리 쓰는 말을 화면에 내보내지 않는다
설계 과정에서 만든 용어는 팀 안에서는 편하지만, 사용자에게는 아무 의미가 없다.
사용자는 앱을 배우러 온 것이 아니라 자기 생각을 기록하러 온 것이다.
**화면에 나가는 모든 문구는 이 앱을 처음 여는 사람이 설명 없이 이해할 수 있어야 한다.**

- 전문용어처럼 보이는 말, 새로 만든 합성어, 영어 약어를 화면에 쓰지 않는다.
- 상태나 기능의 이름은 **그 상태에서 사용자가 할 일**로 짓는다.
  (`판정 대기` ✗ → `결과 확인 필요` ○ — 무슨 상태인지가 아니라 무엇을 하면 되는지를 말한다)
- 개발상의 이름(`pending_judgment`)과 화면에 나가는 말은 별개다. 코드에서 쓰는 식별자를
  그대로 번역해서 화면에 올리지 않는다. (§8.4 대응표 참조)
- 문서 안에서도 마찬가지다. 개념에 이름을 붙이기 전에, 그냥 풀어 쓰면 되는지 먼저 확인한다.

이 앱의 고유 개념 중 화면에 드러내도 되는 것은 **메멘토**(제품 컨셉 자체)뿐이다.

## 2. 정보 구조 (IA)

```
┌─ 홈 (타임라인 + 리마인드 피드)          ← 기본 진입점
│
├─ 노트
│   ├─ 노트 목록
│   └─ 노트 상세
│        ├─ 가설 & 시나리오 보드
│        ├─ 새 정보 피드 (AI 리서치)
│        ├─ 원본 대화 기록
│        ├─ 생각이 바뀐 기록
│        └─ 회고록 (결과 확정 후)
│
├─ 새 노트 작성 (AI 대화)                 ← 전역 진입 가능
│
├─ 리마인드 상세                          ← 홈/알림에서 진입
│
└─ 설정
     ├─ 리마인드 주기 / 알림 채널
     └─ 계정
```

**전역 내비게이션은 3개로 고정한다: `홈` / `노트` / `+ 새 노트`**
설정은 우상단 아바타 메뉴로 밀어낸다. 탭이 늘어나면 P7에 위배된다.

## 3. 화면 설계

> 이 절의 와이어프레임은 모두 **데스크톱(가로 넓은 화면) 기준**이다.
> 모바일(세로 긴 화면)에서의 변환 규칙과 그 근거는 [§10 화면 비율에 따른 설계](#10-화면-비율에-따른-설계)에서 다룬다.

### 3.1 홈 — 타임라인 + 리마인드 피드

홈은 두 개의 층으로 구성된다. 위쪽은 **미래를 향한 시선**(타임라인), 아래쪽은
**지금 해야 할 일**(리마인드 피드)이다.

│  │  ● 삼성전자│ ● 테슬라 │ ▬▬▬▬ 금리│ ● 엔비디아│ ● 부동산 │  │

#### 타임라인 상세 규칙

- **가까운 시점일수록 넓게**: 각 구간의 폭은 같지만 담는 기간은 다르다.
  `이번 주(7일) | ~1개월 | ~3개월 | ~6개월 | 그 이후`
  → 가까운 미래일수록 넓게 표시되어, 임박한 판단에 시선이 간다. (P1)
- **마커 표현**:
  - 특정 시점 시나리오 → 점(`●`)
  - 기간형 시나리오("2026 Q4까지") → 막대(`▬▬▬`)로 구간 전체에 걸쳐 표시
- **색상**: 노트별로 고정 색상을 배정. 같은 노트의 시나리오는 같은 색.
  노트 10개 내외 전제이므로 색상 구분이 실제로 작동한다. (P7)
- **밀집 처리**: 한 구간에 마커가 4개를 넘으면 상위 3개 + `+N` 로 접는다.
  우선순위는 시점 임박 > 확률 높음 순.
- **지나간 것은 표시하지 않는다.** 확인이 밀린 시나리오는 타임라인이 아니라 리마인드 피드에서
  `결과 확인 필요` 카드로 다룬다. (지나간 항목이 타임라인 왼쪽에 쌓이면 P5 위반)
- **인터랙션**: 마커 hover 시 시나리오 요약 툴팁, 클릭 시 해당 노트의 시나리오로 직행.

#### 리마인드 피드 상세 규칙

- **기본 3장까지만 노출**, 나머지는 `더 보기`. (알림 피로 방지)
- 카드 우선순위: `결과 확인 필요 > 지표 달성 > 시점 임박 > 새 정보 > 정기 리마인드`
- **카드에는 "닫기(X)"가 없다.** 대신 카드를 열지 않고 넘기면 자동으로 뒤로 밀린다.
  명시적 "무시" 액션을 두면 무시했다는 사실이 인지되고, 그것이 곧 부채감이 된다. (P5)
- 각 카드는 **왜 지금 이게 떴는지를 한 줄로 반드시 설명**한다. 이유 없는 알림은 소음이다.
- **빈 상태**: 볼 것이 없을 때 "모두 완료!" 같은 성취 문구를 쓰지 않는다.
  ```
  지금 다시 볼 것은 없습니다.

  마지막으로 기록한 지 3주가 지났습니다.
  요즘 생각하고 계신 것이 있나요?          [ 새 노트 ]
  ```

### 3.2 새 노트 작성 — AI와의 대화

폼이 아니라 대화다. 사용자는 생각나는 대로 말하고, AI가 필요한 구조를 끌어낸다. (P6)

```
┌────────────────────────────────────────────────────────────┐
│  ← 나가기                              새 노트 · 대화 중    │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  AI  요즘 어떤 투자 아이디어를 생각하고 계신가요?            │
│      종목이든 테마든, 편하게 말씀해 주세요.                  │
│                                                            │
│                          삼성전자 HBM 때문에 관심 보는 중   │
│                          근데 아직 확신은 없어              │
│                                                            │
│  AI  HBM 쪽을 보시는군요. 어떤 점 때문에                    │
│      관심이 가셨는지 조금 더 들려주시겠어요?                 │
│                                                            │
│                     ... (대화 계속) ...                    │
│                                                            │
│  ┌──────────────────────────────────────────────────┐     │
│  │  지금까지 정리된 내용                             │     │
│  │  ✓ 투자 대상      ✓ 핵심 가설                     │     │
│  │  ✓ 시나리오 2개   ✓ 판단 시점                     │     │
│  │  ⚠ 판단 지표 1개 비었음                           │     │
│  └──────────────────────────────────────────────────┘     │
│                                                            │
│  [ 메시지 입력...                          ] [보내기]      │
│                                     [ 여기까지 정리하기 ]  │
└────────────────────────────────────────────────────────────┘
```

#### 대화가 끌어내야 할 것 (AI의 목표)

우선순위 순으로, 자연스러운 대화 안에서 확보한다. 심문처럼 느껴지면 안 된다.

| 항목 | 필수 | AI의 접근 |
|---|---|---|
| 투자 대상 | ✔ | 첫 발화에서 대개 확보됨 |
| 핵심 가설 | ✔ | "그래서 결국 어떻게 될 거라고 보시는 거죠?" |
| 시나리오 (2개 이상) | ✔ | "반대로 흘러간다면 어떤 모습일까요?" |
| 각 시나리오의 **판단 시점** | ✔ | "이건 언제쯤 판가름 날까요?" |
| 각 시나리오의 **결과 지표** | ✔ | "무엇이 어떻게 되면 맞았다고 보시겠어요?" |
| 각 시나리오의 **근거 항목** | ✔ | "그렇게 되려면 그 전에 무슨 일이 먼저 일어나야 할까요?" |
| 근거 자료 | 선택 | 사용자가 링크를 붙이면 수집 |
| 반증 조건 | 권장 | "이 판단이 틀렸다는 건 뭘로 알 수 있을까요?" |

**판단 시점, 결과 지표, 근거 항목 셋에 대해서만 AI가 끈질기다.** 앞의 둘이 없으면 판정이
불가능하고, 근거 항목이 없으면 나중에 회고할 대상이 없어진다. 다만 강요하지는 않고,
막연하면 범위("올해 안", "다음 실적 발표쯤")로라도 받아낸다.

#### 결과 지표를 끌어내는 대화

"유동성이 풀린다" 같은 가설은 '풀린다'의 기준이 없어서 나중에 맞았는지 틀렸는지 판정할 수
없다. 판정할 수 없으면 복기도 없고, 복기가 없으면 이 앱은 일기장이 된다.
그래서 **숫자로 확인 가능한 조건**을 대화에서 반드시 받아낸다.

사용자에게 "지표를 설정하세요"라고 요구하지 않는다. 사용자는 관측 대상을 말할 뿐이고,
**그것을 실제 데이터 계열로 번역하는 일은 AI가 한다.**

```
  AI  유동성이 풀린다고 보시는 거군요.
      그게 실제로 일어나고 있다는 걸 무엇을 보면 알 수 있을까요?

                              음... 금리가 내려가는 거?

  AI  미국 기준금리로 보면 되겠네요. 지금 4.25%인데,
      어느 정도까지 내려오면 "풀렸다"고 보시겠어요?

                              3.5% 아래로는 가야지

  AI  한 번이라도 3.5%를 밑돌면 되나요,
      아니면 그 아래에서 얼마간 유지돼야 하나요?

                              한 번 내리면 잘 안 올리니까 한 번이면 돼

  AI  정리했습니다.
      ┌────────────────────────────────────────┐
      │ 미국 기준금리 (FRED)                    │
      │ 3.5% 이하 · 1회라도 · 2026.12.31까지    │
      └────────────────────────────────────────┘

```

AI가 결과 지표 대화에서 확보할 것:

| 항목 | 질문 방식 |
|---|---|
| 관측 대상 | "무엇을 보면 알 수 있을까요?" → AI가 실제 계열로 변환해 제안 |
| 목표값 | "어느 정도까지 가면 그렇다고 보시겠어요?" |
| 관측 규칙 | "한 번이라도 닿으면 되나요, 며칠 이어져야 하나요?" |

- **관측 규칙을 반드시 받는다.** 이게 없으면 "코스피 3000 돌파"가 장중 1초 터치로 달성된
  것인지 아닌지를 나중에 사용자 본인과 다투게 된다.
- 지표가 여러 개일 때 **전부 달성(AND)을 기본값으로 하되 강요하지 않는다.**
  "이 중 하나만 되어도 맞다고 보시나요?"를 물어 OR / N개 중 M개도 선택할 수 있게 한다.
  AND만 있으면 거의 모든 가설이 실패로 끝나고, 사용자는 지표 설정 자체를 회피하게 된다.
- 결과 자체가 숫자가 아닌 것(규제 승인, M&A 성사)은 **예/아니오 지표**로 받는다.
  자동 수집은 안 되고 사용자가 직접 표시하지만, 판정 시점을 명확히 하는 효과는 같다.

#### 근거 항목을 끌어내는 대화 — 여기서는 숫자를 묻지 않는다

결과 지표만 있으면 "예상한 일이 일어났는가"는 알 수 있지만 **"그게 내 논리 때문이었는가"는
알 수 없다.** 주가가 올랐어도 시장 전체가 올라서일 수 있다. 그래서 내 논리의 중간 고리를
따로 받아둔다.

정말 중요한 중간 고리들(DRAM 현물가, HBM 매출 비중 같은 것)은 유료 산업 데이터라 API로
가져올 수 없다. **그래서 여기서는 수치화를 시도하지 않는다.** 사용자가 말로 설명한 그대로
받아두고, 나중에 회고할 때 AI가 자료를 조사한다.

```
  AI  마지막으로 하나만요.
      말씀하신 대로 되려면, 그 전에 무슨 일이 먼저 일어나야 할까요?

                    HBM 공급 부족이 계속돼야 하고
                    삼성이 엔비디아 퀄 테스트를 통과해야지

  AI  적어두겠습니다. 나중에 결과가 나오면 이 두 가지가
      실제로 일어났는지 제가 찾아서 정리해 드릴게요.

      ┌────────────────────────────────────────┐
      │ 이 판단이 성립하려면          [사용자]  │
      │ 1. HBM 공급 부족이 2026년 내내 지속     │
      │ 2. 삼성전자가 엔비디아 퀄 테스트 통과   │
      └────────────────────────────────────────┘
```

- **수치나 데이터 출처를 되묻지 않는다.** "그건 어디서 확인하나요?"라고 물으면 사용자는
  막히고 대화가 늘어진다. 자동 추적이 목적이 아니라 검증할 대상을 남기는 것이 목적이다.
- 근거 항목은 사용자의 말이므로 `[사용자]` 저작으로 표기한다.
- 근거 항목 중 마침 FRED·ECOS로 추적 가능한 것(금리, 환율, 수출 증가율 등)이 있으면
  AI가 조용히 지표로도 등록한다. 사용자에게 되묻지 않는다.
- AI는 "나중에 제가 찾아서 정리해 드리겠다"고 **약속을 명시한다.** 지금 답을 못 주는
  질문을 던지는 이유를 사용자가 이해해야 성의 있게 답한다.

#### 대화 종료 → 노트 생성

- 사용자가 `여기까지 정리하기`를 누르거나, AI가 필수 항목을 다 확보하면 제안한다.
- AI가 노트 초안을 생성 → **미리보기 화면**에서 사용자가 확인.
  - 각 섹션마다 `수정` 가능. 직접 수정한 블록은 `[사용자]`로 표기된다. (§8)
  - "이건 내가 말한 뜻과 다른데" → 그 자리에서 대화로 되돌아가 보정 가능.
- 저장 시 **원본 대화 전문이 노트에 영구 첨부**된다. (P2)

#### 이탈과 재개

- 대화 중 이탈해도 임시 저장(draft)되며, 홈 상단에 조용히 재개 링크가 뜬다.
- 필수 항목이 덜 찬 상태로도 저장 가능. 단 이 노트는 **미완성 상태**가 되어
  리마인드 대상에서 제외되고, 노트 상세 상단에 "판단 시점을 정하면 리마인드가 시작됩니다"
  라는 안내가 붙는다. (차단이 아니라 안내 — P5)

### 3.3 노트 상세 — 좌우 분리 구조

**이 화면의 레이아웃 자체가 P4(내 사고 ↔ 외부 정보 분리)의 구현체다.**
왼쪽은 나의 사고, 오른쪽은 세상이 가져온 정보. 이 경계는 시각적으로 명확해야 한다.

```
┌──────────────────────────────────────────────────────────────────────┐
│  ← 노트                          삼성전자                    [⋯]     │

#### 구성 요소

**좌측 — 나의 관점 (변화가 느리고, 내가 소유하는 영역)**
- 핵심 가설: AI가 작성한 요약. 사용자 원문 인용은 `[사용자]`로 구분 표시.
- 시나리오 카드: 확률 막대 + 판단 시점 + **지표 달성 현황** + 상태. `다시 판단하기` 버튼 포함.
  - 지표 현황은 `3개 중 2개 달성`처럼 요약하고, 카드를 펼치면 지표별 목표값·현재값·달성일이
    보인다. 부분 달성은 그 자체로 강한 신호이므로 판정 전에도 계속 노출한다.
  - 노트 상세에는 `이 판단이 성립하려면` 섹션으로 근거 항목이 함께 보인다. 자동 추적되지
    않으므로 체크 표시가 붙지 않고, 결과 확정 후 회고록에서 조사 결과가 채워진다.
- `그 외 예상 못한 전개` 항목 (§6 참조)
- 접히는 섹션: 내가 붙인 자료 / 원본 대화 기록 / 생각이 바뀐 기록

**우측 — 새로 들어온 정보 (변화가 빠르고, 외부에서 오는 영역)**
- 시간 역순 피드. 각 항목은 요약 1~2줄 + 관계 태그 + 원문 링크.
- 관계 표시: `↗ 뒷받침함` / `↘ 어긋남` / `— 관련 있음` — 어느 시나리오에 대한 것인지 함께 적는다.
- `반영` 버튼: 이 정보를 근거로 시나리오를 다시 판단하는 화면으로 이동.
- `지금 다시 조사하기`: 온디맨드 리서치 실행. (MVP의 주 실행 경로)

#### 반응형

좌우 분리는 가로 폭이 있을 때만 가능한 표현이다. 모바일에서는 **세로로 이어 붙이지 않고
탭으로 전환**한다. 근거와 상세는 [§10.3 노트 상세](#노트-상세--분리를-어떻게-유지할-것인가) 참조.

홈의 리마인드 카드를 열면 도달한다. **3단 구성이 고정**이며 순서가 중요하다.

#### 규칙

- **①은 항상 원본 그대로다.** AI가 재요약하거나 현재 시점 정보로 각색하지 않는다. (P2)
  당시 확률 수치까지 그대로 보여준다 — 지금과의 차이가 스스로 드러나야 한다.
- `당시 대화 전문 보기`로 언제나 원본 대화까지 내려갈 수 있다.
- **②는 ①을 읽은 다음에 온다.** 순서가 바뀌면 최신 뉴스의 프레임으로 과거를 읽게 되고,
  그것이 바로 이 앱이 막으려는 문제다.
- **③에서 AI는 소신 있게 의견을 낸다.** 확률 조정, 매수/매도 판단, 타이밍 견해 모두
  제약 없이 제시한다. 면책은 UI 하단 고지가 담당한다.
- `나중에`는 아무 기록도 남기지 않는다. 미룬 횟수를 세지 않는다. (P5)

│    시나리오 2 · 다음 판단 시점 3주 후 · 새 정보 1건          │
│  ──────────────────────────────────────────────────────    │
│  ● 엔비디아                              마지막 검토 8주 전 │
│    ...                                                     │
│  ──────────────────────────────────────────────────────    │
│  ▸ 종료된 노트 (2)                                          │
└────────────────────────────────────────────────────────────┘
```

- 정렬 기본값: **다음 판단 시점이 가까운 순.** (최근 수정순이 아니다 — P1)
- 모든 시나리오의 결과가 정해진 노트는 `종료된 노트`로 접혀 내려간다. 삭제하지 않는다
  (회고 자산이므로).
- 노트 삭제는 `⋯` 메뉴 안쪽에만 둔다. 기록 소실은 이 앱에서 가장 큰 손실이다.

## 4. 시나리오의 상태 변화

시나리오가 어떤 상태를 거치는지는 이 앱의 핵심 로직이다.
**앱이 알아서 "틀렸다"고 정리해버리는 경우는 없다. 결론은 항상 사용자가 낸다.**

```
                      ┌────────────┐
     노트 생성  ─────▶ │  지켜보는 중 │
                      └─────┬──────┘
                            │  판단 시점이 됨
                            ▼
                    ┌───────────────┐
                    │ 결과 확인 필요  │  ← 리마인드가 뜬다
                    └──┬────┬────┬──┘     (앱이 결론 내지 않음)
          사용자가 선택 │    │    │
          ┌────────────┘    │    └────────────┐
          ▼                 ▼                 ▼
    ┌───────────┐    ┌───────────┐    ┌──────────────┐
    │ 그대로 됨  │    │  틀렸음   │    │  시점을 다시  │
    │           │    │           │    │ → 지켜보는 중 │
    └───────────┘    └───────────┘    └──────────────┘
```

### 상태 정의

화면에 나가는 말과 개발상의 이름을 분리한다. (P8)

| 화면 표기 | 내부 식별자 | 의미 | 진입 조건 |
|---|---|---|---|
| 지켜보는 중 | `active` | 아직 판단 시점이 오지 않음 | 생성 시 기본값 / 시점을 다시 정했을 때 |
| 결과 확인 필요 | `pending_judgment` | 시점이 지났거나 지표가 모두 달성되어 사용자 확인을 기다림 | 판단 시점 경과, 또는 지표 달성 조건 충족 (시스템 자동) |
| 그대로 됨 | `confirmed` | 시나리오대로 전개됨 | 사용자가 선택 |
| 틀렸음 | `rejected` | 시나리오가 틀렸음 | 사용자가 선택 |

### 결과를 정하는 화면 — 지표 현황을 먼저 보여준다

판정 전에 **그때 지표가 실제로 어땠는지**를 먼저 보여준다. 기억이 아니라 기록으로
판단하게 하는 것이 이 앱의 목적이다.

```
┌──────────────────────────────────────────────────────┐
│  판단 시점이 지났습니다 · 2026.12.31                   │
│  "HBM 수주 확대 성공"                                  │
│                                                      │
│  결과 지표                                            │
│   ✓ 삼성전자 95,000원 이상       달성  11.18  97,400  │
│   ✗ 코스피 3,200 이상            미달성        3,050  │
│                                  목표까지 95% 도달     │
│                                                      │
│  2개 중 1개 달성 · 전부 달성 조건                       │
│  ────────────────────────────────────────────────    │
│  ⚠ 목표값을 3,400 → 3,200으로 낮춘 적 있음 (09.14)     │
│                                                      │
│  예상하신 일이 일어났나요?                              │
│  [ 그대로 되었다 ]  [ 틀렸다 ]                          │
│  [ 방향은 맞지만 시기를 다시 본다 ]                      │
│                                                      │
│  * 이 판단이 정말 내 논리 때문이었는지는                  │
│    다음 단계에서 자료를 찾아 함께 봅니다.                 │
└──────────────────────────────────────────────────────┘
```

**이 화면은 "예상한 일이 일어났는가"만 묻는다.** "그게 내 논리 때문이었는가"는 자료를
조사해봐야 알 수 있어서 이 자리에서 물으면 사용자가 답할 수 없다. 그 질문은 다음 단계인
회고록(§5)이 담당한다. 두 질문을 한 화면에 섞으면 둘 다 대충 답하게 된다.

**앱은 판정하지 않는다.** 지표가 전부 달성되어도 "적중"으로 확정하지 않고 사용자에게 묻는다.

- 세 번째를 고르면 새 판단 시점을 입력받고 `지켜보는 중`으로 돌아간다.
  지표가 목표에 근접해 있으면(위 예시의 95%) 이 선택지가 시각적으로 먼저 눈에 띄게 한다.
  **시점을 다시 잡은 기록은 남는다** — 벌점이 아니라, 나중에 되돌아볼 때
  "나는 늘 너무 빠르게 예상한다"는 버릇을 발견하기 위한 자료다.
  이 기록은 노트 안쪽 이력에서만 보이고, 카드나 홈에는 드러내지 않는다. (P5)
- 어느 것을 고르든 **이유를 한 줄 남기도록 권한다** (선택 사항).
- 지표를 도중에 수정한 적이 있으면 이 화면에 반드시 표시한다.
  숨기면 복기가 자기기만이 된다.
- `그대로 되었다` 또는 `틀렸다`를 고르면 **회고록으로 이어진다.**

## 5. 회고록 — 제대로 맞췄는가, 소 뒷걸음질인가

결과가 확정되면 열리는 화면이다. **이 앱의 최종 산출물이자 존재 이유다.**
앞의 모든 기능 — 원본 대화 보존, 근거 항목 기록, 지표 추적, 리마인드 — 은 전부
이 한 화면을 위한 준비다.

```
┌────────────────────────────────────────────────────────────┐
│  ← 노트                        삼성전자 · 회고               │
│                        2026.03.02 기록 → 2026.12.31 확정     │
├────────────────────────────────────────────────────────────┤
│                                                            │
│  ①  당시 당신의 논리                            [사용자]    │
│  ┌──────────────────────────────────────────────────┐     │
│  │ HBM 공급 부족 지속                                │     │
│  │        ↓                                         │     │
│  │ 삼성전자가 후발주자로 점유율 확보                   │     │
│  │        ↓                                         │     │
│  │ 주가 상승                                         │     │
│  └──────────────────────────────────────────────────┘     │
│                                    ▸ 당시 대화 전문 보기    │
│                                                            │
│  ②  실제로는 이랬습니다                                     │
│  ┌──────────────────────────────────────────────────┐     │
│  │ ✗ HBM 공급 부족 지속        일어나지 않음          │     │
│  │   SK하이닉스 HBM4 양산이 앞당겨지며 하반기부터     │     │
│  │   공급이 풀렸습니다.                    [출처 2건] │     │
│  │                                                  │     │
│  │ ? 삼성전자 점유율 확보      확인 불가              │     │
│  │   점유율을 공개한 자료를 찾지 못했습니다.          │     │
│  │                                                  │     │
│  │ ✓ 주가 95,000원 이상        달성 (11.18)          │     │
│  └──────────────────────────────────────────────────┘     │
│                                                            │
│  ┌──────────────────────────────────────────────────┐     │
│  │ 같은 기간 비교                                    │     │
│  │   삼성전자      +15%  ▓▓▓▓▓▓▓▓░░░░               │     │
│  │   반도체 업종   +21%  ▓▓▓▓▓▓▓▓▓▓▓░               │     │
│  │   코스피        +18%  ▓▓▓▓▓▓▓▓▓▓░░               │     │
│  └──────────────────────────────────────────────────┘     │
│                                                            │
│  ③  그래서, 제대로 맞춘 건가요?                             │
│  ┌──────────────────────────────────────────────────┐     │
│  │  [ 논리대로 맞았다 ]      [ 결과만 맞았다 ]        │     │
│  │  [ 논리는 맞았는데        [ 둘 다 틀렸다 ]        │     │
│  │    결과가 안 나왔다 ]                             │     │
│  │                                                  │     │
│  │  무엇을 놓쳤고, 다음엔 무엇을 다르게 보시겠어요?    │     │
│  │  ┌────────────────────────────────────────────┐  │     │
│  │  │                                            │  │     │
│  │  └────────────────────────────────────────────┘  │     │
│  │                              [ 나중에 ] [ 저장 ] │     │
│  └──────────────────────────────────────────────────┘     │
└────────────────────────────────────────────────────────────┘
```

### 핵심: 결과 축과 논리 축은 별개다

|  | 논리가 맞았다 | 논리가 틀렸다 |
|---|---|---|
| **결과가 맞았다** | 논리대로 맞았다 | **결과만 맞았다** — 가장 위험한 성공 |
| **결과가 틀렸다** | 논리는 맞았는데 결과가 안 나왔다 | 둘 다 틀렸다 |

오른쪽 위 칸을 잡아내는 것이 이 화면의 목적이다. 다른 앱은 이걸 그냥 "적중"으로 기록한다.
틀린 논리로 운 좋게 번 것을 실력으로 착각하면, 다음에 같은 논리로 더 큰 돈을 넣는다.

왼쪽 아래 칸도 중요하다. 논리가 옳았는데 시기를 잘못 봤다면 그 논리는 버릴 게 아니라
다시 쓸 자산이다.

### 화면 규칙

- **②는 AI가 미리 채워둔다.** 빈 화면에 "회고를 쓰세요"라고 두면 아무도 쓰지 않는다.
  사용자는 이미 정리된 사실 위에 판단만 얹으면 된다.
- **AI는 "이건 운이었습니다"라고 말하지 않는다.** 사실과 대비만 제시한다. 위 예시에서
  삼성전자(+15%)가 업종(+21%)을 밑돈 것은 강한 신호지만, 결론은 사용자가 내린다.
  AI가 논리의 옳고 그름을 선언하면 사용자는 스스로 생각하지 않게 되고, 그러면 이 앱은
  판단력을 기르는 도구가 아니라 대신 판단해주는 도구가 된다.
- **`확인 불가`를 숨기지 않는다.** 자료를 못 찾았으면 못 찾았다고 표시한다.
  ②에서 `확인 불가`가 대부분이면 회고의 가치가 떨어지지만, 그 사실 자체도 정보다
  ("내 논리는 애초에 확인할 방법이 없는 것이었다").
- **벤치마크 비교는 언제나 제공한다.** 근거 항목 조사가 전부 실패해도 이것만은 계산된다.
  "그냥 시장이 올라서"를 거르는 가장 확실한 장치이자, 무료 API로 가능한 유일한 자동 검증이다.
- ①은 원본 그대로다. AI가 각색하지 않는다. (P2)
- 사용자 서술은 `[사용자]` 저작으로 표기된다. (P3)

### 강요하지 않는다

- `나중에`를 누르면 조용히 닫힌다. **안 쓴 회고록의 개수를 세지 않고, 배지도 띄우지 않는다.** (P5)
- AI 초안과 지표 기록은 그대로 남으므로 언제든 다시 열어 쓸 수 있다.
- 대신 **같은 대상으로 새 노트를 만들 때 조용히 꺼내 보여준다.**
  ```
  이 종목으로 지난번에 이렇게 판단하셨습니다.
  "HBM 공급 부족 지속" → 실제로는 일어나지 않았습니다.
                                          [ 그때 회고 보기 ]
  ```
  회고록이 가장 필요한 순간은 같은 실수를 반복하려는 바로 그때다.
  이건 압박이 아니라 메멘토 원칙 그 자체다 — 과거의 내가 지금의 나를 찾아오는 것.

## 6. 확률 입력 UX

### 한 노트의 확률은 모두 합쳐서 100%

한 노트 안의 시나리오들은 **동시에 일어날 수 없는 경우들로 본다.** 확률 합은 항상 100%이고,
하나를 올리면 나머지가 자동으로 줄어든다.

이유: 각각 따로 확률을 매기면 "A도 70%, B도 60%" 같은 앞뒤가 안 맞는 입력이 나온다.
무엇보다 **무언가를 포기하는 감각이 사라진다.** 하나를 올리려면 다른 것을 내려야 한다는
제약이 있어야 생각이 정직해진다.

화면에서는 이 규칙을 설명하지 않는다. 슬라이더를 움직이면 다른 값이 따라 움직이는 것을
보고 사용자가 스스로 알아차린다.

### `그 외 예상 못한 전개`

모든 노트에 **자동으로 만들어지고 지울 수 없는** 시나리오를 하나 둔다.

```
  그 외 예상 못한 전개                    10%
  ▓▓░░░░░░░░░░░░░░░░░░
```

- 사용자가 적은 시나리오들의 합이 100%에 못 미치면 남는 몫이 여기로 간다.
- 최소 5%는 반드시 남긴다 — **"내가 생각한 경우가 전부다"라는 착각을 구조적으로 막는다.**
- 실제로 예상 못한 일이 벌어지면, 사용자는 이를 계기로 새 시나리오를 추가하거나
  노트를 다시 쓴다.

### 입력 방식

- 확률은 5% 단위로만 조정된다. (1% 단위는 정밀해 보이지만 실제로는 근거 없는 숫자다)
- **데스크톱은 드래그 슬라이더, 모바일은 `[−] 65% [+]` 버튼**을 쓴다.
  좁은 화면에서는 5% 한 칸이 17px밖에 안 돼 손가락으로 집기 어렵고, 가로로 끄는 동작이
  세로 스크롤과 부딪힌다. ([§10.4](#104-터치-입력-고려) 참조)
- 하나를 조정하면 나머지가 비율에 맞춰 자동으로 조정된다. 건드리고 싶지 않은 시나리오는
  `고정`해둘 수 있다.
- 조정할 때 **바꾼 이유를 한 줄 남기도록 권한다** (선택 사항, 하지만 강하게 권장).
  나중에 돌아볼 때 "왜 그때 생각을 바꿨는지"가 숫자보다 훨씬 중요하다.

## 7. 리마인드가 뜨는 조건과 순서

### 리마인드가 뜨는 경우

| 경우 | 조건 | 기본 설정 |
|---|---|---|
| 결과 확인 필요 | 시나리오 판단 시점이 지남 | 즉시, 이후 주 1회 |
| 시점 임박 | 판단 시점 7일 전 | 1회 |
| 지표 달성 | 시나리오의 지표 달성 조건이 충족됨 | 즉시 (하루 1회로 묶어서) |
| 새 정보 | AI가 찾은 정보의 관련도가 기준을 넘음 | 즉시 (하루 1회로 묶어서) |
| 정기 리마인드 | 마지막으로 본 지 N주 경과 | 기본 4주 |

### 자주 안 열면 알아서 뜸해진다

같은 노트의 리마인드가 **연속 3번 열리지 않으면 주기를 2배로 늘린다.**
그 뒤로도 계속 열리지 않으면 다시 2배(최대 12주까지).
사용자가 한 번이라도 열면 원래 주기로 즉시 돌아온다.

이는 벌이 아니라 **실제 관심 수준에 앱이 맞춰가는 것**이다. 이 동작은 사용자에게
드러내지 않는다 — "안 보셔서 빈도를 줄였습니다" 같은 안내는 P5 위반이다.

### 하루에 보내는 양

- 홈 화면 기본 노출: 3장

## 8. 화면에 쓰는 말

### 8.1 누가 쓴 글인지 구분하기

노트 내용은 대부분 AI가 쓰므로 **AI가 쓴 글에는 아무 표시도 하지 않고**,
사용자가 쓴 부분에만 `[사용자]`를 붙인다. (P3)

#### `[사용자]`가 붙는 것

| 대상 | 표기 |
|---|---|
| 대화 중 사용자가 한 말이 노트에 그대로 인용된 문장 | `[사용자]` + 왼쪽 선 강조 |
| 사용자가 직접 고쳐 쓴 부분 | `[사용자]` |
| 사용자가 직접 붙인 링크/파일/메모 | 섹션 제목에 `[사용자]` |
| 확률을 바꾼 이유 | `[사용자]` |
| 시나리오 결과를 정한 이유 | `[사용자]` |

#### 붙이지 않는 것

- AI가 쓴 가설 요약, 시나리오 설명, 정보 요약, 조언 — 전부 표시 없음.
- 단, **AI의 주관적 의견(매수/매도 의견, 확률 조정 제안)은 따로 묶어
  "AI의 견해"라는 제목을 붙인다.** 이건 누가 썼는지의 문제가 아니라 사실과 의견의 구분이다.

### 8.2 원본 대화 보기

모든 노트에서 `원본 대화 기록`을 열어 대화 전체를 볼 수 있다.
이 기록은 **읽기만 가능하며 고치거나 지울 수 없다.** (P2)

### 8.3 문구 작성 규칙

P8을 실제 문구로 옮기면 다음과 같다.

- **상태가 아니라 할 일을 말한다.** `결과 확인 필요`(○) / `판정 대기`(✗)
- **명사보다 동사.** `지금 다시 조사하기`(○) / `리서치 실행`(✗)
- **앱이 아니라 사용자를 주어로.** `이 시나리오는 어떻게 되었나요?`(○) /
  `시나리오 상태를 갱신하세요`(✗)
- **숫자와 기간은 그대로.** `5일 남음`(○) / `D-5`(✗)
- **영어 약어를 쓰지 않는다.** 다만 종목명·기술명(HBM, FSD 등 사용자가 이미 쓰는 말)은 예외다.
- **평가하는 말을 쓰지 않는다.** `한동안 보지 않으셨습니다`(○) /
  `3주째 방치 중`(✗) — P5와 직결된다.

### 8.4 개발 이름 ↔ 화면 표기 대응표

코드에서 쓰는 식별자를 그대로 번역해 화면에 올리지 않기 위한 대응표다. (P8)
설계 문서 안에서도 화면 표기 쪽을 우선해서 쓴다.

| 개발상의 이름 | 화면 표기 |
|---|---|
| `active` | 지켜보는 중 |
| `pending_judgment` | 결과 확인 필요 |
| `confirmed` | 그대로 됨 |
| `rejected` | 틀렸음 |
| `timeframe_reset` | 시점을 다시 봄 |
| `residual_scenario` | 그 외 예상 못한 전개 |
| `research_item` | 새 정보 |
| `supports` / `contradicts` / `neutral` | 뒷받침함 / 어긋남 / 관련 있음 |
| `relevance_score` | (화면에 표시하지 않음) |
| `advisor_opinion` | AI의 견해 |
| `conversation` | 원본 대화 기록 |
| `probability_history` | 생각이 바뀐 기록 |
| `indicator` | 판단 지표 |
| `leading` / `outcome` | 근거 지표 / 결과 지표 |
| `not_met` / `met` | 아직 / 달성 |
| `observation_rule` | 언제 달성으로 볼지 |
| `indicator_snapshot` | (화면에 표시하지 않음) |
| `premise` | 이 판단이 성립하려면 |
| `happened` / `did_not_happen` / `unverifiable` | 일어남 / 일어나지 않음 / 확인 불가 |
| `review` | 회고 |
| `logic_held` | 논리대로 맞았다 |
| `outcome_only` | 결과만 맞았다 |
| `logic_only` | 논리는 맞았는데 결과가 안 나왔다 |
| `both_wrong` | 둘 다 틀렸다 |
| `benchmark_comparison` | 같은 기간 비교 |

## 10. 화면 비율에 따른 설계

### 10.0 출발점: 세로는 같고, 가로만 다르다

반응형을 "좁아지니까 줄인다"로 접근하면 데스크톱 레이아웃을 그냥 세로로 무너뜨리게 되고,
그 결과 두 화면 모두에서 어색한 물건이 나온다. 실제 수치를 보면 문제의 성격이 다르다.

| | 콘텐츠 영역(대략) | 가로:세로 |
|---|---|---|
| 데스크톱 | 1440 × 750 | 약 **1.9 : 1** (가로로 누움) |
| 모바일 | 390 × 750 | 약 **0.5 : 1** (세로로 섬) |

**세로 예산은 사실상 같고, 가로만 약 3.7배 차이가 난다.**
따라서 설계 문제는 "모바일에서 무엇을 뺄까"가 아니라 다음 두 가지다.

1. 데스크톱의 **남는 가로 폭으로 무엇을 할 것인가**
2. 그 폭이 사라졌을 때 거기 있던 것을 **어디로 옮길 것인가** (세로로 미루면 안 된다)

### 10.1 가로와 세로가 하는 일이 다르다

이 앱에서 두 축은 서로 다른 의미를 담당한다. 이 원칙이 모든 변환의 기준이 된다.

> **가로축 = 비교와 시간. 세로축 = 순서와 흐름.**

- **비교해야 하는 것**(과거의 나 ↔ 지금의 정보, 시나리오 A ↔ B)은 가로로 나란히 둘 때
  가장 잘 읽힌다. 시선이 두 대상을 왕복할 수 있기 때문이다.
- **순서가 있는 것**(①→②→③, 우선순위 목록)은 세로로 쌓을 때 가장 잘 읽힌다.
- 모바일에는 가로축이 없다. 따라서 **비교를 세로 스택으로 대체하면 안 된다** — 세로 스택은
  "다음 내용"을 의미하지 "대비되는 것"을 의미하지 않는다.
  대신 **탭으로 전환하거나, 스크롤에 따라 차례로 보여주어** 비교의 의미를 살린다.

### 10.2 데스크톱: 가로 폭은 세로를 줄이는 데 쓴다

넓은 화면이 생겼을 때 흔한 실수는 **열을 늘리는 것**이다. 하지만 홈 피드처럼
**우선순위가 있는 목록은 세로로 유지되어야** 한다(9.1). 3열 그리드로 만들면 1순위와
3순위가 같은 높이에 놓여 우선순위가 사라진다.

> 넓은 화면에서는 **열을 늘리지 말고, 각 항목을 가로로 눕혀 높이를 줄인다.**

데스크톱 뷰포트는 세로로 짧으므로(750px), 항목 하나가 140px면 3개에 420px + 타임라인
200px = 스크롤이 발생한다. 같은 카드를 가로로 눕혀 90px로 만들면 270px + 200px = 470px로
**모든 것이 첫 화면 안에 들어온다.** 이것이 넓은 화면의 진짜 이득이다.

```
데스크톱 — 카드를 눕혀 높이를 줄임 (90px)
┌──────────────────────────────────────────────────────────────┐
│ 📅 │ 판단 시점이 다가옵니다 · 5일 남음                        │
│    │ 삼성전자 "HBM 수주 확대" — 6주 전 확률 60%   [열어보기]  │
└──────────────────────────────────────────────────────────────┘

모바일 — 세로로 자연스럽게 흐름 (140px, 세로는 저렴하므로 허용)
┌────────────────────────┐
│ 📅 판단 시점이 다가옵니다│
│    5일 남음             │
│ 삼성전자                │
│ "HBM 수주 확대"         │
│ 6주 전 확률 60%         │
│           [ 열어보기 ]  │
└────────────────────────┘
```

### 10.3 화면별 대응

#### 홈 타임라인 — 축을 90° 회전한다

시간축을 없애거나 목록으로 격하시키지 않는다. **축의 방향만 바꾼다.**

```
데스크톱 (가로축 = 시간, 좌 → 우)
┌──────────┬──────────┬──────────┬──────────┬──────────┐
│  이번 주  │  ~1개월  │  ~3개월  │  ~6개월  │ 그 이후  │
│  ● 삼성전자│ ● 테슬라 │ ▬▬▬ 금리 │ ● 엔비디아│ ● 부동산 │
│          │ ● 삼성전자│          │          │          │
└──────────┴──────────┴──────────┴──────────┴──────────┘

모바일 (세로축 = 시간, 위 → 아래)
┌────────────────────────┐
│ 다가오는 판단 시점       │
│                        │
│ 이번 주 ─────────────  │
│  │  ● 삼성전자          │
│  │    HBM 수주          │
│  │                     │
│ ~1개월 ──────────────  │
│  │  ● 테슬라 FSD 인가   │
│  │  ● 삼성전자 메모리가격│
│  │                     │
│ ~3개월 ──────────────  │
│  │  ▬ 금리 인하 (기간형)│
│  ▼                     │
└────────────────────────┘
```

- 세로축은 오히려 **긴 화면에 더 잘 맞는다.** 위에서 아래로 흐르는 시간은 읽기 방향과
  일치하고, 세로 공간은 모바일에서 저렴하다.
- 가까운 시점을 넓게 보여주는 규칙은 가로·세로 양쪽에 똑같이 적용된다.
- 기간형 시나리오(`▬`)는 데스크톱에서 가로 막대, 모바일에서 세로 막대가 된다.

#### 홈 전체 구성 — 모바일에서는 피드가 주인공

데스크톱에서는 타임라인(200px) + 피드(270px)가 한 화면에 공존한다.
모바일에서는 둘 다 세로를 요구해 서로 경쟁하고, 그대로 쌓으면 화면 3개 길이가 된다.

**모바일 홈은 피드를 기본으로 하고, 타임라인은 세그먼트 전환으로 분리한다.**

```
┌────────────────────────┐
│  Investment Memento 👤 │
├────────────────────────┤
│ ┌────────┬───────────┐ │
│ │다시 볼 시점│ 타임라인 │ │  ← 세그먼트 (기본: 다시 볼 시점)
│ └────────┴───────────┘ │
├────────────────────────┤
│  다음 판단 시점          │
│  삼성전자 HBM · 5일 후 → │  ← 타임라인 요약 한 줄
├────────────────────────┤
│  ┌──────────────────┐  │
│  │ 📅 판단 시점 임박  │  │
│  │ ...              │  │
│  └──────────────────┘  │
│  ┌──────────────────┐  │
│  │ 📰 새 소식 3건     │  │
│  └──────────────────┘  │
└────────────────────────┘
```

근거: 모바일 진입은 대개 **알림을 받고 들어오는 경우**다. 이때 사용자가 원하는 것은
"지금 봐야 할 것"이지 전체 조망이 아니다. 조망은 데스크톱에서 앉아 볼 때의 행위다.
타임라인이 완전히 사라지지 않도록 **다음 판단 시점 한 줄 요약**은 상시 노출한다. (P1)

#### 노트 상세 — 분리를 어떻게 유지할 것인가

가장 중요한 변환이다. P4(내 사고 ↔ 외부 정보 분리)는 데스크톱에서 좌우 배치로 표현되는데,
모바일에는 좌우가 없다.

**세로 스택은 정답이 아니다.** 세로로 이어 붙이면 두 영역이 "하나의 연속된 문서"로 읽혀
분리의 의미가 사라지고, 오히려 P4가 막으려던 혼입이 발생한다. 게다가 새 정보가 화면
두 개 아래로 밀려나 사실상 보이지 않게 된다.

> **분리는 "다른 공간"으로 표현되어야 한다. 데스크톱에서는 좌우, 모바일에서는 탭이다.**

```
┌────────────────────────┐
│ ← 삼성전자              │
│   마지막 검토 6주 전     │
├────────────────────────┤
│ ┌─────────┬──────────┐ │
│ │나의 관점 │새 정보 (3)│ │ ← 탭. 기본값은 항상 "나의 관점"
│ └─────────┴──────────┘ │
├────────────────────────┤
│ 핵심 가설                │
│ HBM 공급 부족이 2026년   │
│ 까지 이어지며...         │
│                        │
│ [사용자] "결국 공급이    │
│  못 따라가는 게 핵심"    │
│                        │
│ 시나리오                 │
│ ┌────────────────────┐ │
│ │ A. 수주 확대   65%  │ │
│ │ ▓▓▓▓▓▓▓▓▓▓░░░░    │ │
│ │ 📅 2026 Q4까지     │ │
│ │  [다시 판단하기]   │ │
│ └────────────────────┘ │
│ ...                    │
├────────────────────────┤
│ ⚠ 판단과 책임은 본인에게 │
└────────────────────────┘
```

- **기본 탭은 항상 `나의 관점`.** 새 정보를 먼저 보면 그 프레임으로 과거를 해석하게 되어
  이 앱의 목적 자체가 무너진다.
- 새 정보 탭에 미확인 항목이 있으면 개수만 표시한다(`새 정보 (3)`). 빨간 배지는 쓰지 않는다. (P5)
- 탭 전환은 상태를 유지한다 — 스크롤 위치가 초기화되면 왕복 비교가 불가능해진다.

#### 리마인드 상세 — 대비를 만드는 방식이 다르다

이 화면의 목적은 **과거의 나와 그동안의 일을 대비시키는 것**이다.
대비는 가로축의 일이므로(9.1), 데스크톱에서는 오히려 현재의 3단 세로 배치가 낭비다.

```
데스크톱 — ①과 ②를 나란히 두어 대비를 물리적으로 만든다
┌───────────────────────────────┬────────────────────────┐
│ ① 6주 전, 당신은 이렇게 생각    │ ② 그동안 이런 일이       │
│    했습니다                    │    있었습니다            │
│                               │                        │
│  HBM 공급 부족이 2026년까지    │  ↘ SK하이닉스 HBM4      │
│  이어지며...                   │    양산 일정 단축        │
│                               │                        │
│  [사용자] "누가 만들든 팔린다"  │  ↗ 엔비디아 공급사       │
│                               │    다변화 검토           │
│  A. 수주 확대 성공  60%        │                        │
│  B. 기술 격차 지속  30%        │  — 메모리 가격 반등      │
│         (폭 7)                │        (폭 5)          │
├───────────────────────────────┴────────────────────────┤
│ ③ 지금은 어떻게 보시나요?            (전체 폭)           │
│    AI의 견해 / 되짚어볼 질문                             │
│         [ 다시 판단하기 ]   [ 나중에 ]                   │
└─────────────────────────────────────────────────────────┘

모바일 — 스크롤에 따라 차례로 보여주며 대비를 만든다
  ① 과거의 나  →  (스크롤)  →  ② 그동안의 일  →  (스크롤)  →  ③ 지금은?
```

- **데스크톱**: ①과 ②가 한 시야에 들어와 차이가 즉각적으로 보인다.
  ①을 더 넓게(7:5) 두어 시선이 왼쪽에서 시작하도록 하고, 읽기 순서는 좌→우 배치로 보장한다.
- **모바일**: 가로가 없으므로 대비를 **시간차로 만든다.** ①을 먼저 읽고 스크롤해야
  ②가 나타나는 구조는 오히려 순서 강제가 확실하다는 장점이 있다.
- **③은 두 화면 모두 전체 폭**이다. 결론과 액션은 비교 대상이 아니라 귀결이므로 나누지 않는다.
- 트레이드오프: 데스크톱의 나란한 배치는 "①을 먼저 읽는다"는 순서 강제가 모바일보다 약하다.
  대비의 즉각성이라는 이득이 더 크다고 판단해 이 배치를 택하되, ①의 시각적 우위(폭·강조)로
  보완한다.

#### 노트 작성 대화 — 남는 폭에 노트를 실시간으로 짓는다

채팅 UI는 세로로 긴 화면에 이미 최적화된 형태다. 문제는 데스크톱이다.
1440px 화면 한가운데 700px짜리 대화창만 두면 양옆이 그냥 빈다.

**데스크톱의 남는 폭에는 "지금 만들어지고 있는 노트"를 실시간으로 보여준다.**

```
데스크톱
┌─────────────────────────────┬──────────────────────────┐
│  AI  요즘 어떤 투자 아이디어를 │  만들어지는 노트          │
│      생각하고 계신가요?       │                          │
│                             │  대상   삼성전자      ✓   │
│      삼성전자 HBM 때문에      │  가설   HBM 공급 부족...  │
│      관심 보는 중             │                          │
│                             │  시나리오                 │
│  AI  어떤 점 때문에 관심이     │   A 수주 확대 성공    ✓   │
│      가셨는지...              │     📅 2026 Q4          │
│                             │   B 기술 격차 지속        │
│                             │     📅 시점 미정  ⚠      │
│  [메시지 입력...    ] [전송]  │                          │
│                             │      [ 여기까지 정리하기 ] │
└─────────────────────────────┴──────────────────────────┘

모바일 — 정리된 내용은 접히는 상단 바로 축약
┌────────────────────────┐
│ ← 새 노트               │
│ ▾ 대상✓ 가설✓ 시나리오 2 │  ← 탭하면 펼쳐짐
│  판단 시점 1개 비었음 ⚠ │
├────────────────────────┤
│                        │
│  AI  요즘 어떤 투자      │
│      아이디어를...       │
│                        │
│       삼성전자 HBM 때문에│
│       관심 보는 중       │
│                        │
├────────────────────────┤
│ [메시지 입력...  ] [전송]│
└────────────────────────┘
```

- 데스크톱 오른쪽 패널은 단순한 진행률 표시가 아니라 **결과물의 미리보기**다.
  대화가 어떻게 구조로 번역되고 있는지 보이면 사용자가 부족한 부분을 스스로 채운다.
- 모바일에서는 이 패널이 들어갈 폭이 없다. 접히는 상단 바로 축약하되,
  **빠진 항목(특히 판단 시점)은 접힌 상태에서도 보이게** 한다.
- 입력창은 모바일에서 하단 고정(엄지 도달 범위), 키보드 노출 시 대화가 밀려 올라간다.

#### 노트 목록 — 행을 눕혀 전부 보이게

노트는 10개 내외 전제이므로(P7), 데스크톱에서는 **스크롤 없이 전부 보이는 것**이 목표다.

- **데스크톱**: 한 행에 `노트명 · 가설 요약 · 시나리오 수 · 다음 판단 시점 · 새 정보`를
  가로로 전부 배치. 행 높이 약 56px × 10개 = 560px로 한 화면에 들어온다.
- **모바일**: 한 항목이 카드가 되며 3줄로 접힌다(노트명+시점 / 가설 요약 / 시나리오·새 정보).
  높이 약 96px, 스크롤 발생하지만 세로는 저렴하므로 허용한다.

### 10.4 터치 입력 고려

가로 폭 축소는 레이아웃만이 아니라 **조작 방식**도 바꾼다.

**확률 슬라이더가 대표적인 문제다.** 5% 단위면 조절 칸이 20개인데, 모바일 폭 340px에서는
한 칸이 17px밖에 안 된다. 손가락으로 정확히 집기 어렵고, 가로로 끄는 동작이 페이지
세로 스크롤과 부딪힌다.

> **모바일에서는 슬라이더 대신 `−` / `+` 버튼을 쓴다.**

```
데스크톱          A. 수주 확대 성공                    65%
                 ●━━━━━━━━━━━━━━━━━━━━━━━━━━  (드래그)

모바일            A. 수주 확대 성공
                 ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░  (표시 전용)
                 [  −  ]    65%    [  +  ]   (5% 단위)
```

그 외 규칙:
- 손가락으로 누르는 영역은 최소 44×44px. 시나리오 카드의 `다시 판단하기`,
  새 정보의 `반영` 등이 해당.
- 주요 버튼(`열어보기`, `다시 판단하기`)은 화면 아래쪽 1/3 안에 둔다 — 엄지가 닿는 범위.
- hover에만 의존하는 정보를 두지 않는다. 데스크톱 타임라인의 마커 툴팁은 모바일에서
  탭으로 열리는 시트가 된다.
- 가로 드래그 제스처는 확률 조정 외에도 전면 회피한다. 세로 스크롤과 충돌한다.

### 10.5 브레이크포인트

| 구간 | 폭 | 레이아웃 |
|---|---|---|
| Wide | ≥ 1280px | 완전한 2단 구성. 노트 상세 좌우 분리, 리마인드 ①②나란히, 작성 시 노트 패널 |
| Medium | 768 ~ 1279px | 단일 열. 노트 상세는 탭, 리마인드는 세로 3단. 타임라인은 가로축 유지 |
| Narrow | < 768px | 모바일 규칙 전면 적용. 타임라인 세로축, `−`/`+` 버튼 입력, 하단 고정 입력창 |

Medium 구간은 **모바일 규칙을 따르되 타임라인만 가로축을 유지**한다.
768px면 5구간 가로축이 아직 읽히지만, 노트 상세의 좌우 분리는 각 열이 380px 이하로
좁아져 실용성이 없다.

### 10.6 금지 패턴

아래는 반응형 작업에서 흔히 나오지만 이 앱에서는 명시적으로 금지한다.

| 금지 | 이유 |
|---|---|
| 좌우 분리 영역을 세로 스택으로 변환 | 분리(P4)가 "연속된 문서"로 읽혀 의미가 소실됨 |
| 넓은 화면에서 우선순위 목록을 다열 그리드로 변환 | 우선순위가 사라짐 (9.1) |
| 모바일에서 타임라인을 단순 목록으로 격하 | 시간 조망이라는 고유 가치를 잃음. 축 회전으로 해결 |
| 새 정보 피드를 모바일 하단 접힘 섹션으로 밀기 | 사실상 미노출과 같음 |
| 데스크톱에서 세로 스크롤을 전제한 배치 | 뷰포트가 세로로 짧음(750px). 가로 폭으로 높이를 줄일 것 |
| 모바일에서 데스크톱과 다른 정보를 삭제 | 정보 삭제가 아니라 배치 변경으로 해결. 기록 접근성은 이 앱의 핵심 |

### 10.7 구현 순서

**작성은 데스크톱, 확인은 모바일**이라는 실사용 패턴을 전제로 한다.

1. 데스크톱 전체 (Wide) — 작성·조회의 주 환경
2. 모바일 리마인드 확인 흐름 (홈 → 리마인드 상세 → 다시 판단하기)
3. 모바일 전체 (작성 대화 포함)
4. Medium 구간 정리

## 11. 온보딩

첫 사용자는 노트가 없어 이 앱의 가치를 전혀 체감할 수 없다.
설명 대신 **첫 노트를 즉시 만들게 하는 것**이 유일한 온보딩이다.

1. 로그인
2. 한 화면짜리 컨셉 설명 (3문장 이내) — "과거의 당신을 잊지 않게 돕습니다"
3. 면책 고지 + 동의
4. **바로 대화 시작**: "요즘 어떤 투자 아이디어를 생각하고 계신가요?"
5. 첫 노트 저장 직후, 리마인드가 언제 올지 안내:
   > "4주 뒤, 그리고 A 시나리오의 판단 시점(2026 Q4)이 다가올 때
   >  이 노트를 다시 보여드리겠습니다."

이 마지막 안내가 앱의 핵심 약속이므로 반드시 노출한다.

## 12. MVP UX 범위

### 포함
- 홈: 타임라인 + 리마인드 피드 (기본 3장)
- 대화형 노트 작성 → AI 노트 생성 → 미리보기/수정 → 저장
- 노트 상세: 좌우 분리 구조, 시나리오 보드, 확률 조정, 원본 대화 열람
- 리마인드 상세 3단 화면
- 시나리오 상태 변화 (네 가지 선택지 포함)
- 대화로 결과 지표·근거 항목 설정, 일 1회 수집·평가, 달성 현황 표시
- 회고록 (AI 초안 + 벤치마크 비교 + 사용자 서술)
- `[사용자]` 저작 표기
- 온디맨드 AI 리서치 (`지금 다시 조사하기`)
- 정기 / 시점 기반 리마인드, 이메일 알림
- 노트 목록, 검색
- Wide / Narrow 두 구간의 반응형 대응 (§10.7 구현 순서에 따름)

### 이연
- 자동 주기 백그라운드 리서치 → Phase 2
- 이벤트 기반 즉시 알림 → Phase 2
- 확률 변화 그래프 시각화 → Phase 3 (MVP는 이력 리스트로 대체)
- 회고 리포트 / 판단 패턴 분석 → Phase 3
- 푸시 알림(PWA) → Phase 2
- 종료된 노트 아카이브 뷰 → Phase 2
- Medium 구간(768~1279px) 세부 정리 → Phase 2 (MVP는 Narrow 규칙으로 근사)

## 13. 남은 오픈 이슈

- **타임라인 구간 경계값**: `이번 주 / ~1개월 / ~3개월 / ~6개월 / 그 이후`가 실제 투자
  판단 주기와 맞는지 프로토타입으로 검증 필요.
- **대화 길이 관리**: AI가 필수 항목을 확보하기까지 몇 턴이 적정한가. 너무 길면 P6에 위배.
  목표치를 5~8턴으로 잡고 실측 필요.
- **노트 간 연결**: 여러 노트가 같은 거시 변수(예: 금리)에 걸려 있을 때 이를 연결해 보여줄
  것인가. 가치는 크지만 P7(단순한 내비게이션)과 충돌 — Phase 3에서 재검토.
- **AI 견해의 강도 조절**: 사용자가 AI 의견의 적극성을 설정할 수 있게 할 것인가
  (정보만 / 의견 포함 / 적극 제안). 현재는 "적극 제안" 고정으로 설계.
- **알림 중복**: 이메일과 푸시가 함께 켜졌을 때 어떻게 묶어 보낼지.
- **작성 대화의 길이**: 시나리오 2개 × (결과 지표 + 근거 항목)이면 질문이 크게 늘어난다.
  전체 대화를 5~8턴으로 유지한다는 목표(P6)와 정면으로 충돌한다. 근거 항목은 숫자를 묻지
  않아 한 턴이면 끝나지만 그래도 부담이다. 지표 설정을 노트 저장 후 2단계로 뺄지 검토 필요.
  **이 기능에서 가장 큰 UX 위험이다.**
- **회고록의 재방문 동선**: 같은 대상으로 새 노트를 만들 때 과거 회고를 소환하는 것 외에,
  노트 목록에서 종료된 노트의 회고를 어떻게 다시 만나게 할지 미정.
- **지표 이름의 번역 품질**: 사용자가 말한 "유동성"을 FRED의 어느 계열로 매핑할지가
  이 기능의 사용성을 좌우한다. AI가 틀린 계열을 제안했을 때 사용자가 알아차릴 수 있는지,
  대안을 어떻게 보여줄지 미정.
- **지표가 하나도 안 잡히는 가설**: 정성적 판단(경영진 신뢰도, 브랜드 가치)만으로 이루어진
  가설을 어떻게 다룰지. 예/아니오 지표로도 안 잡히는 경우가 있다.
- **모바일 홈의 기본 세그먼트**: 피드를 기본으로 두었으나, 실제로는 타임라인부터 보고 싶어하는
  사용자가 있을 수 있다. 마지막 선택을 기억하게 할지 검토 필요.
- **데스크톱 리마인드 화면의 읽기 순서**: ①②를 나란히 두면 대비는 강해지지만 "①을 먼저 읽는다"는
  강제가 약해진다. 실사용에서 ②를 먼저 읽는 비율이 높으면 세로 배치로 전환을 검토.
- **가로 모드 태블릿**: 세로가 짧고 가로가 넓은 형태(예: 1024×768)는 Medium 구간에 속하지만
  데스크톱에 가까운 모양이다. 폭이 아니라 화면 비율로 나눠야 하는지 검토 필요.
